# Урок 89. Отчёт «Анализ компенсаций» и ошибки уроков 72/88 (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=7cqIh8w083w · ~30 мин · [полный текст](../transcripts/089_7cqIh8w083w.md)

## О чём урок
Работа над ошибками и **отчёт «Анализ компенсаций»** (билет из урока 88 — «водитель, компенсация на ремонт»): «сотрудник, отработано часов, был ли штраф, сумма компенсации» — отчёт нужен для **ручного контроля**, что компенсация не начислена при прогуле.

## Работа над ошибками
### 1. Базовый период командировки при задним числом (урок 72)
В билете «командировка» после уроков 71–72 (**командировка может вводиться задним числом**) базовый период продолжал считаться от **периода регистрации** — неверно (август), а нужно — **от периода действия (даты начала)**:
- `БазовыйПериодНачало = ДобавитьМесяц(НачалоМесяца(Строка.ДатаНачала), -2)`;
- `БазовыйПериодКонец = НачалоМесяца(Строка.ДатаНачала) − 1` (последняя секунда месяца, предшествующего месяцу начала).
Пример: командировка в июле → база: май и июнь (а не июнь–июль); командировка июнем → апрель–май.
(В ранней версии урока 71 период регистрации и действия совпадали — там было нормально.)

### 2. Срез последних без периода (урок 88)
В запросе расчёта срез регистра «ПоказателиРасчётаЗарплаты» подтянули **без указания периода** → всегда передавать `&ПериодРегистрации`: `Запрос.УстановитьПараметр("ПериодРегистрации", ПериодРегистрации)` (замечание зрителя Иванчи).

## Отчёт «Анализ компенсаций»
**Образец:** «сотрудник, отработано часов, был ли штраф, сумма компенсации»; отчёт — **за один месяц** (отбор по периоду регистрации — «видно, что один месяц»).

**Запрос (объединение трёх выборок, а не соединение):**
1. **Основные начисления**, `ВидРасчета = &ОплатаПоЧасовомуТарифу`: `Сотрудник`, `ОтработаноЧасов` (реквизит регистра, не ресурс — для отчёта ресурсом быть не обязан), `ЛОЖЬ` («БылШтраф»), `0` (сумма компенсации); `ПериодРегистрации = &ПериодРегистрации`, **`Активность = ИСТИНА`**.
2. **Основные начисления**, `ВидРасчета = &Прогул`: `Сотрудник`, `0`, `ВЫБОР КОГДА Результат > 0 ТОГДА ИСТИНА ИНАЧЕ ЛОЖЬ КОНЕЦ` («БылШтраф»), `0`.
3. **Дополнительные начисления**, `ВидРасчета = &КомпенсацияНаРемонт`: `Сотрудник`, `0`, `ЛОЖЬ`, `Результат`.
- **Почему `ОБЪЕДИНИТЬ ВСЕ`, а не соединения:** если отработанных часов нет, а штраф есть (весь месяц прогулы), соединения потребуют кучу `ЕСТЬNULL`/левых соединений.
- «Штраф» — прогул (одно без другого не бывает).
- **Идея отчёта:** по компенсации и штрафу в одном месяце видно ошибку, которую должен поймать пользователь (ручной контроль условия «невыходов не было»).

**СКД:**
- Параметры «ПериодРегистрации» (приведение к началу месяца: `НачалоПериода(&ПериодРегистрации, "Месяц")` — **в кавычках**), виды расчёта «Прогул», «КомпенсацияНаРемонт», «ОплатаПоЧасовомуТарифу» — **параметрами**; пользовательские настройки; значение — начало месяца (хотя в пользовательском режиме перезадаётся).
- **Группировка по «Сотруднику»**, чтобы свернуть «простыню»: **ресурсы** — «ОтработаноЧасов» (СУММА), «СуммаКомпенсации» (СУММА), «БылШтраф» (**МАКСИМУМ** — Истина > Ложь, значит, если был хоть один прогул — Истина); в выбранные поля вывести эти три; «выводить параметры» — не выводить.
- Условное оформление: ширина колонок — минимальная/максимальная 15 символов; заголовки полей — полужирный, по центру; **строки с ошибкой (БылШтраф = Истина **И** СуммаКомпенсации > 0) — красным цветом текста** (выделить для пользователя; условие — в «группировке», а не в заголовке); для **«БылШтраф» итог не считать** (на закладке «Ресурсы» — только для группировки «Сотрудник»); «Итого:» двоеточие не рисовать.
- Автор не стал делать цветную подсветку «настоящей» — «не нужна, никто не требует».
