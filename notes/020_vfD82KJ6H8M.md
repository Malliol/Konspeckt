## О чём урок

## Как устроен срез последних
В базе данных нет таблицы «срез последних»: при его вызове платформа раскладывает его на запросы.
1. Запрос по регистру: группировка по **всем измерениям** регистра и `МАКСИМУМ(Период)` — для каждой комбинации измерений дата её последнего изменения; здесь накладываются все отборы (`Период <= &Период` и отборы по измерениям).
2. Внутреннее соединение этой таблицы с самим регистром по периоду и всем измерениям: остаются только записи с максимальным периодом для этой комбинации.

Поэтому срез последних по регистру «набор + продукт» возвращает «лишнюю» строку (лук с 2020 года): для комбинации «Набор №1 + Лук» последнее изменение было в 2020 г.

**Правильное решение для состава набора:** в подзапросе «даты последних изменений» группировать **только по набору продуктов** (убрать измерение «Продукт»), т. е. взять максимальный период для набора, а затем соединить с регистром по периоду и набору — отсекутся все записи, кроме самого свежего состава набора (лук исчезнет).

## Откат «оптимизации» из урока 19
В прошлом занятии по просьбе зрителя был создан временной регистр `ВТ_СоставНаборовПродуктов` с уже наложенным отбором. Но отбор нужен только один раз: в таблице «даты последних изменений». Для второй таблицы отбор не нужен, поскольку отсев происходит внутренним соединением. Поэтому:
- в `ВТ_ДатыПоследнихИзмененийНаборов`: напрямую из `РегистрСведений.СоставНаборовПродуктов` с условиями `Период <= &Период` и `НаборПродуктов В (...)`;
- в таблице состава наборов: напрямую регистр (с внутренним соединением по периоду и набору);
- лишнюю временную таблицу удалить (и поправить индексы результатов в массиве `ВыполнитьПакет`).

Замечания:
- Лук можно было не удалять признаком «Использование» — но принятая на экзамене структура регистра именно такая: новый состав просто вводится с новой датой. Автор говорит, что экзаменаторы привыкли к этой структуре и принимают даже срез последних.
- В таблице `ВТ_ПродуктыИБлюда` могут быть дубли номенклатуры (разложенные наборы). Группировать их при формировании движений нужно; для таблицы остатков `Различные` не нужны — выигрыша производительности не будет.

## «Ручная комплектация» (упрощённый билет)
В актуальной формулировке билета (подтверждена зрителем «Потолке»): «**документом комплектация пользователь делает движение в любые регистры накопления и правильность записи контролирует сам**». Тогда проведение с контролем не нужно.
- Документ «РучнаяКомплектация» без реквизитов; **движения вносятся вручную** в форму документа: «Движения» (регистр остатков) — расход продуктов, приход блюда; на форме выводится набор записей регистра.
- Конфигурация: документ делает движение по «Остаткам номенклатуры» (Движения → флажок). Обработка проведения не пишется. Документ **не проводится — только записывается**.
- **Период записей** заполняют кодом, чтобы его не вводить вручную (в «ПередЗаписью»):
  ```
  Для Каждого Запись Из Движения.ОстаткиНоменклатуры Цикл Запись.Период = Дата; КонецЦикла;
  ```
- **Пометка на удаление должна отключать движения**, а не удалять. Если оставить как есть, при пометке на удаление набор записей записывается пустым — движения исчезнут из регистра и из табличной части формы. Решение: в `ПередЗаписью` при `РежимЗаписи = Удаление` или при пометке на удаление отключить активность (`Запись.Активность = Ложь`): неактивные записи остаются, но не участвуют в остатках и оборотах. Обработчик: если `ПометкаУдаления` — установить `Активность = Ложь` во всех записях набора; при снятии пометки — снова `Истина`. Для корректной работы набор нужно предварительно **прочитать** (`Движения.ОстаткиНоменклатуры.Прочитать()`), иначе набор пустой и записывается пустым.
  На экзамене это делать не стоит (никто не помечает документы на удаление), но полезно знать.
- **Копирование:** по умолчанию движения не копируются. Для копирования в обработчике `ПриКопировании(ОбъектКопирования)` выбирают записи регистра по регистратору (`РегистрыНакопления.ОстаткиНоменклатуры.Выбрать(Отбор по Регистратору = ОбъектКопирования.Ссылка)`) и добавляют их в движения. На экзамене не нужно.
- **Расходная накладная:** при формировании сообщения о нехватке не забыть **`Отказ = Истина`**: иначе документ проведётся с отрицательным остатком (в уроке автор забыл).

## Отчёт «Ведомость продуктов и блюд» (билет)
- Источник — виртуальная таблица остатков и оборотов (без оборотов): начальный остаток, приход, расход, конечный остаток по количеству.
- Отборов нет (в регистре остатков только продукты и блюда). Ресурсов нет. Параметр «Период» — стандартный период (параметры начала и конца периода скрыты, период обязателен).
- Структура — детальные записи. Выбранные поля: номенклатура, начальный остаток, приход, расход, конечный остаток; заголовки полей: «Нач. ост.», «Приход», «Расход», «Кон. ост.».
- Условное оформление: заголовки — жирный шрифт и по центру (область — заголовки полей), для данных группировки — выравнивание влево; отступ 1 символ для номенклатуры.
- **Минимальная ширина** колонок задаётся условным оформлением одним элементом для всех числовых полей (идея зрителя «Воробей бородатый»).
- Заголовок «Ведомость продуктов и блюд за период с … по …» (шаблон ячейки, формат даты) — группировка «Заголовок» (дополнительная информация), макет группировки; у заголовка макет оформления отключают, у группировки детальных записей включают; пустую строку из-за вложенности оставляют или убирают подчинением.
- Параметр называют «Период» (так принято в типовых и в книгах по разработке отчётов).

### Сортировка: блюда или продукты первыми
- Сортировка **в запросе** по виду номенклатуры идёт по **представлению** (алфавит): «Блюдо» раньше «Продукт».
- **СКД** сортирует по **порядку значений в перечислении**: «Продукт» (первый) раньше «Блюдо» (в соответствии с перечислением). Направление «по убыванию» перевернёт порядок, но это странный приём.
- Лучший способ управлять порядком: вычисляемое поле **«Порядок»**: `ВЫБОР КОГДА ВидНоменклатуры = Блюдо ТОГДА 1 КОГДА ВидНоменклатуры = Продукт ТОГДА 2 ИНАЧЕ 3 КОНЕЦ` (с запасом для будущих видов), и сортировка по полю «Порядок». Поле «Порядок» нужно скрыть от пользователя ограничениями поля (флажки «Поле», «Условие», «Группировка»), оставив только «Упорядочивание».
