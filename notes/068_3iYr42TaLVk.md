# Урок 68. Расчёт премии (СПР). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=3iYr42TaLVk · 68 мин · [полный текст](../transcripts/068_3iYr42TaLVk.md)

## О чём урок
Продолжение билета № 1: **премия в процентах от оклада**, процент зависит от **стажа**; шкала хранится в регистре сведений. План видов расчёта **«Дополнительные начисления»**, регистр расчёта с **базовым периодом**, **виртуальная таблица «База»**, расчёт стажа. База — выгрузка урока 67 (совместительства нет).

## Точность результата (отступление)
Автор оставляет у ресурса «Результат» **10/2** — точность взята из «Оклада» в регистре «СведенияОСотрудниках» (каркас). Белоусов использует 12/2; максимум при 10/2 — 99 999 999,99 ₽; для зарплат достаточно, за это оценку не снижают. Общее правило: **берём точность из аналогичного поля каркаса**.

## Условие
- Оклад (урок 67) + **дополнительно сотрудникам может быть начислена премия в процентах от начисленного им за тот же период оклада**; **процент зависит от стажа работы сотрудника**; **шкала значений процента премии вводится пользователем** (регистр сведений); **на момент начала ведения учёта в базе у сотрудника уже может быть стаж, отличный от нуля** (формулировка «на данном предприятии» некорректна: трактуют как стаж на момент начала ведения учёта).
- Премия начисляется документом «НачислениеЗарплаты» (табличная часть «Дополнительные начисления»).

## План видов расчёта и регистр
- **Где какие начисления:** виды расчёта, **протяжённые во времени** (оклад, отпуск, больничный, командировка), — **«Основные начисления»** (период действия — **вкл.**); **не протяжённые** (премия «за месяц») — **«Дополнительные начисления»** (период действия — **выкл.**). Если в задаче нет протяжённых видов — можно всё в основные.
- **База** (флажок «Зависимость от базы» → указываем **план видов расчёта-«базу»: «Основные начисления»**; премия считается **от оклада** — оклад «база»; если от отпусков/больничных — база их сумма). **Зависимость от базы** — **по периоду действия** (в 99 % случаев; **если в плане базы нет периода действия — система берёт период регистрации, ошибки нет**); **по периоду регистрации** — обычно у **«Удержаний»** (в каркасе уже так).
  - Различие: «по периоду регистрации» — в базу попадают все начисления за тот же период регистрации (месяц), без пропорций; «по периоду действия» — система анализирует интервалы, пропорционально высчитывая базу в **базовом интервале**.
- **Регистр расчёта «ДополнительныеНачисления»** (имя = имя плана; регистратор — «НачислениеЗарплаты»; **флажок «Базовый период»** — включает поля «БазовыйПериодНачало»/«БазовыйПериодКонец»; **периода действия нет**): измерение **«Сотрудник»** (запрет незаполненных; без подразделения — совместительства нет); ресурс **«Результат»** (10/2); реквизиты **«БазаНачислений»** (10/2) и **«ПроцентПремии»** (5/2) — «поля, легшие в основу расчёта» (чтобы экзаменатор видел вычисление); **не называть реквизит «база начисления» так, чтобы не путать с полем «РезультатБаза»**. График работы и дата начала/окончания в доп. начислениях **не нужны** (убрать в документе); результат в табличной части документа убрать.
- Документ: табличная часть **«ДополнительныеНачисления»** (тип плана — «ДополнительныеНачисления»; поля «Сотрудник», «Вид расчёта»); **основные начисления в документе делают необязательными** (премию можно начислить без оклада; «проверка заполнения табличной части» убрана); **если оба раздела пусты → «Нет данных для проведения», `Отказ`** в **`ОбработкаПроверкиЗаполнения`** (срабатывает при проведении, не при записи: «обработка проверки заполнения»).
- Удержания — отдельный план видов расчёта нужен, чтобы при выплате («основные + дополнительные − удержания») вычитание шло по плану (у Белоусова штрафы иногда кладут в основные/дополнительные — автор считает «полным бредом»).

## Подготовка записей (этап 1)
В обработке проведения (после основных): `Для Каждого Строка Из ДополнительныеНачисления Цикл Движение = Движения.ДополнительныеНачисления.Добавить(); ЗаполнитьЗначенияСвойств(Движение, Строка); Движение.ПериодРегистрации = НачалоМесяца(Дата); Движение.БазовыйПериодНачало = НачалоМесяца(Дата); Движение.БазовыйПериодКонец = КонецМесяца(Дата)` — **базовый период = весь месяц начисления**; `Движения.ДополнительныеНачисления.Записать()`.

## Виртуальная таблица «База»
- **`РегистрРасчета.ДополнительныеНачисления.База(&Измерения (массив из одного измерения: «Сотрудник»), , , Регистратор = &Ссылка)`** — **база для регистра**: поле называется **`РезультатБаза`** (ресурс «Результат» + слово «База»), **номер строки** (`НомерСтроки`); сопоставление основного и дополнительного регистров — по **общим измерениям** (в экзамене — «в 100 % случаев одинаковые», один параметр «Сотрудник»). Это **не** реквизит «БазаНачислений» (его заполняем сами).
- **База включает только строки, для которых нашлась база**: сотрудник без оклада в этом месяце **не попадает** в результат (без левого соединения) → в цикле расчёта: **`Если Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки") Тогда`** (в отличие от оклада, где строка находится всегда); перед поиском — **`Выборка.Сбросить()`**. **`ЕСТЬNULL` для базы не нужен** (нет левого соединения; нулевая база — только при нулевом окладе).
- Вопрос «удалять ли движения без базы» — никто не удаляет (ни Белоусов, ни Прохоров) — не удаляем.

## Шкала процентов премии от стажа
- Регистр сведений **«ШкалаПроцентовПремииОтСтажа»** (подсистема «Расчёты»): **периодичности нет**; измерение **«СтажОт»** (число 2/**1**? в уроке — 5/2 или целое «2 знака, точность 0»; «неотрицательное» не ставят — «умные люди не ставят»; **проверку заполнения у «СтажаОт» отключают** — иначе нулевую запись (от 0) нельзя ввести; запрет незаполненных значений — не ставить), ресурс **«ПроцентПремии»** (5/2, «Выдавать ошибку»); значения — «от 0 до 1 года — 5 %; от 1 — 10 %; от 3 — 15 %» (**«СтажОт» = 0, 1, 3**; верхней границы нет — используют «следующий СтажОт» из шкалы; автор рассматривал «от 3 до 999», но принял «стаж 3 и выше» через «больше или равно»).
- В регистре «СведенияОСотрудниках» добавляют **«ДатаПриёма»** (дата, «Выдавать ошибку») и **«НачальныйСтажДней»** (число, **в днях** — не в годах: «100 дней — не 0 лет»; «стаж в целых годах/месяцах некорректен»).

## Расчёт стажа и процента (запрос)
1. Таблица **базы** (`База(…)`, `Регистратор = &Ссылка`): номер строки, сотрудник, `РезультатБаза`.
2. Соединение с `СведенияОСотрудниках.СрезПоследних(&ПериодРегистрации, Сотрудник В (ВЫБРАТЬ Сотрудник ИЗ …))` по сотруднику: `ДатаПриёма`, `НачальныйСтажДней`.
3. **Стаж (лет) = (РАЗНОСТЬДАТ(ДатаПриёма, &ПериодРегистрации, ДЕНЬ) + НачальныйСтажДней) / 365** (вещественный; **не округлять**; високосные годы игнорируем — «на экзамене не важно»); в запросе — `ВЫРАЗИТЬ(… КАК ЧИСЛО(12, 2))` при необходимости.
4. **Левое соединение с шкалой** по условию **`Стаж >= Шкала.СтажОт И Стаж < ШкалаСледующая.СтажОт`** (то есть попадание в интервал; **строгое «меньше» у верхней границы — чтобы стаж ровно 1 год не попал под 5 %**); **`ЕСТЬNULL(Процент, 0)`** — шкала может быть не заполнена; поле стажа выводится для наглядности (реквизит «Стаж» регистра: 5/2).
5. Цикл расчёта: `Результат = Выборка.РезультатБаза × Выборка.Процент / 100`; `ЗаполнитьЗначенияСвойств(Движение, Выборка)` — копирует базу и процент (полям регистра нужны такие же имена); **для регистра без периода действия `Движения.ДополнительныеНачисления.Записать()` — без параметров** (если период действия есть — `Записать(, Истина)`).
- Пример: Бердыев (приём 1 января, начальный стаж 365 дней; на 1 августа — 578 дней / 365 = 1,58 года) → 10 % от 100 000 = 10 000; Васина (стаж 4,5 года) → 15 % от 120 000 = 18 000 (итого 138 000).
- Замечание зрителя Шерзода: «по закону 15 дней стажа округляют до месяца» — в типовых при вводе года/месяцы/дни считают с округлением; автор — в днях, без округления.

## Консоль запросов (баг каркаса)
При нажатии «**Получить из запроса**» в параметрах **список значений/массив преобразуется в строку** — после этого запрос ломается; **заново указать тип «Массив»/список значений**.

## Прочее
- Для запросов к «Базе» нужно **включить флажок «Базовый период»** в регистре, иначе таблицы «База» не будет.
