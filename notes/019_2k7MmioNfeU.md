## Условие билета
- Возможна продажа продуктов, **наборов продуктов** и **готовых блюд**.
- Для приготовления блюд служит документ **«Комплектация»**; если из продуктов изготовлено блюдо, то продаваться может только блюдо, входящие в состав продукты — уже нет (то есть продукты списываются, блюдо оприходуется).
- Закупаются продукты, продаётся всё. Склады не ведутся (удалены).
- **Состав набора может меняться не чаще раза в день** → периодический регистр сведений; при продаже берётся состав, актуальный на момент продажи.
- Комментарии «для сдающих» (в источниках) — не формулировка билета.

## Конфигурация
- «ВидыНоменклатуры»: Продукт, Набор продуктов, Блюдо. В приходной накладной — параметры выбора: только продукты.
- Документ **«Комплектация»**: реквизит «Блюдо» (параметр выбора — вид «Блюдо»; проверка заполнения), «Количество» (проверка), табличная часть «Продукты» (номенклатура — продукты, количество). Движения по «Остаткам номенклатуры».
- Регистр сведений **«СоставНаборовПродуктов»**: периодичность «в пределах дня», независимый, измерения «НаборПродуктов» (параметр выбора — вид «Набор продуктов») и «Продукт» (вид «Продукт»), ресурс «Количество» (неотрицательное). У измерений — «Ведущее», «Запрет незаполненных значений», проверка заполнения «Выдавать ошибку».
- Тестовые данные: набор «Набор из овощей №1» в 2020 г. = 2 огурца + 3 помидора + 1 лук; в 2021 г. состав изменён: 1 огурец + 3 помидора + 1 зелень (лука больше нет).

## Документ «Комплектация» (новая методика проведения)
1. Запрос по табличной части (продукт, количество; группировка, отбор по ссылке) → `ВТ_Товары` (поле индексировать: оно участвует в условии второго запроса).
2. Запрос выбирает номенклатуру, количество, период (дата документа) — данные для **расходных** движений продуктов.
3. Расход продуктов; оприходование блюда: `Движения.ОстаткиНоменклатуры.ДобавитьПриход()` (период, номенклатура = блюдо, количество из шапки) — контролировать не нужно.
4. `Записывать = Истина`, `БлокироватьДляИзменения = Истина`, `Движения.Записать()`.
5. Контроль остатков вторым запросом (менеджер временных таблиц общий): `Остатки(&Граница, Номенклатура В (...))`, `КоличествоОстаток < 0`; граница с видом «Включая»; результат не пуст → `Отказ`, сообщения `СтрШаблон("Недостаточно продукта %1 в количестве %2", ...)`.
Замечание: зрители (в частности, «Потолке») предлагали документ комплектации как «бухгалтерскую операцию» с прямой записью движений. Автор считает это необоснованным, если в формулировке задачи об этом ничего не сказано.

## Актуальный состав набора на дату — не срез последних
Срез последних для набора вернёт и **неактуальные** строки: в составе остаётся лук, хотя в 2021 г. его заменили зеленью (срез берёт последнюю запись по каждой комбинации измерений «набор + продукт», а не «последний состав набора»). На экзамене срез последних часто «канает», но это **ошибка**.

Правильное решение — выбрать записи с **максимальным периодом** для каждого набора:
1. `ВТ_ДатыПоследнихИзмененийНаборов`: из регистра `СоставНаборовПродуктов` выбрать `НаборПродуктов`, `МАКСИМУМ(Период)`; условия: `НаборПродуктов В (наборы из табличной части документа)`, `Период <= &Период` (дата документа); сгруппировать по набору.
2. `ВТ_СоставНаборовПродуктов`: исходная таблица регистра (не срез последних) с **внутренним соединением** с датами последних изменений по **периоду и набору продуктов**; поля — набор, продукт, количество.
(В обсуждении выяснилось, что на срезе последних система делает то же самое, но с лишним соединением; прямое обращение к таблице регистра быстрее. Автор «оптимизировал» запросы: отбор по набору и периоду вынесен в отдельную временную таблицу `ВТ_СоставНаборовПродуктов` до расчёта дат. Идея вызвала путаницу: в процессе были допущены ошибки — потерялись `МАКСИМУМ(Период)`, индексы, привязка менеджера временных таблиц; автор признал, что оптимизация «усложнила материал», и её лучше не делать.)

## Разложение табличной части расходной накладной
Пакет запросов с общим `МенеджерВременныхТаблиц`:
1. `ВТ_Товары` — табличная часть расходной накладной (номенклатура, вид номенклатуры, количество, группировка, отбор по ссылке).
2. `ВТ_Наборы` — номенклатура вида «Набор продуктов» из `ВТ_Товары` (временная таблица нужна, чтобы дважды не повторять отбор по виду; поле «Номенклатура» индексируется).
3. Даты последних изменений наборов и состав наборов на дату (см. выше), индексы: у `ВТ_Наборы` — «Номенклатура» (используется во вложенном запросе `В`); у `ВТ_Даты…` и `ВТ_Состав…` — «Период» и «НаборПродуктов» (соединение).
4. `ВТ_ПродуктыИБлюда`: левое соединение `ВТ_Товары` с `ВТ_Состав…` по номенклатуре = набор продуктов. Колонки: номенклатура продажи, продукт, количество продажи, количество в составе. Итоговые:
   - **Номенклатура** = `ВЫБОР КОГДА Состав.Продукт ЕСТЬ NULL ТОГДА ВЫБОР КОГДА ВТ_Товары.ВидНоменклатуры <> Набор ТОГДА ВТ_Товары.Номенклатура КОНЕЦ ИНАЧЕ Состав.Продукт КОНЕЦ` (продукты и блюда переносятся, а набор без определённого состава остаётся `NULL`, чтобы вывести ошибку);
   - **Количество** = `ЕСТЬNULL(Состав.Количество, 1) * ВТ_Товары.Количество` (поле количества можно также защитить условием по виду).
5. Проверка ошибки: запрос по `ВТ_ПродуктыИБлюда` (номенклатура продажи, «Номенклатура» `ЕСТЬ NULL`) — набор без состава; сообщение «Не определён состав для набора %1», `Отказ`, `Возврат`. Результат берётся по индексу из `ВыполнитьПакет()` — внимательно считать (нумерация с 0), а после вставки новой временной таблицы индексы сдвигаются.
6. Данные для движений: `ВТ_ПродуктыИБлюда`, номенклатура, количество (группировка), период (дата документа).
7. Контроль остатков: `Остатки(&Граница, Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ ВТ_ПродуктыИБлюда))` — важно брать номенклатуру именно из таблицы разложенных продуктов и блюд, а не из `ВТ_Товары`; `КоличествоОстаток < 0`; проверку на пустой результат до обхода.
8. Индекс по `ВТ_ПродуктыИБлюда.Номенклатура` (используется во вложенном запросе).
9. **Улучшенное сообщение:** для продуктов — «Недостаточно продукта %1 в количестве %2 (может входить в состав набора)», для блюд — «Недостаточно блюда %1…». Продукт может входить в неограниченное число наборов, поэтому вычислять, в какой именно, не стали (в уроке 17 было проще: комплектующая — в одном стеллаже).
10. Не индексировать «ВидНоменклатуры» ради отбора (низкая селективность, не требуется).
