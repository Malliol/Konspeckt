# Урок 44. Отчёт по продажам (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=RFVgD71ooa0 · 41 мин · [полный текст](../transcripts/044_RFVgD71ooa0.md)

## О чём урок
Завершение бухгалтерской задачи № 15: **отчёт по продажам** с группировкой по **значению характеристики** (пользовательская характеристика номенклатуры, например «Страна»). Ключевые приёмы бухучёта: как получить продажи, если данных в регистре не хватает; **корреспонденция счетов** в запросе; приведение типа субконто.

## Характеристики номенклатуры (как в оперативном учёте, см. урок 21)
- Справочник «ЗначенияХарактеристик» (подсистема «Бухгалтерский учёт»), владелец — ПВХ; ПВХ «ХарактеристикиОбъектов» (бывш. «СвойстваОбъектов»); справочник входит в составной тип значения ПВХ; предопределённые элементы не нужны (в билете характеристика выбирается пользователем — не «зашита»).
- Регистр сведений **«ЗначенияХарактеристикНоменклатуры»**: измерение «Номенклатура» (ведущее, запрет незаполненных значений, «Выдавать ошибку»), измерение «Характеристика» (ПВХ, ведущее, запрет, «Выдавать ошибку»; «Создание при вводе» — включено), ресурс «Значение» (составной тип ПВХ; **связь параметров выбора** — владелец «Характеристика», связь по типу).
- Тестовые данные: кинокамера — «Страна» = Россия; «Абуди-вдув» — Чехия; «Бадьян» — без значения (нужен случай «пусто»).

## Проблема: в проводках нет суммы продаж по номенклатуре
- В проводке **Дт «Прибыли и убытки» / Кт «Товары»** есть количество и себестоимость по номенклатуре, но **выручка** — отдельная проводка **Дт «Покупатели» / Кт «Прибыли и убытки»** на общую сумму документа: непонятно, какая сумма к какой позиции относится.
- **Решение (общее правило для отчётов по продажам):** добавить к счёту **«Прибыли и убытки»** нужный **вид субконто** («Номенклатура»; для других разрезов — склад, контрагент и т. д.) и поставить флажок **«Только обороты»** (остатки по прибылям/убыткам хранить бессмысленно — остаток = финансовый результат; аналог оборотного регистра накопления «Продажи» из оперативного учёта).
- Правка расходной накладной: **выручку** проводить **в цикле по номенклатуре** (а не одной проводкой на документ): `Дт Покупатели, Кт Прибыли и убытки`, `СубконтоКт[Номенклатура] = Выборка.Номенклатура`, `Сумма = Выборка.Сумма` (сумма строки берётся из табличной части; в итоги запроса — `МАКСИМУМ`, как количество); проводка списания — `СубконтоДт[Номенклатура] = Выборка.Номенклатура` (по Дт «Прибыли и убытки» тоже). Нюанс отладки: после изменения плана счетов в пользовательском режиме изменение не сразу видно (перезапуск), а номенклатуру в цикле берут из **итоговой записи** выборки (после выхода из цикла детальных записей) — ошибка автора в уроке.
- В итоге по счёту «Прибыли и убытки» видны: **количество**, **себестоимость** (оборот по дебету) и **сумма продажи** (оборот по кредиту) по каждой номенклатуре.

## Запрос отчёта
- `Управленческий.Обороты(&НачалоПериода, &КонецПериода, , Счет = &СчетПрибылиИУбытки, &ВидыСубконто, , КорСчет В (&Товары, &Покупатели) …)` — **обороты по счёту** с **корреспондирующими счетами**: «при получении итоговых данных из регистра бухгалтерии не учитывается корреспонденция счетов» — типичная ошибка, **−1,5 балла**. Нужно ограничить корсчета: себестоимость — корреспондирует «Товары», выручка — «Покупатели» (даже если сейчас других проводок нет — защищаемся от будущих).
- Поля: номенклатура, `КоличествоОборотДт` (количество списанного товара — совпадает с проданным), `СуммаОборотДт` (себестоимость), `СуммаОборотКт` (сумма продажи). Лишние поля (счёт, субконто 2/3 — склады и партии, корсчета, `КоличествоОборотКт`) убрать; по субконто — `ВидыСубконто` явно (массив или один элемент: если используется один вид, можно передать **сам вид**, а не массив).
- Не использовать оборот «сумма оборот» без разделения Дт/Кт — минусы «мешают».
- **Параметры отчёта:** «Период» (стандартный период, `&Период.ДатаНачала`, `&Период.ДатаОкончания` — не забыть выражения параметров начала/конца периода: заметка зрителя Романа Киселева); виды субконто, счета «Покупатели», «Прибыли и убытки», «Товары» — параметры без «доступен список значений» (лишний флажок снять).
- **Приведение типа субконто:** `ВЫРАЗИТЬ(Субконто1 КАК Справочник.Номенклатура)` — иначе при выводе отчёта система выполняет **несколько лишних левых соединений** (проверено профайлером). Указание вида субконто в массиве/параметре типизацию не создаёт (мнение многих неверно); `ВЫРАЗИТЬ` решает. Белоусов оставляет без `ВЫРАЗИТЬ` («и не парится») — автор считает некорректным.
- Присоединение характеристики: **левое соединение** `Обороты` с `ЗначенияХарактеристикНоменклатуры` по номенклатуре **и** `Характеристика = &Характеристика` (параметр пользователя — характеристика, выбранная пользователем); пустое значение (`NULL`) допустимо — в отчёте будет «пусто» (товар без характеристики). Значение не суммируем — NULL не мешает.

## СКД
- Структура: группировка по «Значение характеристики» (заголовок-параметр «Характеристика»), внутри детальные записи (номенклатура, количество, себестоимость, сумма продаж). Параметр «Характеристика» — снять «ограничение доступности», «Всегда использовать», в пользовательские настройки. Параметры вывода — не выводить; итоги по вертикали — «Нет». «Расположение полей группировок» — не менять (один из отчётов, где оно не нужно). Если характеристика не задана — отчёт пуст («дуля»; в задаче нет требования заполнять по умолчанию).
- Оформление: заголовки колонок — через макет/заголовок (поле «Значение характеристики» — заголовок макета группировки, `[Характеристика]`), количество/себестоимость/сумма — жирные, по центру, ширина.
- Отчёт и объекты — в подсистему «Бухгалтерский учёт».

## Позиция автора по способу Белоусова
Белоусов показывает «характеристики в отчёте» через настройку пользователя и **выгрузку настройки в XML / в конфигуратор**. Автор считает это дурью: в типовых так не делают, в билете такого требования нет; характеристика задаётся **параметром** пользователя прямо в отчёте.
