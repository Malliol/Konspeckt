# Урок 51. Отчёт «Недошедшие товары» (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=7FhH47nQwVc · 55 мин · [полный текст](../transcripts/051_7FhH47nQwVc.md)

## О чём урок
Отчёт к задаче № 10 (урок 50: отправление/прибытие/потери): **«Недошедшие товары на дату»** — по складу-получателю и номенклатуре: отправлено, получено, потеряно (количество и сумма). Автор считает его самым сложным бухгалтерским отчётом на тот момент (сложнее был только один — отчёт по стеллажам, урок 38). База — выгрузка занятия 50.

## Почему не остатки
В отчёте указывается одна дата, и кажется, что нужны остатки. Но на счёте «Товары в пути» остатков нет: всё получено или списано как потеря; остатки «Товаров» и «Прибылей и убытков» не показывают отправленное/полученное/потерянное. Значит **нужны обороты** по счёту «Товары в пути».

## Идея: что есть что (по корреспонденции)
Проводки по счёту «Товары в пути» (ТвП):
- **отправка:** Дт «ТвП» — Кт «Товары»; склад — отправитель;
- **получение:** Дт «Товары» — Кт «ТвП»; склад — получатель;
- **потеря:** Дт «Прибыли и убытки» — Кт «ТвП».
Обороты в «Оборотах» (счёт ТвП по любой стороне) путаются: зеркальные корреспонденции — отправка и получение отличаются только стороной. Поэтому используют **`ОборотыДтКт`** («обороты Дт/Кт»): в таблице обороты считаются отдельно **по дебету и по кредиту** (`СчетДт`, `СчетКт`, `КоличествоОборотДт/Кт`…), и можно точно указать, с какой стороны стоит счёт.

## Запрос (пакет из трёх выборок + соединения)
Решение «в одном запросе»: **три таблицы `ОборотыДтКт`**, главная — «Отправка», к ней **левыми** соединениями «Получение» и «Потеря» по номенклатуре и документу отправления.
1. **Отправка:** `Управленческий.ОборотыДтКт(, &КонецПериода, , СчетДт = &ТоварыВПути, &ВидыСубконтоДт (номенклатура, документы отправления), СчетКт = &Товары, …)` — `КоличествоОборотДт`, `СуммаОборотДт`, `СубконтоДт1 = номенклатура` (выразить), `СубконтоДт2 = документ отправления`; склад-отправитель в отчёте не нужен.
2. **Получение:** `ОборотыДтКт(…, СчетДт = &Товары, …, СчетКт = &ТоварыВПути, …)` — `КоличествоОборотКт`, `СуммаОборотКт`, субконто **Кт** (номенклатура, документ отправления — для соединения с отправкой), **склад получателя** — `СубконтоДт` счёта «Товары» (с видом субконто «Склады»; указывать только нужное).
3. **Потеря:** `ОборотыДтКт(…, СчетДт = &ПрибылиИУбытки, …, СчетКт = &ТоварыВПути, …)` — `КоличествоОборотКт`, `СуммаОборотКт`, субконто Кт.
4. Соединение: **главная — «Отправка»** (флажок «все»): если товар не дошёл, он остаётся на **пустом складе** (удобно пользователю — видно, что ещё не дошло); соединения по номенклатуре **и** документу отправления; в получении и потере — поля по **Кт**-субконто (счёт «ТвП» — по кредиту), в отправке — по **Дт**-субконто.
5. **`ЕСТЬNULL`**: для всех полей получения и потери (`ЕСТЬNULL(КоличествоПолучено, 0)`, суммы); склад: `ЕСТЬNULL(СкладПолучатель, ЗНАЧЕНИЕ(Справочник.Склады.ПустаяСсылка))`. Типизация склада — `ВЫРАЗИТЬ(… КАК Справочник.Склады)`; номенклатура — `ВЫРАЗИТЬ(… КАК Справочник.Номенклатура)`.
6. Виды субконто — параметрами и **только нужные** в каждой таблице: у «ТвП» — номенклатура и документы отправления (для соединений); у «Товаров» — только склады (в получении); у «Прибылей и убытков» субконто нет.
- Вариант «5 запросов с временными таблицами» (отправка/получение/потеря в отдельных ВТ) — возможен, но громоздок, много временных таблиц.

## Параметр «период» (одна дата)
Отчёт строится **на дату** (одна дата): параметр «НачалоПериода» — «начало времён» (скрыт), **«КонецПериода» — пользователь** (название «Период», запрещено не указывать). По умолчанию — «начало завтрашнего дня»; «секунда на которой строится отчёт не должна учитываться» — можно отнять секунду (`ДобавитьКДате(&Дата, ДЕНЬ, 0, … -1 секунду)`); начало «с начала времён» не снижает оценку («иного решения нет»).

## СКД
- Параметры: период, счета (ТвП, Товары, Прибыли и убытки — без списка значений), виды субконто (флажок «доступен список значений»: номенклатура, документы отправления; склады), запрет не использовать/не указывать период.
- Структура: группировка по **«СкладПолучатель»** → детальные записи; выбранные поля: номенклатура, **количество/сумма отправлено**, **получено**, **потеряно** (парные поля сгруппированы «Вертикально»: количество над суммой, как в образце); параметры вывода — «Не выводить»; расположение группировок — «Отдельно и только в итогах».
- Итоги по складу не нужны (в билете не просят).

## Есть NULL: зачем писать
Автор проверил: без `ЕСТЬNULL` отчёт «работает» (СКД сама обрабатывает NULL при группировке), но **пользовательский отбор** («Количество потеряно = 0») перестаёт работать: у NULL нет значения 0 — даже если в поле СКД задан числовой тип. **Приведение типа в наборе данных поля СКД не помогает**, как и указание типа у поля составного типа для склада (оно не приводит значение к справочнику в запросе). Вывод: **всегда писать `ЕСТЬNULL` при левом соединении** — «чем ловить полтергейсты, проще писать». (Рамзес привёл «убийственный» аргумент про отбор.)

## Пустой склад (поле «игнорировать NULL» в роли)
Товары, которые отправили, но не приняли, не показываются: на **пустом складе** строка пропадает. Причина — **роль поля «СкладПолучатель»** в СКД: у поля стоит флажок **«Игнорировать значения NULL»** (ставится автоматически для составных/ссылочных полей, у которых в запросе возможно NULL). Решение: **снять этот флажок** («Роль» поля) **или** привести NULL запросом к пустой ссылке: `ЕСТЬNULL(ВЫРАЗИТЬ(СкладПолучатель КАК Справочник.Склады), ЗНАЧЕНИЕ(Справочник.Склады.ПустаяСсылка))`. Тест: вводят остатки «куртка замшевая», отправляют 10 шт. и не принимают — в отчёте появляется строка на **пустом складе**. (Склад получателя неизвестен в момент отправки — «отправляем просто на счёт товаров в пути».)

## Прочее
- Пример тестовых данных: отправка 10 кинокамер (потеряна 1), отправка 10 портсигаров (все получены), второе отправление 5 апреля.
- Консоль запросов: «сохранение запроса» ломается на параметрах — виды субконто проще вводить заново.
- Анонсы: решение следующей части — через неделю.
