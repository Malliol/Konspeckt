# Урок 56. Продажа комплектов (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=VUp7KajFsqY · 66 мин · [полный текст](../transcripts/056_VUp7KajFsqY.md)

## О чём урок
Бухгалтерская задача (билет, аналог оперативной задачи о комплектах): **продажа комплектов с разворотом на комплектующие**. Сборки нет — **комплектующие списываются при продаже комплекта**. База — выгрузка занятия 41.

## Условие
- Состав комплекта хранится в системе; **в комплект не могут входить другие комплекты**; **деталь не может входить в состав разных комплектов** (уникальность комплектующих).
- **Сборка не осуществляется** (в отличие от урока 54: «когда сборки нет — в условии говорится об этом»): покупатель получает **комплектующие**, а не комплект.
- Продажа — «Расходная накладная»: в табличной части **комплекты и их количество** (комплектующие там указывать нельзя — упрощает задачу); склад указывается.
- Проводки: при продаже комплекта списываются комплектующие согласно составу (себестоимость), Дт «Покупатели» — Кт «Прибыли и убытки» (продажа комплекта).
- Себестоимость — **средняя по номенклатурной позиции на складе**.
- Отчёт «Продажа комплектов»: комплект, сумма продажи, себестоимость.
- Приходной накладной в условии нет → закупку отражают «Операцией». Белоусов (по информации автора с курсов): если приходная накладная не упомянута — её создавать не нужно; счета в плане счетов «создавать не обязательно» (можно «вместо ввода остатков» оформить закупку: Дт «Товары» — Кт «Поставщики»; вспомогательный «00» не заводить без нужды).

## Структура данных
- Регистр сведений **«СоставКомплекта»**, непериодический: измерение **«Комплектующая»** (единственное измерение; Номенклатура; запрет незаполненных значений, «Выдавать ошибку»; параметр выбора — вид «Комплектующая») — этим обеспечивается **уникальность**: одна комплектующая в одном комплекте; ресурсы **«Комплект»** (Номенклатура; параметр выбора — вид «Комплект»; «Выдавать ошибку») и **«Количество»** (число 10/0, неотрицательное, «Выдавать ошибку»).
  - Ответ зрителю Нику Биллову: **если добавить «Комплект» измерением, уникальность комплектующих пропадёт** — её пришлось бы проверять кодом. Правильно — комплектующая единственным измерением.
- Перечисление **«ВидыНоменклатуры»** (значения: «Комплект», «Комплектующая»; проверка заполнения у реквизита «ВидНоменклатуры» справочника), для каждой номенклатуры задаётся вид. В расходной накладной — параметр выбора номенклатуры «Комплект».
- План счетов: «Товары» — субконто **«Номенклатура», «Склады»** (максимум субконто 2); **«Прибыли и убытки» — «Номенклатура»** (именно **комплект** — разрез отчёта по продажам; только обороты); «Операция» обновить.
- Реквизит «Склад» в расходной накладной (проверка заполнения, на форме) — пропущен в начале, добавлен по замечанию зрительницы Елены.

## Подготовка данных
Закупка «Операцией»: Дт «Товары» (номенклатура, склад) — Кт «Поставщики»: «Абуди-вдув» 100 шт., «Бадьян» 100 шт., молоко, манка, йогурт. Состав: «Рыбный комплект» = 1 «Абуди-вдув» + 1 «Бадьян»; «Продуктовый комплект» = 10 молока + 5 манки + 20 йогуртов. Для теста — комплект «Молочный» без состава.

## Проведение (старая методика)
1. **Пакет запросов:**
   - `ВТ_Товары`: табличная часть расходной накладной — номенклатура (= комплект), количество, **сумма**; отбор по ссылке; свёртка.
   - **Запрос 2 (проверка состава):** левое соединение `ВТ_Товары` с `СоставКомплекта` по `Комплект = Номенклатура` — **записи, где комплектующая `NULL`** (состав не задан) → сообщение «Не задан состав комплекта %1», `Отказ`, `Возврат` (поэтому в этом запросе без `ЕСТЬNULL`, а нужно ловить NULL).
   - **Запрос 3 — разворот:** `ВТ_Комплектующие`: комплект, комплектующая, `Количество = ВТ_Товары.Количество × СоставКомплекта.Количество` (количество комплекта × количество комплектующей в комплекте), **сумма** комплекта (максимум на уровне итогов); индексы по комплектующей (индексировать поля соединения; **ресурсы регистра сведений сами не индексируются** — индекс по полю «Комплект» нужен отдельно). Сгруппировать не нужно (комплектующие уникальны в комплектах — повторяться не могут).
2. **Блокировка** — **по комплектующим** (а не по комплектам): `Блокировка.Добавить("РегистрБухгалтерии.Управленческий")`, счёт «Товары», склад из шапки, номенклатура — **результат запроса** (`ИсточникДанных = РезультатЗапроса3`, поле «Комплектующая») — запросы нужны **до** блокировки. Менеджер временных таблиц — `МенеджерВременныхТаблиц` запроса (используется в следующем запросе).
3. **Остатки комплектующих:** запрос с **описанием временной таблицы** «ВТ_Комплектующие» (поля комплект, комплектующая, количество — когда таблица создана в предыдущем запросе того же менеджера, конструктор её не видит; можно либо скопировать запросы, либо описать таблицу в конструкторе), левое соединение с `Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконто (номенклатура, склады), Субконто1 В (комплектующие) И Субконто2 = &Склад)` по комплектующей = `Субконто1`; `ЕСТЬNULL`; **итоги по комплекту** (количество, сумма продажи — `МАКСИМУМ` (одинакова на всех строках комплекта); остатки — `СУММА`); в консоли запросов итоги наглядны («товары разбиваются по кучкам»).
   - Типы полей временной таблицы нужно указать (иначе нельзя раскрыть поля, получить представление).
4. **Обход:** итоговые записи (комплекты) → детальные (комплектующие). В обработке — сначала выполняется проверка состава (результат запроса 2 не пуст → сообщения и отказ).
5. **Контроль остатков** по комплектующей: `Количество > КоличествоОстаток` → «Недостаточно остатков товара %1 (комплект %2) в количестве %3», `Отказ`; при отказе дальше не формировать.
6. **Проводки:**
   - списание комплектующей (в детальных записях): Дт «Прибыли и убытки» (`СубконтоДт[Номенклатура] = комплект`) — Кт «Товары» (`СубконтоКт[Номенклатура] = комплектующая`, `СубконтоКт[Склады] = Склад`, `КоличествоКт`), `Сумма` = себестоимость (если `Количество = КоличествоОстаток` → `СуммаОстаток`, иначе `СуммаОстаток / КоличествоОстаток × Количество`);
   - продажа (на уровне **итоговой записи** по комплекту, между «КонецЦикла» детальных и итоговых): Дт «Покупатели» — Кт «Прибыли и убытки» (`СубконтоКт[Номенклатура] = комплект`), `Сумма = ВыборкаКомплект.Сумма`.
   - Ошибка в уроке: сумму не вытащили в `ВТ_Комплектующие`; пропали виды субконто в запросе остатков.
- Результат на тесте: рыбный комплект: списание 1 «Абуди-вдув» + 1 «Бадьян» = 2 × 1000 … (сумма продаж 10 000, 25 000 продуктовый).

## Спорный вопрос: контроль остатков в цикле или пакетным запросом
Зритель Иванча: проверять остатки отдельным пакетным запросом до формирования движений (не формировать «149 строк из 150»). Автор: идея равноценна и допустима, но **канонический способ (Белоусов) — в цикле**; экзаменатор привык к стандартной схеме; ситуация нехватки — «скорее исключительная» (пользователь подбирает по остаткам), поэтому лишний запрос и лишняя таблица обычно не нужны. «Если есть точная информация, как любит экзаменатор, лучше следовать».

## Отчёт «Продажа комплектов»
- `Управленческий.Обороты(&Начало, &Конец, , Счет = &ПрибылиИУбытки, &ВидыСубконтоНоменклатура, , КорСчет В (&Покупатели, &Товары))`: `Субконто1 = комплект` (`ВЫРАЗИТЬ(… КАК Справочник.Номенклатура)` — «пока не расширяют»), `СуммаОборотДт` — себестоимость (корсчёт «Товары»), `СуммаОборотКт` — сумма продажи (корсчёт «Покупатели»); корсчета — обязательно.
- СКД: «Период», «ВидыСубконто», счета; детальные записи: комплект, продажа, себестоимость.

## Дополнения
- **Бухгалтерские задачи решаются только по старой методике проведения** (в проводках всегда есть сумма → нужна себестоимость; новая — «чисто оперативный учёт», да и там — несколько задач).
- Автор: «в этой задаче и в предыдущей про сборку решения разные — в каждом билете своя постановка».
