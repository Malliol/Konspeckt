# Урок 46. Себестоимость по инвентарному номеру (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=r-Dz7QlPw24 · 91 мин · [полный текст](../transcripts/046_r-Dz7QlPw24.md)

## О чём урок
Бухгалтерская задача (билет № 8 по нумерации автора): штучный учёт товаров по **инвентарным номерам**, себестоимость по каждому номеру, **сотрудник-продавец с произвольными свойствами** (образование и т. п.), отчёт по продажам. База — выгрузка занятия 41.

## Работа над ошибками (урок 43)
В запросе расходной накладной (урок 43) итог по **сумме остатка** был лишним: для расчёта себестоимости хватает детальных записей, а в итоговой записи использовались только количество и количество остатка. Лишнее — потенциальное замечание экзаменатора.

## Условие
- **Приходная накладная:** каждая единица товара — **отдельной строкой с количеством = 1**; каждой единице присваивается **уникальный инвентарный номер** (за уникальностью следит пользователь). Проводка Дт «Товары» — Кт «Поставщики».
- **Расходная накладная:** контроль наличия товара **по инвентарному номеру**; **себестоимость по каждому инвентарному номеру**; проводки Дт «Прибыли и убытки» — Кт «Товары» (себестоимость) и Дт «Покупатели» — Кт «Прибыли и убытки» (продажа). **Указывается сотрудник**, совершивший продажу; для сотрудников нужны **свойства** (пол, образование…).
- Отчёт «Продажи по сотрудникам»: сотрудник (+свойство «Образование»), товар, себестоимость, сумма продаж.

## Количество = 1
- Обязательно ли ограничивать — нет (люди сдают без запретов; некоторые просто удаляют колонку «Количество» — автору это не нравится: противоречит формулировке и усложняет алгоритмы).
- Автор делает: у колонки «Количество» — «только просмотр»; в событии табличной части «ПриНачалеРедактирования» при новой строке: `ТекущиеДанные = Элементы.СписокНоменклатуры.ТекущиеДанные; ТекущиеДанные.Количество = 1`. Для расходной накладной — то же. Дополнительно можно задать мин./макс. значение 1 (необязательно). Вывод: «количество можно зашить в коде — этого достаточно».

## Справочник «ИнвентарныеНомера»
- Длина **наименования = 0** (наименование отключено), длина **кода 4 символа**, **автонумерация выключена** (вводят вручную), поля ввода по строке — только код; **контроль уникальности кода** — включить.
- Владелец справочника — номенклатура, **контроль уникальности «в пределах подчинения владельцу»** (номер уникален в пределах номенклатуры: у кинокамеры и портсигара может быть «0001»). На курсах 1С.рф принято «уникальный во всей базе» — оба варианта оценку не снижают.
- Связь параметров выбора: «Инвентарный номер» → отбор по владельцу из поля «Номенклатура» (в приходной и расходной накладных).
- Реквизит «Инвентарный номер» в табличной части (проверка заполнения, на форме). Пользователь по-прежнему может ввести несколько одинаковых строк или количество 2 — **это не контролируют** («за уникальностью следит пользователь»).

## План счетов
- Максимум субконто — **3**: «Номенклатура», «ИнвентарныеНомера», **«ФизическиеЛица»** (универсальное имя вместо «Сотрудники»; ПВХ «ВидыСубконто» → составной тип: добавить справочники «ИнвентарныеНомера» и «ФизическиеЛица»).
- Счёт «Товары»: субконто — номенклатура и инвентарный номер; счёт «Прибыли и убытки»: номенклатура, инвентарный номер, физическое лицо — для отчёта по продажам; «только обороты» (общее правило).
- Обновить документ «Операция» (таблицу с формы заново).

## Приход
Запрос (сгруппировать: номенклатура, инвентарный номер, количество, сумма; отбор по ссылке). Проводка: Дт «Товары» (СубконтоДт номенклатура и инвентарный номер, `КоличествоДт`, сумма) — Кт «Поставщики» (без субконто; количества нет). **Свёртка в запросе** защищает от дублей пользователя (две строки с одним номером сложатся, а не потеряются).

## Количественный учёт: обсуждение
В условии нет слов «на количество и сумму себестоимости» (на счёте «Товары» у Прохожего/1С.рф количество ведётся). Автор сначала отключил количественный учёт (по замечанию «буковки»: без количества можно контролировать остатки по сумме остатка > 0), потом вернул: «отсутствие количественного учёта по товарам — нонсенс» — на курсах и у Прохожего он есть; контроль остатков по количеству нужен, даже если в условии не сказано; в проводке `КоличествоДт`/`КоличествоКт` по счёту «Товары». Условие по количеству не указано в задаче — это невнимательность формулировки, а не запрет. При вопросах на экзамене — сообщить автору.

## Расходная накладная
1. Реквизит «Сотрудник» (справочник «ФизическиеЛица», проверка заполнения, на форме).
2. Запрос: `ВТ_Товары` (номенклатура, инвентарный номер, количество, сумма; индексы по номенклатуре и инвентарному номеру) ЛЕВОЕ СОЕДИНЕНИЕ `Управленческий.Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконто, (Субконто1, Субконто2) В (SELECT номенклатура, инвентарный номер из ВТ_Товары))` по номенклатуре и инвентарному номеру; `ЕСТЬNULL` для остатков (иначе платформа бросит ошибку вместо вашего сообщения). **Виды субконто — массив из двух видов**. Итоги не нужны (сумма и количество — по строке).
3. Контроль остатков: `Количество > КоличествоОстаток` → «Недостаточно товара %1 с инвентарным номером %2 в количестве %3», `Отказ = Истина`, `Продолжить`.
4. Проводка списания: Дт «Прибыли и убытки» — Кт «Товары»; **субконто Дт**: номенклатура, инвентарный номер, **физическое лицо = сотрудник из шапки**; субконто Кт: номенклатура, инвентарный номер; `КоличествоКт`; сумма = **себестоимость**.
5. **Себестоимость с условием последнего списания:** если `Количество = КоличествоОстаток` → `Себестоимость = СуммаОстаток`; иначе `СуммаОстаток / КоличествоОстаток × Количество`. (Количество обычно 1 = остатку, но пользователь может ввести 2 — условие страхует.)
6. Проводка продажи: Дт «Покупатели» — Кт «Прибыли и убытки» с теми же разрезами (субконто Кт для прибылей и убытков) и `Сумма = Выборка.Сумма` (в цикле по строкам).
7. Блокировка: регистр бухгалтерии «Управленческий», исключительная; **счёт «Товары»**; номенклатура и инвентарный номер из списка номенклатуры (`ИсточникДанных` = табличная часть, поле через вид субконто «Номенклатура» и «ИнвентарныеНомера»).

## Характеристики (свойства) сотрудников
- Справочник «ЗначенияСвойствОбъектов» (владелец — ПВХ), ПВХ «СвойстваОбъектов» (составной тип — добавить справочник значений), регистр сведений **«ЗначенияСвойствСотрудников»**: измерение «Сотрудник» (ФизическиеЛица), измерение «Свойство» (ПВХ), ресурс «Значение» (составной тип, связи параметров выбора как раньше, «Создание при вводе»). Данные: у Васиной — «Образование» = среднее.
- **Вытаскивание свойств в отчёте:** у справочника «ФизическиеЛица» → «Характеристики» → указать «Виды характеристик» (ПВХ), «Значения характеристик» (регистр сведений), поля для типа/значения — тогда в СКД в пользовательском режиме можно выводить свойства сотрудника; «Расположение реквизитов» — «отдельно» (в других колонках).
- Если нужно зашить свойство «в конфигурацию»: сохранить настройки варианта в файл и «Загрузить настройки из файла» в конфигураторе (как делает Белоусов; поле отмечено крестиком — запрос его не возвращает, но настройка остаётся стандартной). Автор: «странная ситуация», лучше дать пользователю самому.

## Отчёт «Продажи по сотрудникам»
- Запрос: `Управленческий.Обороты(&НачалоПериода, &КонецПериода, , Счет = &ПрибылиИУбытки, &ВидыСубконто, , КорСчет В (&Товары, &Покупатели))`; `СуммаОборотДт` — себестоимость (корсчёт «Товары»), `СуммаОборотКт` — сумма продажи (корсчёт «Покупатели»). Субконто 1/2/3 — номенклатура, инвентарный номер, физическое лицо. **Корреспонденцию счетов указывать обязательно** (−1–1,5 балла).
- `ВЫРАЗИТЬ(Субконто1 КАК Справочник.Номенклатура)` и т. д. — желательно (сегодня не снижают оценку, «завтра могут»).
- СКД: параметры «Период», «ВидыСубконто» (список из трёх видов), счета (покупатели, прибыли и убытки, товары) — без списка значений; «Период» — в пользовательские настройки; группировка/детальные записи: сотрудник, номенклатура (+ инвентарный номер в представлении: `Номенклатура.Наименование + "/" + ИнвентарныйНомер.Код`), себестоимость, сумма продаж.
