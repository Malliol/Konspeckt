# Урок 17. Стеллажи и комплектующие. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=51E-Hc80gp0 · 101 мин · [полный текст](../transcripts/017_51E-Hc80gp0.md)

## О чём урок
Сложный билет (по нумерации автора — № 6): торговля стеллажами и комплектующими; **стеллаж при продаже автоматически раскладывается на комплектующие**. Нужна новая методика проведения, регистр состава стеллажей с требованием уникальности деталей и отчёт «Наличие деталей на дату». Основа — выгрузка после урока 3 (новая методика).

## Условие билета (суть)
- Оптовая торговля стеллажами и комплектующими. Закупка — приходная накладная, продажа — расходная.
- **Учёт себестоимости вести не требуется** → нужна и допустима **новая методика проведения** (экзаменатор это обязательно проверит).
- Каждый стеллаж — набор комплектующих; **одна деталь не может относиться к разным стеллажам** (уникальность).
- Покупаются только комплектующие, продаются и комплектующие, и стеллажи (стеллаж при продаже раскладывается на комплектующие).
- Складской учёт ведётся (если в варианте не ведётся — просто убрать склад).
- Позже в актуальных билетах к этому добавились **характеристики стеллажей** (план видов характеристик) — это отдельная тема, автор разберёт позже (билет № 9 по его нумерации).

## Конфигурация
- Перечисление «ВидыНоменклатуры» заменяется на **«Комплектующая»** и **«Стеллаж»** (вместо товар/услуга; если появятся другие виды, конфигурацию придётся менять — постановка именно такая).
- Реквизит «ВидНоменклатуры» в номенклатуре (проверка заполнения — «Выдавать ошибку»).
- В приходной накладной параметры выбора: только «Комплектующая». В расходной — оба вида.

### Регистр сведений «СоставСтеллажей»
- Измерение «**Комплектующая**» (единственное измерение!), ресурсы «Стеллаж» и «Количество» (количество — как везде, 10 знаков, 0 точность; можно перетащить мышью из другого регистра).
- **Уникальность обеспечивается структурой регистра**: записи регистра сведений уникальны по сочетанию измерений. Если комплектующая — единственное измерение, одна деталь не может попасть в два стеллажа, и **ни строки кода не нужно**. Проверка `ПередЗаписью` в наборе записей, как делают некоторые, — неправильное решение. (Автор уверен, что при снижении оценки за такую структуру экзаменатор ошибается.)
- Периодичность **не использовать**: с периодом пришлось бы разные периоды допускать для одной детали в разных стеллажах — уникальность была бы нарушена; в реальной задаче такого требования нет, это «академический пунктик». Оптимальный компромисс — непериодический регистр.
- Свойства: у измерения — «Ведущее» и «Запрет незаполненных значений»; у ресурса «Стеллаж» — параметры выбора по виду номенклатуры (только «Стеллаж»), у измерения «Комплектующая» — только «Комплектующая».
- Регистр выводят в командный интерфейс.

## Расходная накладная (новая методика)
**Разложение стеллажей на комплектующие запросом:**
1. Запрос 1: табличная часть расходной накладной, группировка по номенклатуре, ссылка → временная таблица `ВТ_Товары` (Номенклатура, **ВидНоменклатуры**, Количество), индекс по номенклатуре.
2. Запрос 2 (результат — `ВТ_Комплектующие`): левое соединение `ВТ_Товары` с `СоставСтеллажей` **по стеллажу** (`ВТ_Товары.Номенклатура = Состав.Стеллаж`); поля:
   - Комплектующая: если соединение удалось — комплектующая из регистра, иначе (если вид номенклатуры «Комплектующая») — номенклатура из табличной части: `ВЫБОР КОГДА Состав.Комплектующая ЕСТЬ NULL ТОГДА ВЫБОР КОГДА ВТ_Товары.ВидНоменклатуры = Комплектующая ТОГДА ВТ_Товары.Номенклатура КОНЕЦ ИНАЧЕ Состав.Комплектующая КОНЕЦ`;
   - Количество: `Состав.Количество * ВТ_Товары.Количество`, а если соединения нет — количество из табличной части (проверка по виду номенклатуры аналогично).
   Если не добавить проверку вида, **стеллаж без определённого состава** попал бы в колонку комплектующих и пытался бы двигаться по регистру остатков — это неправильно. С проверкой вида в таких случаях в колонке будет `NULL`.
3. Запрос 3 (проверка): «НоменклатураПродажи» (стеллаж) из временной таблицы там, где «Комплектующая» `ЕСТЬ NULL` — стеллаж без состава.
4. Запрос 4 (данные для движений): `ВЫБРАТЬ Склад, Период, Комплектующая КАК Номенклатура, СУММА(Количество) ... СГРУППИРОВАТЬ` по комплектующей (схлопывание); склад и период — параметры.
5. **Пакет запросов** (несколько запросов в одном тексте, а не временные таблицы) выполняют методом `ВыполнитьПакет()`; результат — **массив результатов запросов** (нумерация с 0). Нужный результат берут по индексу: `Результаты[2]`.
   Для временных таблиц, созданных в одном запросе, используемых другим, нужен **`МенеджерВременныхТаблиц`**, привязанный ко всем запросам (иначе временные таблицы уничтожаются после выполнения). Автор использует отдельные переменные запросов для наглядности (в курсах 1С:Образования подменяют тексты у одного запроса — он считает это «франкенштейном»).
6. **Проверка** состава: результат запроса 3 не пустой → `Отказ = Истина`, сообщения «Не определён состав стеллажа %1» в цикле (много стеллажей может быть без состава); сразу `Возврат` (движения не формируем).
7. Движения: обход результата запроса 4, `Движения.ОстаткиНоменклатуры.Добавить()`, расход, заполнение значений свойств.
8. **`Записывать = Истина`** (в новой методике удобнее взводить перед записью), **`БлокироватьДляИзменения = Истина`** (отключение разделения итогов), `Движения.Записать()`.
9. **Контроль остатков после записи** отдельным запросом (тот же менеджер временных таблиц):
   - `Остатки(&Граница, Склад = &Склад И Номенклатура В (ВЫБРАТЬ Номенклатура ИЗ ВТ_Комплектующие))`; граница «Включая»;
   - остатки считают по **разложенной таблице** (не по `ВТ_Товары`, где стеллажи!), иначе нехватку по комплектующим стеллажа не увидеть (допущенная в уроке ошибка);
   - только отрицательные остатки; для сообщения нужны: представление номенклатуры, `-КоличествоОстаток` (количество нехватки).
   - Если результат не пустой: `Отказ`, сообщения «Недостаточно комплектующих %1 в количестве %2».
10. **Улучшение сообщения (компромисс):** соединить отрицательные остатки с составом стеллажей и вывести стеллаж, в состав которого входит нехватающая комплектующая: «Недостаточно комплектующих %1 (входит в состав стеллажа %3) в количестве %2». Если стеллаж пуст (`NULL`), другое сообщение. Идеальный вариант — разбить нехватку на «из них N входит в состав стеллажа…, остальные — отдельные комплектующие», но это долго и на экзамене не нужно. Идея привязки сообщения к строке (двойной клик) — вне экзамена, но в работе нужна.
- Блокировать нужно только регистр накопления (автоматически при записи в новой методике); регистр сведений блокировать не надо.
- Замечание зрителя: умножать количество можно в виде проверки на `ЕСТЬNULL` до или после умножения — равноценно.

## Отчёт «Наличие деталей на дату» (билет)
- Запрос: остатки номенклатуры (`ОстаткиНоменклатуры.Остатки`) с левым соединением к `СоставСтеллажей` **по комплектующей** (не по стеллажу). Поля: склад, стеллаж (может быть `NULL` — деталь не входит ни в один стеллаж, это нормально и полезно пользователю), деталь (номенклатура), количество.
- Ресурсы не нужны, итогов нет. Параметр «Период» (дата и время, использование всегда, запрет пустого значения).
- Структура: группировки «Склад» → «Стеллаж» → детальные записи; расположение полей группировок — «Отдельно и только в итогах».
- Сортировка: склад, стеллаж, деталь; но если задан **заголовок группировкой**, сортировка по такой группировке вызывает ошибку «Поле Деталь не может быть использовано в группировке». Решение: сортировку делать **в самих группировках** (склад — по складу, стеллаж — по стеллажу, детальные записи — по детали), а не на уровне отчёта.
- Условное оформление: влево, отступ 1 символ, заголовки полей жирные и по центру; область использования — группировка (в прошлом уроке её забыли).
- Заголовок «Наличие деталей на дату [Период] г.»: группировка «Заголовок» (детальные записи, дополнительная информация), макет группировки; формат даты в макете. Пустую строку между заголовком и таблицей убирают подчинением группировки «Склад» заголовку; тогда у склада нужно включить макет оформления.
- Количество: минимальная ширина 8–10 символов.

## Замечания
- Сертификат сам по себе не повышает зарплату, но квалификацию повышает умение решать эти задачи.
- Принцип KISS: не делать лишнего.
