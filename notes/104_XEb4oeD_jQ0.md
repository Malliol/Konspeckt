# Урок 104. Компенсация затрат на обеды: рабочие дни в допначислениях (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=XEb4oeD_jQ0 · ~1 ч 10 мин · [полный текст](../transcripts/104_XEb4oeD_jQ0.md)

## О чём урок
Билет № 10 (продолжение): **«компенсация затрат на обеды»** — «казалась безобидной», но требует рабочих дней по графику для **дополнительного начисления** (у него нет периода действия, поэтому «ДанныеГрафика» недоступны). Разобраны **три способа**, константа, и важные ошибки.

## Условие (смысл)
**Компенсация затрат на обеды = процент от суммы начислений по тарифу за текущий период × (отработанные дни / рабочие дни за период)**: «за каждый отработанный день компенсируем часть» (процент хранится — константа, 5 %). Вид расчёта — **в «ДополнительныхНачислениях»** (нет начала/конца), база — «оплата по часовому тарифу» (по периоду действия), **базовый период — месяц периода регистрации** (`БазовыйПериодНачало = ПериодРегистрации`, `БазовыйПериодКонец = КонецМесяца(ПериодРегистрации)`).

## Константа вместо числа
**Если число присутствует в постановке — хранить в константе** (в уроке: «ПроцентКомпенсацииЗатратНаОбед» 5/2; в подсистему через «Дополнительно → Подсистема»; не писать `0,05` в коде — «недочёт»). Получать константу можно просто `Константы…Получить()` (не обязательно в запросе).

## Способ 1 (популярный, «не нравится автору»): ресурсы НормаДней/ОтработаноДней и максимум в базе
- Регистр сведений «ГрафикРаботы»: ресурсы «Часов» (8/0) и «Дней» (1/0, **выходные — 0**: в видео из-за ошибки получилось 31 день — выходные «1»; исправить обработку заполнения); регистр расчёта «ОсновныеНачисления» — **ресурсы «ОтработаноДней» и «НормаДней»** (заполняются из `ДанныеГрафика`: `ЕСТЬNULL(ЗначениеДнейФактическийПериодДействия, 0)`, `…ПериодДействия`); регистр «ДополнительныеНачисления» (по образцу основных; **базовый период — вкл.**, реквизиты «ОтработаноДней», «БазаНачислений», «БазаРабочихДней», «ПроцентКомпенсацииЗатратНаОбед»).
- **Стороно-записи:** `Если Движение.Сторно Тогда Движение.НормаДней = 0` (**обнулять норму дней**; иначе удваивается); отработанные дни — сторнируются (`?(Сторно, -1, 1)`).
- Запрос расчёта компенсации: **база в разрезе номера строки с `МАКСИМУМ` нормы дней** (разрезы = {НомерСтроки}); `База(&Измерения, &Разрезы, , Регистратор = &Ссылка И ВидРасчета В (&ВидыРасчета))`: `НомерСтрокиРазрез` (служебное поле; **без него всё схлопнется**), `РезультатБаза`, `ОтработаноДнейБаза` (СУММА), `НормаДнейБаза` (МАКСИМУМ); результат — во временную таблицу «ВТ_База» (индекс по номеру строки); затем **основная таблица допначислений (`Регистратор`, `ВидРасчета`) ЛЕВОЕ соединение с «ВТ_База» по номеру строки** (ЕСТЬNULL для базы; **значение константы выводить из основной таблицы**: иначе при отсутствии базы константа не подтянется, а мы хотим заполнять параметры расчёта всегда).
- Цикл: `Результат = ?(Выборка.БазаРабочихДней <> 0, Выборка.ОтработаноДней * Выборка.БазаНачислений / Выборка.БазаРабочихДней * Выборка.Процент / 100, 0)`; `ЗаполнитьЗначенияСвойств(Движение, Выборка, "ОтработаноДней, БазаНачислений, БазаРабочихДней, Процент…")`; `Записать()`.
- **Недостатки:** сторно ресурсов обнулением («так не делают в типовых — ресурсов “нормо-часы” там нет»); при переводе сотрудника на другие графики/подразделения в течение месяца норма дней **суммируется (41 день!)** — максимум «компромиссный» и спорный («1 день по шестидневке увеличил норму»). Но «наиболее популярное; экзаменатор съест».

## Способ 2 (идея): компенсация — в основных начислениях
Создать вид расчёта «КомпенсацияЗатратНаОбеды» **в «ОсновныхНачислениях»** с принудительными датами (программно подставлять начало/конец месяца; условное оформление — поля дат недоступны) → тогда можно получать «ДанныеГрафика» без баз и обнулений. Минус: нарушается логика (нет периода действия; пользователь может задать интервал).

## Способ 3 (рекомендуемый автором): рабочие дни — из регистра сведений напрямую
- Базу получать **без разрезов и без нормы дней**: `База(&Измерения, , , Регистратор = &Ссылка И ВидРасчета В (&ВидыРасчета))`: `РезультатБаза`, `ОтработаноДнейБаза`. (В регистре расчёта «ОтработаноДней» — ресурс (сумма дней по сегментам), «НормаДней» не нужна — в «ЗУП» такого ресурса нет.)
- **График для допначислений: реквизит «ГрафикРаботы» в регистре «ДополнительныеНачисления» и в табличной части документа** (параметр для расчёта; «связь с графиком» не настраивать; проверку заполнения — не включать; условное оформление «график только для компенсации» — на экзамене не делать).
- Запрос «рабочие дни по графикам»: из `РегистрСведений.ГрафикРаботы` **в разрезе графиков, а не номеров строк**: `ГрафикРаботы В (ВЫБРАТЬ ГрафикРаботы ИЗ ВТ_Основная)`, `Дата МЕЖДУ &НачалоПериода И &КонецПериода`, **`СУММА(Дней)`** → «РабочихДней» (ВТ, индекс по графику) → затем **левое соединение с основной таблицей по графику** (а не «разворачиваем 30 записей на каждую строку» — при 5 000 строк и двух графиках в 5 000 раз тяжелее). Условия соединения/параметров: **конец периода регистрации — параметром** (не выражением в соединении).
- Результат: `Результат = Выборка.ОтработаноДней * Выборка.БазаНачислений / Выборка.БазаРабочихДней * Выборка.Процент / 100`; при «БазаРабочихДней = 0» — 0.
- **Автор: «нет ничего плохого в том, чтобы тянуть данные из регистра сведений; не нарушает стандарты и не проблема производительности»** — «−2 балла за получение данных графика не через `ДанныеГрафика`» относится к случаю, когда **можно** было использовать «ДанныеГрафика»; здесь иначе никак (допначисление — период действия нет). В пояснительной записке обязательно написать: «график из регистра сведений получен напрямую, т.к. в регистре дополнительных начислений нет периода действия».

## Ошибки/нюансы урока
- **Одинаковые имена таблицы и поля** (конфликт «значения неоднозначно»): таблица константы «ПроцентКомпенсацииЗатратНаОбед» и поле с тем же именем → переименовать псевдоним поля (напр. «ПроцентКомпенсации»).
- **«Базовый» флажок** — **у измерений в обоих регистрах** (в том, который рассчитываем, и в том, из которого получаем базу): «индексируются поля соединения при получении базы с двух сторон».
- Для основной таблицы в документе — убрать «Выдавать ошибку» с обеих ТЧ; пустой документ — в `ОбработкаПроверкиЗаполнения` (`Если ОсновныеНачисления.Количество() = 0 И ДополнительныеНачисления.Количество() = 0`).
- Исправлена запись выходных: в обработке заполнения графика «Дней» для выходного — 0.
- Проверка конструкции «?»: `?(Сторно, -1, 1)` — писать именно так.
- Ошибка заполнения периода: при тестировании «за октябрь» убедиться, что график заполнен до месяца.
