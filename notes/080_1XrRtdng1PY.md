# Урок 80. Способы расчёта и приоритеты (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=1XrRtdng1PY · ~40 мин · [полный текст](../transcripts/080_1XrRtdng1PY.md)

## О чём урок
Работа над ошибками (сторно и база) и последняя фраза **билета № 4**: **«необходимо предоставить пользователю возможность самостоятельно создавать новые виды расчёта и привязывать их к существующим алгоритмам расчёта»** — решение через **перечисление «Способы расчёта»**, а «как любит Белоусов» — ещё и с **приоритетами**.

## Работа над ошибками
### Сторно ломает базу (замечание зрителя Андрея М.)
После сторнирования по таблице дополнения (урок 72) база командировки получилась неверной (268 тыс. вместо 176 тыс.): запись сторно **копируется целиком, вместе с ресурсами** («Результат», «ОтработаноЧасов») — они попадают в базу и увеличивают её. Решения:
- обнулить ресурсы в сторно-записях (результат, отработано часов; параметры можно оставить), **либо лучше —**
- **не использовать `ЗаполнитьЗначенияСвойств(Движение, Строка)` целиком**, а явно присваивать **только нужные поля**: **измерения (сотрудник, подразделение), вид расчёта, график работы** (график — чтобы `ДанныеГрафика` посчитал период) + три поля сторно (период регистрации, период действия начало/конец, `Сторно = Истина`). Остальное остаётся нулевым. Белоусов так и делает (поэлементно, без «заполнить значения свойств»). Код «по курсам 1С.рф» (копирование всей строки) работает, только пока нет расчёта по базе.

### Отбор по виду расчёта
Даже если в плане видов расчёта один вид — **всегда задавать отбор `ВидРасчета = &Вид`** в запросах расчёта (где реализуется алгоритм именно для этого вида) и **писать условие `Если Выборка.НайтиСледующий(...)`** (в табличной части могут быть и другие виды). Иначе при появлении нового вида (например «оклад госдепа») алгоритм «случайно» сработает и для него. В прошлых уроках автор это не исправляет (белоусов тоже не делает) — «лучше так».

## Способ 1 (курсы 1С.рф): перечисление «Способы расчёта»
- Создать **перечисление «СпособыРасчёта»** (значения-описания алгоритмов, не названия видов): «ОплатаПоЧасовомуТарифу», «ПроцентОтОплатыПодчинённыхЗаПрошлыйМесяц».
- В планах видов расчёта «ОсновныеНачисления» и «ДополнительныеНачисления» — **реквизит «СпособРасчёта»** (тип — перечисление, «Выдавать ошибку»). В пользовательском режиме для каждого вида расчёта задаётся способ (один и тот же способ можно привязать к любому числу видов).
- В коде запросов вместо отбора по виду расчёта — **отбор по `ВидРасчета.СпособРасчета = &СпособРасчета`**; в цикле `Движение.ВидРасчета.СпособРасчета`. Для всех видов с заданным способом выполняется один алгоритм.
- Одно перечисление для всех планов (никто не делает отдельные для основных/дополнительных).
- Проверка: «оклад госдепа» с способом «оплата по часовому тарифу» считается; если способ не указан или не подходит для плана — не считается.

## Способ 2 (Белоусов): способы расчёта + приоритеты
Белоусов: «Какие приоритеты? Вы не дали пользователю полных возможностей — **он не может определить порядок расчёта**» — фразу о «создании новых видов расчёта» он понимает как требование **приоритета** (порядок «основные → дополнительные» не должен быть жёстко зашит). С точки зрения курсов 1С.рф без приоритетов — ок, с точки зрения Белоусова — ошибка (поэтому на экзамене делать с приоритетами).
- В планах видов расчёта — реквизит **«Приоритет»** (число, длина 3; обязателен) в **каждом** плане (основные и дополнительные); приоритет оклада = 1, премии = 2 (порядок важен, если база премии — оклад текущего месяца).
- В документе — запрос **«конструктор запроса с обработкой результата»**: из каждой табличной части («ОсновныеНачисления», «ДополнительныеНачисления») выбрать `ВидРасчета.СпособРасчета` и `ВидРасчета.Приоритет` по регистратору → **`ОБЪЕДИНИТЬ` (без «ВСЕ»)**, чтобы не было повторяющихся комбинаций (флажок «Без дубликатов»/«ВСЕ» снять), **`УПОРЯДОЧИТЬ ПО Приоритет`**.
- В `ОбработкаПроведения` — **цикл по этой выборке (комбинации «способ — приоритет»)**: `Если Выборка.СпособРасчета = Перечисления.СпособыРасчета.ОплатаПоЧасовомуТарифу Тогда` … алгоритм расчёта часовой оплаты (запрос по `ДанныеГрафика`, цикл по движениям, `Записать(, Истина)`) `ИначеЕсли … ПроцентОтОплатыПодчинённых Тогда` … алгоритм премии (база, разрезы, `Записать()`); внутри — отбор `СпособРасчета = Выборка.СпособРасчета` (и приоритета).
- Т.е. порядок расчёта задаёт пользователь приоритетами, а не жёсткая последовательность в коде. Можно «из каприза» посчитать сначала премию, потом оплату.
- **Запросы в цикле** — формально запрещены (−2 балла), но здесь итераций мало (число комбинаций способ/приоритет — штук 5–6), так делает и Белоусов; без цикла пришлось бы писать `Если Приоритет = 1 … Если Приоритет = 2…`, то есть цикл — лучше. «Разрешённые запросы в цикле» — двойной стандарт (автор просит экзаменаторов обозначить разницу).
