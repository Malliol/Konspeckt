# Урок 100. Больничный, входящий в базу больничного; рабочие дни по двум графикам (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=U7Ik96scIOs · ~1 ч · [полный текст](../transcripts/100_U7Ik96scIOs.md)

## О чём урок
Билет № 15 («диаграмма Ганта» — отдельная тема в следующем стриме). Условие почти как в билете из урока 99, но есть **три нюанса**, из-за которых «то же решение» даёт **неправильный результат**: больничный входит в базу больничного, дни болезни — по пятидневке (а рабочие дни базы — по сменному графику), «запрос в цикле по периодам действия».

## Условие (смысл)
- Метод отклонений; совместительства нет (подразделение убрано); сотрудники работают **в три смены «сутки через двое»** (сменный график, урок 78); оплата по окладу **по часам**; больничный — как в уроке 99; **произвольная сумма денег**: «в любой момент времени каждому сотруднику может быть начислено поощрение в виде произвольной суммы»; сторно (задним числом); отчёт по начислениям.
- **Больничный: средняя дневная ставка = сумма ВСЕХ начислений (в т.ч. больничных) за предыдущий месяц / количество рабочих дней в предыдущем месяце; дни болезни — по пятидневке.**
- Заготовка автора: основные и дополнительные начисления, сторно — «как в прошлой задаче».

## Нюанс 1. Больничный входит в базу больничного
- В плане видов расчёта «Основные начисления», у вида **«Больничный»** на закладке «Базовые» — **«Больничный» тоже отмечен** (и «Оклад»). (Больничный **не должен вытеснять больничный** — «ошибка ввода»; поэтому «Больничный» не вытесняет «Больничный».)
- Тест: больничный за август (база июль: 100 000), за сентябрь (оклад сентября 100 000 − сторно 20 000 + больничный за август 20 000 = 100 000 ← база!) и за октябрь. В решении «одним циклом» базы получились 80 000 вместо 100 000: **расчёт больничного идёт одним запросом/циклом вперемешку, а запись — в конце**, поэтому база сентябрьского больничного **не видит** результата августовского.

## Решение: запрос в цикле по периодам действия (разрешённый случай)
Считать больничные **последовательно по возрастанию периода действия** и **записывать каждый результат** в базу, прежде чем считать следующий:
```bsl
// запрос: РАЗЛИЧНЫЕ ПериодДействияНачало из ОсновныеНачисления (Регистратор = &Ссылка, ВидРасчета = &Больничный)
// УПОРЯДОЧИТЬ ПО ПериодДействияНачало
Пока ВыборкаПоПериодамДействия.Следующий() Цикл
    // запрос данных графика и базы — ТОЛЬКО по записям с этим периодом действия:
    //   ... ПериодДействияНачало = &ПериодДействия
    // выборка.НайтиСледующий(...)
    // цикл по Движения.ОсновныеНачисления: Если Движение.ПериодДействияНачало <> ВыборкаПоПериодам.ПериодДействия Тогда Продолжить;
    Движения.ОсновныеНачисления.Записать(, Истина);       // запись после каждого периода!
КонецЦикла;
```
- Отбор «`Период действия = &ПериодДействия`» должен быть **и в данных графика, и в базе**; в цикле по движениям — `Если Движение.ПериодДействияНачало <> Период Тогда Продолжить;` вместо «`Если` найти следующее» без проверки.
- **Это «запрос в цикле», который можно** (альтернативы нет; итераций мало — число больничных). Белоусов такую задачу не разбирает. Выгрузка решения — по ссылке в описании.

## Нюанс 2. Дни болезни — по пятидневке
- **Не** «ставить пятидневку программно вместо графика» из-за лишних действий пользователя: **предопределённый элемент «Пятидневка»** в справочнике «ГрафикиРаботы» (код/наименование не искать, `Справочники.ГрафикиРаботы.Пятидневка`); в движении больничного **подменить график**: `Движение.ГрафикРаботы = Справочники.ГрафикиРаботы.Пятидневка`. Пятидневку заполнить (обработка заполнения; «67» выходные). Тогда `ОтработаноДней` (дни болезни) считаются по пятидневке — правильно.
- В базе рабочих дней — **график, указанный в записи** (после подмены — тоже пятидневка).

## Нюанс 3 (спорный): рабочие дни базы — по сменному графику
«Извращенцы» трактуют: **дни болезни — по пятидневке, а «рабочие дни за прошлый месяц» — по сменному графику** (смысл: график сотрудника). Автор считает трактовку **неверной** (при сменном графике ~10 дней/месяц и 22 дня болезни по пятидневке человек за болезнь получит 220 000 при окладе 100 000 — «выгодно болеть»; ТЗ этого явно не говорит; «мы переводчики»). Лучше брать **по пятидневке**. Но «для убеждённых» разобраны два способа:

### Популярное решение (неправильное)
- Отработанные дни **хранить в основных начислениях как ресурс «НормаДней»** (рабочие дни по графику оклада), а базу рабочих дней брать **из `База(…)` по полю «НормаДней»**. Проблемы: (а) надо **сторнировать и ресурс «НормаДней»** (`НормаДней * ?(Сторно, -1, 1)`), (б) каждый новый интервал/сторно **удваивает/обнуляет** нормы дней (в базе: 10 − 10 = 0; при двух больничных → 30 дней) — результат абсурдный. «Забудьте эту схему».

### Нормальное решение (регистр сведений)
- **Базу рабочих дней брать из регистра расчёта по графику записи (сменный график — подставлен в движении)**, а **дни болезни по пятидневке — из регистра сведений «ГрафикРаботы»**: отдельная временная таблица **«ДанныеГрафикаПоПятидневке»**:
  `ФактическийПериодДействия` (регистр расчёта; `Регистратор = &Ссылка`, `ВидРасчета В (&ВидыРасчета)`) → `НомерСтроки`, `ПериодДействияНачало`, `ПериодДействияКонец` → **соединение с `РегистрСведений.ГрафикРаботы` по условию `ПериодДействияНачало <= Дата И ПериодДействияКонец >= Дата И ГрафикРаботы = &Пятидневка`** (условие по графику — **в условии соединения как дополнительный отбор**, а не отдельным запросом/временной таблицей: «временные таблицы тяжёлые»), группировка по номеру строки, `СУММА(Дней)` → «ОтработаноДнейПоПятидневке» (`ЕСТЬNULL`).
- В основном запросе левое соединение `ВТ_ДанныеГрафика` с ней по номеру строки; результат больничного: `БазаНачислений / БазаРабочихДней * ОтработаноДнейПоПятидневке`.
- **Требование «получать данные графика через таблицы регистра сведений — −2 балла»** — для **вынужденных** случаев (нет возможности получить из «ДанныеГрафика») допускается; «люди боятся этих минусов и делают полнейшую дичь». То же — «запросы в цикле».
- Пример проверки: больничный строка 4 (5–10 октября) = 4 дня по пятидневке (2 по сменному), строка 5 (20–31 октября) = 8 дней.

## Прочее
- Приём «условие в соединении» — для таблицы только слева/справа: «Включить в условие дополнительно: `Графики.ГрафикРаботы = &Пятидневка`» (в левом соединении).
- Юмор про «тест Роршаха».
- В «нормальном решении» заготовка: удалить ресурс «НормаДней»; выгрузка «после занятия 100».
