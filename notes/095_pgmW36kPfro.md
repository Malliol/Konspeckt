# Урок 95. Документ «Зарплата к выплате» (простой способ) (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=pgmW36kPfro · ~25 мин · [полный текст](../transcripts/095_pgmW36kPfro.md)

## О чём урок
Билет с меняющимся окладом (уроки 93–94), следующее условие: **«В конфигурации необходимо создать документ “Зарплата к выплате”. Документ формируется по конкретному подразделению; предусмотреть возможность автоматического заполнения документа по остаткам невыплаченных сумм; отчёт — в разрезе сотрудников и видов расчёта»**. Два способа: **простецкий (рекомендуется делать на экзамене)** и «метод Белоусова» (разбирается позже, если будут желающие).

## Документ «ЗарплатаКВыплате»
- Подсистема «Расчёты»; **подразделение — реквизит документа** («Выдавать ошибку»), табличная часть **«Сотрудники»**: «Сотрудник» (физлицо, «Выдавать ошибку»), «ВидРасчета» (в простом способе — **план «ОсновныеНачисления»? / тип зависит**; см. ниже), «Сумма» (13/2, неотрицательная, «Выдавать ошибку»). **Оперативное проведение — запретить** (для зарплатных документов).
- **Вид расчёта в документе по-взрослому не нужен** (в типовых «ЗУП»: «сотрудник — 50 000»), но в билете отчёт требуется «в разрезе видов расчёта» → автор делает вид расчёта **измерением** (простой способ; метод Белоусова/1С.рф — вид расчёта — реквизит, а в ведомости указывается отдельно со сложными запросами и полными соединениями).

## Регистр накопления «ВзаиморасчётыССотрудниками»
- **«Остатки»** (учёт задолженности по зарплате), подсистема «Расчёты». Измерения: **«Сотрудник»**, **«Подразделение»** (выплаты — в разрезе подразделений), **«ВидРасчета»** (план видов расчёта — **`ПланВидовРасчетаСсылка`** — «ОсновныеНачисления/ДополнительныеНачисления/Удержания»: для простоты поле типа «любой вид расчёта» — составной тип), все с запретом незаполненных; ресурс «Сумма» (13/2). Регистраторы — «НачислениеЗарплаты» и «ЗарплатаКВыплате». (Название «Взаиморасчёты между сотрудниками» — неверное; правильно «Взаиморасчёты с сотрудниками».)

## Начисление: приход
В конце `ОбработкаПроведения` документа **«НачислениеЗарплаты»** — после всех расчётов (когда всё записано): **запрос по регистрам расчёта (основным и дополнительным), сгруппировать по сотруднику, подразделению, виду расчёта** (`СУММА(Результат)`), **`Регистратор = &Ссылка`** (поля называем так, чтобы регистр «съел» их без переименования — «Сумма»), результат — `ОБЪЕДИНИТЬ ВСЕ` основных и дополнительных (и удержания — со знаком); цикл по выборке: `Движение = Движения.ВзаиморасчетыССотрудниками.Добавить(); Движение.ВидДвижения = ВидДвиженияНакопления.Приход; Движение.Период = ПериодРегистрации (или Дата); ЗаполнитьЗначенияСвойств(Движение, Выборка);`, флажок **`Движения.ВзаиморасчетыССотрудниками.Записывать = Истина`** (в самом начале; запись набора произойдёт автоматически). Белоусов делает приход сразу при расчёте каждого вида — автор делает «в конце, один запрос».
- **Период** движения — по умолчанию период регистрации (момент возникновения задолженности).
- Остатки/обороты в пользовательском режиме смотреть **через отчёт «Остатки и обороты» регистра** — форму в конфигураторе не создавать (Белоусов создаёт).

## Выплата: расход
В `ОбработкаПроведения` «ЗарплатаКВыплате»: `Движения.ВзаиморасчетыССотрудниками.Записывать = Истина; Для Каждого Строка Из Сотрудники Цикл Движение = Движения.ВзаиморасчетыССотрудниками.Добавить(); Движение.ВидДвижения = ВидДвиженияНакопления.Расход; Движение.Период = Дата; Движение.Подразделение = Подразделение; ЗаполнитьЗначенияСвойств(Движение, Строка);`. Блокировки — при желании (проверка остатков при проведении «если не хватает — отказ»: **контроль остатков**: «если остатков нет — не проведётся»; обработка проверки заполнения с ошибкой «нет остатков» — см. ниже). Движения при перепроведении замещаются сами — очищать не нужно.

## Автозаполнение «Заполнить остатками»
- Команда формы **«ЗаполнитьОстатками»** (не называть «Заполнить» — типовое имя; **заголовок — «Заполнить остатками»**), клиент → сервер.
- Запрос: `РегистрНакопления.ВзаиморасчетыССотрудниками.Остатки(&Дата, Подразделение = &Подразделение)`: `Сотрудник`, `ВидРасчета`, `СуммаОстаток` → «Сумма». **Заполнение табличной части — обходом выборки, а не `Загрузить`/`ЗагрузитьЗначения`** («экзаменатор может не любить загрузку результата запроса»): `Объект.Сотрудники.Очистить(); Пока Выборка.Следующий() Цикл НоваяСтрока = Объект.Сотрудники.Добавить(); ЗаполнитьЗначенияСвойств(НоваяСтрока, Выборка); КонецЦикла;`.
- **Дата остатков:** можно `Объект.Дата` (моментом нельзя: при втором документе с тем же временем заполнение пустое); Прохоров — **`РеквизитФормыВЗначение("Объект").МоментВремени()`** (с **границей `Новый Граница(МоментВремени, ВидГраницы.Включая)`**) — «перебор»; Белоусов — остатки **на конец месяца включительно** (граница «Включая») или на начало следующего месяца. Автор — просто дата документа.
- **Защита от повторного заполнения/проведения:** если документ **проведён — заполнение остатками не выполнять** (снять проведение, иначе остаток уже списан): в обработчике команды `Если Объект.Проведен Тогда Сообщить("..."); Возврат; КонецЕсли` (или проверка в процедуре); проверка заполнения не даёт провести пустой (остатков нет). Тест: два документа подряд на одно время — второй не заполняется (остатков нет).
- `ВыборкаСбросить` здесь не нужен — только `Следующий()` по порядку (а не поиск `НайтиСледующий`).
