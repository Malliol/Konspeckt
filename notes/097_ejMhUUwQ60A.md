# Урок 97. Расчётно-платёжная ведомость по методу Белоусова, часть 2 (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=ejMhUUwQ60A · ~4 ч (с отладкой) · [полный текст](../transcripts/097_ejMhUUwQ60A.md)

## О чём урок
Та же задача (зарплата к выплате и ведомость), но **«как у Белоусова»**: **вид расчёта — реквизит**, а не измерение регистра накопления. Автор: «для экзамена это избыточно» (в экзамене сейчас такой задачи нет, но «всегда будьте готовы, что отчёт усложнят»). Урок включает долгую отладку; главные итоги — **полное соединение**, **максимум/ВычислитьВыражениеСГруппировкой**, **фигурные скобки для параметров СКД**.

## Отличие метода Белоусова
- В типовых (ЗУП 2.5/3.1) «Взаиморасчёты с сотрудниками» **без вида расчёта**, в документе «Зарплата к выплате» вида расчёта нет — при выплате неважно, по какому виду. Поэтому **у Белоусова «ВидРасчёта» — реквизит регистра накопления** («приход» — с видом расчёта, «расход» — **без вида**; отбор «вид расчёта заполнен → начисление, пуст → выплата»).
- Последствия: в **«ОстаткиИОбороты» нет вида расчёта** (реквизиты в виртуальных таблицах недоступны) → для ведомости нужны **детальные таблицы** движений и **попарные соединения**; выплату по видам расчёта вывести нельзя — только итог (поэтому в «белоусовском» отчёте вид расчёта выводится вместе с «начислено» в группе колонок).
- В документе «ЗарплатаКВыплате» — **без колонки вида расчёта**: «сотрудник, сумма»; при заполнении остатками **не группируют и не суммируют** (остатки сами свёрнуты). Для расхода вид расчёта не заполняется (пустая ссылка).

## Запрос ведомости: полные соединения
Временные таблицы (все — с отбором по подразделению и `Активность = ИСТИНА`; индексы по сотруднику):
1. `ВТ_ОстаткиНаНачало` — `ВзаиморасчетыССотрудниками.Остатки(&НачалоПериода, Подразделение = &Подразделение)`: `Сотрудник`, `СуммаОстаток` → «НачальноеСальдо».
2. `ВТ_Начислено` — **детальная таблица движений**, `ВидРасчета <> ПустаяСсылка` (признак «начислено»), период в границах месяца, группировка `Сотрудник, ВидРасчета`, `СУММА(Сумма)`.
3. `ВТ_Выплачено` — детальная таблица, `ВидРасчета = ПустаяСсылка` (пустая ссылка плана видов расчёта).
4. `ВТ_ОстаткиНаКонец` — `Остатки(&НачалоСледующегоМесяца, …)` («конец периода» + 1 секунда).
- **Объединение таблиц — через `ПОЛНОЕ СОЕДИНЕНИЕ`** (записи могут быть только в одной): `НачальноеСальдоНачислено` = `ВТ_ОстаткиНаНачало` ПОЛНОЕ СОЕДИНЕНИЕ `ВТ_Начислено` по сотруднику (**в каждом поле — `ЕСТЬNULL`, в том числе в «Сотрудник»**: `ЕСТЬNULL(Начислено.Сотрудник, НачальноеСальдо.Сотрудник)`); затем **соединение «с результатом предыдущего соединения»** (отдельная временная таблица), а не с одной из исходных; затем с «Выплачено», затем с «ОстаткиНаКонец». Поля соединений индексировать; «вид расчёта» выводить только из «Начислено».
- Параметры запроса: «НачалоПериода» = начало месяца, «КонецПериода» = конец месяца, «НачалоСледующегоМесяца» = **`ДобавитьКДате(КонецПериода(&Период, "Месяц"), "Секунда", 1)`** (в СКД; **в выражениях параметров — только те параметры, которые пользователь задаёт в интерфейсе**; простое `КонецПериода + 1` не работает).
- **Лучше было бы** объединение (`ОБЪЕДИНИТЬ ВСЕ`) с нулями: получилось бы проще — «полное соединение — это хуже во всех отношениях», но вид расчёта мешает. Вариант «3 объединения + 1 полное соединение» (гибрид): остатки/начислено/выплачено объединить без вида, затем один раз соединить с «начислено» по виду.
- На любом «полном» соединении **нужно писать `ЕСТЬNULL` везде** (иначе NULL в полях слева/справа).

## СКД
- Набор данных-запрос; ресурсы — 4 суммы. **Структура:** группировка по сотруднику + детальные записи (вид расчёта); ресурсы — **`МАКСИМУМ`** для величин без детализации по видам расчёта («НачальноеСальдо», «Выплачено», «КонечноеСальдо» — они повторяются в каждой строке вида расчёта, поэтому в группировке «Сотрудник» берём максимум; сумма удвоила/утроила бы). Для **«Начислено»** — `СУММА`.
- **Условное оформление:** в **детальных записях** скрыть повторяющиеся поля сальдо/выплачено — **«Текст» = пустой для оформляемых полей** (область — «только в группировке»/«детальные записи»).
- **Итоги (общий итог)** при максимуме считаются **неправильно** (максимум по всему отчёту). Решение: на закладке «Ресурсы» выражение — **`Сумма(ВычислитьВыражениеСГруппировкойМассив("Максимум(НачальноеСальдо)", "Сотрудник"))`** (= сумма по сотрудникам максимумов); аналогично для «Выплачено» и «КонечноеСальдо».
- **Автопозиция ресурсов — «не использовать»**, чтобы вид расчёта вывелся в нужное место; «номер по порядку» — системное поле «НомерПоПорядку» (перенести в группировку).
- Макет оформления отчёта — «море» (выделить итоги); «заголовок» — как в уроке 96 («Расчётно-платёжная ведомость № … за … по подразделению …», формат даты `ММММ гггг`).

## ГЛАВНЫЙ УРОК: фигурные скобки у параметра виртуальной таблицы
При получении остатков на конец периода «КонечноеСальдо» не выводилось/дублировало начальное: параметры виртуальной таблицы в запросе СКД **надо брать в фигурных скобках `{&Параметр}`** (`Остатки({&НачалоСледующегоМесяца}, …)`), иначе компоновщик **подменяет их значениями «периода» отчёта** (остатки на «начало периода» — одинаковые для начала и конца).
- Альтернатива (подсказка зрителя Евгения Чернова): на закладке **«Компоновка данных»** конструктора запроса явно указать параметры виртуальной таблицы («начало периода/конец периода» → параметры) — вместо фигурных скобок.
- Параметр, который заключён в `{…}`, нужно **заранее объявить** на закладке «Параметры» (например, «Период»): «Использование — всегда», запрет «не использовать» (иначе «Параметр не найден»).
- Автор: «Не забуду фигурные скобки в СКД на всю жизнь» (подобное было в одном из предыдущих занятий).
