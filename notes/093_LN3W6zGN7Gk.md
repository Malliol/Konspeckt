# Урок 93. Оклад, меняющийся в течение месяца: разбивка периода действия (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=LN3W6zGN7Gk · ~1 ч 15 мин · [полный текст](../transcripts/093_LN3W6zGN7Gk.md)

## О чём урок
Начало **«самой сложной» задачи по СПР** (билет № 2 по нумерации автора): **оклад меняется несколько раз в течение расчётного периода → одна строка документа должна «разбиваться» на несколько записей регистра расчёта с разным периодом действия и разным первоначальным окладом**. Автор советует **заранее подготовить решение** («на экзамене не изобретёшь» — Евгений Афанасьев рассказывал, что тоже не успел).

## Условие
- Метод отклонений; **совместительство не допускается** (убрать «Подразделение» из регистра расчёта, документа, регистра сведений).
- **Все сотрудники работают по графику, установленному для каждого подразделения** → подразделение выступает графиком: реквизит «ГрафикРаботы» заменён на **«Подразделение»** (регистр сведений «ГрафикРаботы» — измерение «Подразделение»; связь с графиком в регистре расчёта — «Подразделение»; обработка заполнения графика переписана на «Подразделение»; единица — часы).
- **Оклад — пропорционально отработанному времени в часах.**
- **В течение расчётного периода первоначальное значение оклада может быть неоднократно изменено; в базе необходимо хранить историю изменений; расчёт должен проводиться исходя из действующего на рассчитываемую дату значения оклада** (не на период регистрации!).
- Тест (Афанасьев): 01.01.21 — 100 000; 01.06.21 — 150 000; 25.09.21 — 200 000; **05.10.21 — 250 000; 25.10.21 — 300 000**; 05.11.21 — 400 000. Октябрь: 1–4 — 200 000; 5–24 — 250 000; 25–31 — 300 000.
- Регистр сведений «СведенияОСотрудниках»: периодичность «день» (период, сотрудник, оклад).

## Подготовка записей: разбивка по интервалам
Раньше оклад брали срезом последних на начало периода регистрации и один раз. Здесь — **запрос + цикл в обработке проведения**.

### Запрос (пакет) — получить все ставки, действующие в периоде каждой строки
1. `ВТ_ДанныеДокумента` ← ТЧ «ОсновныеНачисления»: `НомерСтроки`, `Сотрудник`, `ВидРасчета`, `ДатаНачала`, `ДатаОкончания`, + **период регистрации** (начало месяца даты документа); `Ссылка = &Ссылка`; индекс по сотруднику.
2. `ВТ_НачисленияСОкладом` — **левое соединение** с «СведенияОСотрудниках» (**не срезом**: нужна вся история) по сотруднику; поля: «Период», «Оклад» (`ЕСТЬNULL`); **условие `Период <= ДатаОкончания`** (отсекаем будущие изменения; **не по периоду регистрации**, а по дате окончания строки).
   - **Отбор по виду расчёта = «Оклад»** (для остальных видов разбивка не нужна): основная таблица — только оклад; остальные виды объединяются отдельно (`ОБЪЕДИНИТЬ ВСЕ`) с нулевым окладом/пустым периодом (ошибок «пропали виды» не будет).
3. **Срез последних «вручную» по временной таблице** (срез по обычной таблице, а не по регистру — «пригодятся знания, как делать срез по комплектующим»):
   - `ВТ_ДатаСреза` ← максимальный период (`МАКСИМУМ(Период)`) среди записей с **`Период <= ДатаНачала`** (по **номеру строки**, а не по сотруднику; «ошибка курсов 1С.рф» — группировка по сотруднику, поэтому одного сотрудника нельзя завести несколькими строками одного вида расчёта);
   - **внутреннее** соединение таблицы с окладами с `ВТ_ДатаСреза` (по номеру строки и по периоду = дате среза) — получаем **оклад, действующий на дату начала строки** (запись с «Период» подменяется на `ДатаНачала` — срез на дату начала, а не на дату установки оклада);
   - `ОБЪЕДИНИТЬ ВСЕ` с записями, где **`Период > ДатаНачала И Период <= ДатаОкончания`** — все изменения внутри интервала (строгое «больше»: за 1 октября уже действует ставка из среза; ставка за «дату окончания» включена, хотя последняя запись >31 числа отсеяна).
   - **Упорядочить по номеру строки и по периоду**; итоги — по «НомеруСтроки» (разбиваем каждую строку изолированно).
   - **Нельзя** использовать период регистрации вместо даты начала: интервалы одной строки/нескольких строк в документе могут начинаться 10-го или 20-го.

### Цикл «разбивки» (в `ОбработкаПроведения`)
Одна строка документа → несколько движений. Запись «исправляется» при следующей итерации (конец предыдущей = начало следующей − секунда):
```bsl
Выборка = Результат.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам);   // по НомеруСтроки
Пока Выборка.Следующий() Цикл
    ВыборкаДетали = Выборка.Выбрать();
    ДвижениеПред = Неопределено;
    Пока ВыборкаДетали.Следующий() Цикл
        Если ДвижениеПред <> Неопределено Тогда
            ДвижениеПред.ПериодДействияКонец = ВыборкаДетали.ПериодДействияНачало - 1;   // −1 секунда (время есть!)
        КонецЕсли;
        Движение = Движения.ОсновныеНачисления.Добавить();
        ЗаполнитьЗначенияСвойств(Движение, ВыборкаДетали);   // сотрудник, вид, оклад (реквизит «Оклад» 10/2), ПериодДействияНачало
        Движение.ПериодРегистрации    = НачалоМесяца(Дата);
        Движение.ПериодДействияКонец  = КонецДня(ВыборкаДетали.ДатаОкончания);   // последняя запись тянется до конца интервала
        ДвижениеПред = Движение;
    КонецЦикла;
КонецЦикла;
Движения.ОсновныеНачисления.Записать();
```
- «Дата начала» в запросе называется **«ПериодДействияНачало»**, «ДатаОкончания» — **«ПериодДействияКонец»** (чтобы `ЗаполнитьЗначенияСвойств` заполнил сразу).
- Для последнего сегмента: **`КонецДня(ДатаОкончания)`** (не `КонецМесяца`!). Для «исправления предыдущего»: `ПериодДействияНачало − 1` секунда (в составе даты есть время — на день уменьшать нельзя). Ошибка в видео: период действия конец стал 00:00:00, пока не добавили `КонецДня` и `−1 сек`.
- Реквизит **«Оклад»** (10/2) добавить в регистр расчёта — заполняется автоматически.
- Тест: Афанасьев — 3 записи (1–4: 200 тыс; 5–24: 250 тыс; 25–31: 300 тыс); при двух строках документа одного сотрудника — разбивка каждой по своему (номер строки, не сотрудник).

### Контроль: нет ставки
Если оклад не задан (Бердыев) — **ошибка**: отдельный запрос по `ВТ_НачисленияСОкладом` («`Оклад = 0`» → сотрудники без ставки): `Сообщить("Не указана ставка оклада у сотрудника " + Выборка.СотрудникПредставление); Отказ = Истина; Возврат;` (без повторяющихся). Проблема: внутреннее соединение с «Период <= ДатаОкончания» отсекает сотрудника без записей совсем — **условие по периоду надо ставить в условие соединения/после левого соединения** (иначе строка теряется): итоговое решение — отбор по периоду в условии соединения.
- Идея зрителя Юрия Зайцева: левое соединение с таблицей документа там, где максимальный период; воробей: «можно `>=` вместо среза» — **нельзя**: ставка может быть установлена задолго до начала периода — «срез нужен».

## Расчёт
`ДанныеГрафика(Регистратор = &Ссылка, ВидРасчета В (&ВидыРасчета))` (ссылка параметром — Иванча): `НомерСтроки`, **`ЕСТЬNULL(ЗначениеПериодДействия, 0)` → «НормоЧасов»**, **`ЕСТЬNULL(ЗначениеФактическийПериодДействия, 0)` → «ОтработаноЧасов»**; оклад берётся **из движения** (`Движение.Оклад`), не из запроса. Цикл: массив видов; `Выборка.Сбросить()`; `Если Движение.ВидРасчета = Оклад Тогда Если Выборка.НормоЧасов <> 0 Тогда Результат = Движение.Оклад / Выборка.НормоЧасов * Выборка.ОтработаноЧасов`; `ЗаполнитьЗначенияСвойств(Движение, Выборка, "НормоЧасов, ОтработаноЧасов")`; **`Записать(, Истина)`**. Реквизиты «НормоЧасов», «ОтработаноЧасов» (5/2).
- Нормо-часы по сегменту — **часы графика на период действия записи (а не месяца)**, поэтому сегменты суммируются в зарплату за месяц.
- Пример: 200 000 / 168 × 16 ≈ 19 047.
