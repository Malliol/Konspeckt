# Урок 43. Расчёт себестоимости по складам и партиям (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=KLuoOZz506Y · 50 мин · [полный текст](../transcripts/043_KLuoOZz506Y.md)

## О чём урок
Продолжение бухгалтерской задачи № 15 (купля-продажа): **расходная накладная** — проверка остатков на складе, списание себестоимости по ФИФО/ЛИФО (учётная политика), проводки. Отчёт по продажам — следующее занятие.

## Условие (часть 2)
- Продажа документом «Расходная накладная»; **склад** — реквизит в шапке.
- При проведении проверяется **достаточность количества** товара на складе.
- Проводки: **Дт «Прибыли и убытки» — Кт «Товары»** на **себестоимость** (в разрезе номенклатуры/склада/партии, количество — по кредиту «Товаров»); **Дт «Покупатели» — Кт «Прибыли и убытки»** на сумму продажи (сумма документа, одна проводка без детализации по номенклатуре).
- Себестоимость считается **в разрезе партий на складе**; списание — **ФИФО или ЛИФО** по **учётной политике** (определяется в начале года, в течение года не меняется).

## Исправление базы (выгрузка после занятия 41)
- В «Операции» копирование не переносило субконто: в `ПриКопировании` при копировании выборки нужно также `ЗаполнитьЗначенияСвойств(Движение.СубконтоДт, Выборка.СубконтоДт)` и `…СубконтоКт`.
- Добавлено поле **«Содержание»** в документ «Операция» (на практике «операций» бывает несколько на одну задачу — подписывают, что делает документ).
- В документы вытащить регистр бухгалтерии на форму; удалить старые данные и перепровести тестовые документы (регистр бухгалтерии и приходные накладные).

## Подготовка
- Реквизит «Склад» в расходной накладной (проверка заполнения, на форме).
- Учётная политика: регистр сведений **«УчётнаяПолитика»** — периодический (в пределах года), ресурс «МетодСписанияСебестоимости» (перечисление «УчётнаяПолитика»: ФИФО, ЛИФО; проверка заполнения «Выдавать ошибку»).
- Пример данных: приход 10 кинокамер по 10 000 (1 апреля) и 10 по 30 000 (5 апреля) на основной склад — партии; расход 15 шт. — 10 из первой партии (100 000) + 5 из второй (150 000) = 250 000.

## Виртуальные таблицы регистра бухгалтерии
- `Управленческий.Остатки(&МоментВремени, Счет = &Счет, , …)`: работает как таблица остатков регистра накопления, но **счёт указывается обязательно**; регистр бухгалтерии — «совокупность регистров накопления, по одному на счёт» с управляемыми измерениями (субконто). Таблицы «Остатки», «Обороты», «ОстаткиИОбороты»; «Движения с субконто» — физическая таблица (в ней есть активность).
- Параметры: **виды субконто как массив** (`ВидыСубконто` — список видов `ПланыВидовХарактеристик.ВидыСубконто.Номенклатура/Склады/Партии`) и условия по `Субконто1/2/3`. Порядок видов в массиве задаёт **«Субконто1, Субконто2, Субконто3»**; благодаря этому запрос защищён от пользователя, поменявшего порядок субконто в плане счетов (его менять никто не запрещает; запрещать на экзамене не нужно).
- **Не добавлять в массив лишние виды субконто** (иначе лишние левые соединения — запрос медленнее).

## Запрос расходной накладной (старая методика)
1. Временная таблица товаров документа (`ВТ_Товары`: номенклатура, сумма количества) с индексом по номенклатуре.
2. Запрос: `ВТ_Товары` **ЛЕВОЕ СОЕДИНЕНИЕ** `Управленческий.Остатки(&МоментВремени, Счет = &СчетТовары, &ВидыСубконто, Субконто2 = &Склад)` по `Субконто1 = Номенклатура` (отбор по складу — в параметрах, для использования индекса). Поля: номенклатура (представление для сообщения), количество продажи, **партия = Субконто3**, количество остатка, сумма остатка.
3. **Итоги** по номенклатуре (количество — максимум, остатки — сумма).
4. **Порядок** — по моменту времени партии: `ВЫРАЗИТЬ(Остатки.Субконто3 КАК Документ.ПриходнаяНакладная).МоментВремени`. Причина `ВЫРАЗИТЬ`: субконто — **составной тип**; обращение через точку к составному типу порождает **неявные левые соединения по всем возможным типам** (медленно); явное приведение к одному типу — только одно соединение. Выражать нужно только там, где обращаются через точку; в выборке для отчёта субконто также выражают (иначе система при выводе тянет представления через кучу соединений).
5. Вынесение условия по складу в параметры виртуальной таблицы — как у регистра накопления; `Субконто2` лучше не использовать напрямую (порядок могут поменять) — для блокировки и запроса использовать вид субконто.

## Алгоритм (ФИФО/ЛИФО)
1. **Учётная политика:** `РегистрыСведений.УчётнаяПолитика.ПолучитьПоследнее(Дата).МетодСписанияСебестоимости` — метод **всегда возвращает структуру** с полем (при отсутствии записи — пустое значение: пустая ссылка). Если пусто → сообщение «Не указана учётная политика», **`Отказ = Истина`** и **`Возврат`** (отказ обязателен — иначе документ запишется; возврат нужен, чтобы дальше не выполнять код).
2. Для ЛИФО меняется **порядок упорядочивания в тексте запроса**. Способы: заменить `УБЫВ` (в консоли запросов оно часто пропадает) на пустую строку (предложено зрителем иванча — «изящнее и устойчивее»: `УБЫВ` консоль не убирает, а «ВОЗР»/пустое по умолчанию подразумевается) — выбран этот вариант: в запросе по умолчанию `УПОРЯДОЧИТЬ ПО … УБЫВ`, а для ФИФО `УБЫВ` заменяется на пустую строку (или `ВОЗР`).
3. Блокировка: `Блокировка = Новый БлокировкаДанных; Элемент = Блокировка.Добавить("РегистрБухгалтерии.Управленческий")`, режим исключительный; блокируются **счёт «Товары»**, вид субконто «Склады» = склад из шапки, вид субконто «Номенклатура» — из списка номенклатуры документа (`ИсточникДанных = Товары`, поле «Номенклатура»). Блокируют по **виду субконто**, а не по номеру («Субконто2»): пользователь может поменять порядок.
4. Цикл по номенклатуре и партиям: `КоличествоСписать = Выборка.Количество`; пока `КоличествоСписать > 0` — `Количество = Мин(КоличествоСписать, КоличествоОстаток)`; если количество = остатку → себестоимость = `СуммаОстаток`; иначе **себестоимость = СуммаОстаток / КоличествоОстаток × Количество** (себестоимость единицы умножить на количество; при расчёте не дублировать умножение — ошибка, найденная зрителем). Округлять отдельно не нужно: у ресурса «Сумма» 2 знака.
5. Проводка списания: `СчетДт = Прибыли и убытки`, `СчетКт = Товары`; **субконто Кт**: номенклатура, склад (из шапки), партия (из выборки); **КоличествоКт = Количество**, `Сумма = Себестоимость`.
6. Контроль остатков: если количество продажи > количества остатка → сообщение «Недостаточно товара %1 в количестве %2» (представление номенклатуры, нехватка), `Отказ = Истина`; цикл прекращается (`Если Отказ Тогда Продолжить`).
7. Проводка выручки: `СчетДт = Покупатели`, `СчетКт = Прибыли и убытки`, `Сумма = СуммаПоДокументу`.

## Проверка
15 шт. по ФИФО: 100 000 (10 из 1-й партии) + 150 000 (5 из 2-й); по ЛИФО — наоборот. Метод учётной политики меняет порядок списания.

## Замечания зрителей
- Ширина строки кода по стандарту — ≤120 символов (автор принял).
- Отказ без возврата при пустой учётной политике запишет документ — отказ обязателен.
- «Характеристики к товарам» — в следующем видео (относится к отчёту); следующее занятие в 16:00 (отчёт по продажам).
