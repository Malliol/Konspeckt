# Урок 38. Отчёт по остаткам стеллажей. Подготовка к специалисту по платформе 1С
(в заголовке видео: «Отчёт по остаткам стеллажей / наличие деталей»)

Видео: https://www.youtube.com/watch?v=OIVlmkohkXs · 46 мин · [полный текст](../transcripts/038_OIVlmkohkXs.md)

## О чём урок
Новая версия билета № 6 (по нумерации автора): отчёт «НаличиеДеталей» — сколько **стеллажей** можно собрать из комплектующих, лежащих на складах, с выводом склада, стеллажа, **страны** (характеристика) и количества. Автор называет его самым сложным отчётом курса (в прежней версии билета характеристик не было). Основа — конфигурация после занятия 17.

## Исходные данные
- Регистр сведений «СоставСтеллажей» (стеллаж, комплектующая, количество); **комплектующая — единственное измерение** (комплектующая входит только в один стеллаж); остатки ведутся только по комплектующим — стеллажей на остатках нет.
- Исправление ошибки старого решения (вопрос зрителя Юрия Черномора): у ресурса «Количество» регистра состава должна стоять **проверка заполнения «Выдавать ошибку»** (нулевого количества быть не может → деления на ноль в запросе нет и дополнительная защита не нужна; для интерактивно заполняемых регистров проверку заполнения нужно ставить).

## Характеристики (ПВХ)
- План видов характеристик **«ХарактеристикиОбъектов»** (бывш. «СвойстваОбъектов»); доп. значения — справочник **«ЗначенияХарактеристик»** (владелец — ПВХ; в составном типе ПВХ добавлен как тип значения; длина наименования увеличена). Подробности про ПВХ — урок 21.
- Регистр сведений **«ЗначенияХарактеристикСтеллажей»**: измерение «Стеллаж» (тип «Номенклатура», ведущее, запрет незаполненных, «Выдавать ошибку», параметр выбора — вид номенклатуры «Стеллаж»), измерение «Характеристика» (ПВХ), ресурс «Значение» (тип из ПВХ; **связь параметров выбора** по типу значения характеристики, владелец — характеристика).
- Предопределённый элемент ПВХ **«Страна»**: в отчёте страна фиксирована.
- Проблема: автоматические команды связанных объектов в форме номенклатуры позволяют создать комплектующую «со стеллажом» и наоборот → выключить их в командном интерфейсе формы номенклатуры. Данные: стеллаж 1 — Россия, 2 — США, 3 — без значения.

## Идея запроса (пакет)
1. `ВТ_ОстаткиДеталей`: `ОстаткиНоменклатуры.Остатки(&Период,)` — номенклатура (деталь), склад, количество остатка. Индекс: деталь + склад.
2. **Левое соединение** `СоставСтеллажей` (левая — полная таблица комплектующих по стеллажам) с остатками деталей: нет остатка → NULL.
3. Для каждой пары «стеллаж + склад» считаем по каждой детали «на сколько стеллажей хватает» = `ЕСТЬNULL(КоличествоОстаток, 0) / Количество` (NULL → 0, иначе минимум по группе потеряет нулевые).
4. **Количество собираемых стеллажей = МИНИМУМ по деталям** стеллажа (в группировке по стеллажу): единственная нехватка детали обнуляет весь стеллаж. Нулевые записи убирают в секции `ИМЕЮЩИЕ МИНИМУМ(...) > 0` (отбор после группировки; `ГДЕ` — до неё).
5. **Склад.** Если добавить склад только из остатков, детали, отсутствующие на складе, дадут пустой склад (из-за левого соединения), и результат будет неверным. Приём: **перемножить** «СоставСтеллажей» со справочником «Склады» (соединение без условия — «каждый с каждым»; индексы бессмысленны), получить временную таблицу «СоставСтеллажейСоСкладами» и использовать её вместо регистра: тогда склад везде заполнен. Соединяют по комплектующей и складу.
6. **Округление вниз:** `ВЫРАЗИТЬ(Частное - 0,5 КАК ЧИСЛО(10, 0))` — сначала вычесть 0,5, затем округлить (2,5 → 2, 2,99 → 2, 3,1 → 3). Вычитание единицы после обычного округления неверно. Функции `ЦЕЛ` в запросе нет.
7. **Страна:** левое соединение временной таблицы данных с регистром значений характеристик: `Стеллаж = Стеллаж И Характеристика = ЗНАЧЕНИЕ(ПланВидовХарактеристик.ХарактеристикиОбъектов.Страна)`; выбирается значение характеристики.

## СКД
- Отчёт «НаличиеДеталей» (в билете такое имя; автор предпочёл бы «Учёт по стеллажам»), подсистема «Оперативный учёт»; набор «запрос»; параметр «Период» (по умолчанию «Начало завтрашнего дня», в пользовательских настройках, с запретом незаполненных значений).
- Структура: группировка «Склад» → детальные записи; итогов нет — ресурсы не нужны. Параметры вывода — не выводить; расположение группировок — «Отдельно и только в итогах» (склад и стеллаж в отдельных колонках).
- «Выбранные поля»: **группа «Стеллаж, Страна»** (стеллаж + страна в одной ячейке), заголовок «Стеллаж, страна»; заголовки колонок; жирные заголовки; количество — по левому краю (условное оформление).
- **Сортировка:** по складу, стеллажу, стране. Основной склад должен быть выше дополнительного (в образце билета). Сортировка по убыванию — «полный бред». Варианты: склад — предопределённый элемент и вычисляемое поле «порядок» (выбор: предопределённый → 0, иначе 1); либо реквизит справочника «Порядок» и вычисляемое поле («ЕСЛИ порядок = 0 ТО 9999 ИНАЧЕ порядок»); либо сортировка по коду. Вычисляемое поле ограничено «только для упорядочивания»; добавить его **в сортировку и в «Авто»** группировки «Склад» (иначе автосортировка по складу его перебьёт). Лишние отступы у дополнительного склада в образце — «скорее всего просто криво напечатали».
- Предложения зрителей: регистр накопления «гипотетических стеллажей» — не нужен (запрос в отчёте проще и не боится); реквизит «порядок».

## Индексы
- Временные таблицы: остатки деталей — индекс по «Номенклатура, Склад»; состав со складами — по «Комплектующая, Склад» (соединение); таблица данных отчёта — по «Стеллаж» (соединение с регистром значений). Для «каждый с каждым» индекс не нужен. У регистра сведений измерение «Стеллаж» ведущее — индекс есть автоматически.
