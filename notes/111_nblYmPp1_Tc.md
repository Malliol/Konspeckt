# Урок 111. Премия в билете «Табель» (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=nblYmPp1_Tc · ~20 мин · [полный текст](../transcripts/111_nblYmPp1_Tc.md)

## О чём урок
Билет № 11 (табель + невыход), последнее условие: **премия в процентах от начисленного оплаты по часовому тарифу за тот же расчётный период; процент задаётся в документе «НачислениеЗарплаты»**. «Никаких нюансов, всё как раньше».

## Конфигурация
- Вид расчёта **«Премия»** — «ДополнительныеНачисления» (нет периода действия); **зависимость от базы — по периоду действия, базовый вид — «ОплатаПоЧасовомуТарифу»** (оплата **входит в базу** — без этого база нулевая: **главная ошибка урока**); регистр расчёта «ДополнительныеНачисления»: измерения «Сотрудник», «Подразделение», флажок «Базовый период»; **«Базовый» у измерений** — в обоих регистрах (в основных и допначислениях).
- Регистр «ДополнительныеНачисления»: убрать график работы, тарифную ставку, отработанные часы, дни невыхода — **оставить «БазаНачислений» (10/2) и параметр «Процент» (10/2)**; **«ГрафикРаботы» в основных начислениях оставлен «на вырост»** (фиксация возможности нескольких графиков; на расчёт не влияет — в билете график не используется).
- Документ: табличная часть «ДополнительныеНачисления» (сотрудник, подразделение, вид расчёта, параметр — процент); **без дат и графика** (базовый период — тот же расчётный месяц); «Выдавать ошибку» с обеих ТЧ **снять**; в `ОбработкаПроверкиЗаполнения` — **если обе таблицы пусты → «Документ не заполнен»**, `Отказ = Истина` (+ `Возврат`).
- «Период действия» у оклада/невыхода (план «ОсновныеНачисления»): **не обязательно диктуется потребностью в «ДанныхГрафика»**; «виды времени по сути протяжённые по времени → логично в основных начислениях».

## Подготовка записей
```bsl
КонецПериодаРегистрации = КонецМесяца(ПериодРегистрации);   // посчитать один раз
Для Каждого Строка Из ДополнительныеНачисления Цикл
    Движение = Движения.ДополнительныеНачисления.Добавить();
    ЗаполнитьЗначенияСвойств(Движение, Строка);
    Движение.ПериодРегистрации = ПериодРегистрации;
    Если Строка.ВидРасчета = Премия Тогда
        Движение.БазовыйПериодНачало = ПериодРегистрации;
        Движение.БазовыйПериодКонец  = КонецПериодаРегистрации;      // тот же расчётный месяц
    КонецЕсли;
КонецЦикла;
Движения.ДополнительныеНачисления.Записать();
```

## Расчёт
- Запрос — **только база** (без соединений: «в параметрах расчёта только база» — метод Белоусова): `ДополнительныеНачисления.База(&Измерения, , , Регистратор = &Ссылка И ВидРасчета В (&ВидыРасчета))`: `НомерСтроки`, `РезультатБаза` → «БазаНачислений»; **`ЕСТЬNULL` не нужен** («никому ещё не удавалось получить NULL при получении базы»).
- Цикл: `Если ВидыРасчета.Найти(Движение.ВидРасчета) = Неопределено Тогда Продолжить`; `Выборка.Сбросить()`; **`Если Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки") Тогда`** (базы может не быть — соединения нет); `Если Движение.ВидРасчета = Премия Тогда Движение.Результат = Выборка.БазаНачислений * Движение.Параметр / 100; ЗаполнитьЗначенияСвойств(Движение, Выборка, "БазаНачислений")`; `Записать()`.
- **Ошибка на съёмке:** базу не нашёл (0): в запросе поле называется **`РезультатБаза`** (ресурс + «База»), а автор по ошибке использовал **реквизит «БазаНачислений» регистра** (который нулевой) — «я уже попадал в такую фишку»; проверять поле выборки.
- Тест с двумя сотрудниками (Бердыев + Жупиков) — «обычно становится очевидной ошибка соединений».
