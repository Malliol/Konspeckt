# Урок 23. Отчёт по недоотгруженным заказам. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=dOx1kJRh-lo · 32 мин · [полный текст](../transcripts/023_dOx1kJRh-lo.md)

## О чём урок
Ввод на основании и отчёт «Анализ недоотгруженных заказов покупателей» (билет № 12): объединение запросов, **левое соединение с отбором по правой таблице превращается во внутреннее**, оформление заголовка с параметром и представление номера заказа. Основа — решение урока 22.

## Ввод на основании (расходная накладная на основании заказа клиента)
Ходят слухи, что на экзамене формулировку «отгрузка только на основании заказа» трактуют как требование. Делается быстро:
1. В расходной накладной закладка «Ввод на основании»: указать, что документ вводится на основании «ЗаказКлиента»; открывается конструктор ввода на основании.
2. Конструктор заполняет номенклатуру, количество и ссылку на заказ (цены и суммы нет — в заказе их не было).
3. В сгенерированном коде `ОбработкаЗаполнения` следует **убрать лишнее обращение «ДанныеЗаполнения.Ссылка»** (данные заполнения уже ссылка; получение ссылки по ссылке — лишнее, за такое могут снизить балл).
Теперь расходные накладные создаются на основании заказов.

## Данные для отчёта
Отчёт «Анализ недоотгруженных заказов покупателей» (в образце колонки: характеристика, заказ, оборудование, **не закуплено**, **не отгружено**).
- **Не закуплено** = остатки регистра «ТоварыКЗакупке» (заказано, но не куплено).
- **Не отгружено** = остатки регистра «ОстаткиНоменклатуры» (куплено, но не отгружено; в разрезе заказа).
- Два показателя из разных регистров выводят в разных колонках через **объединение** запросов (быстрее, чем соединение): первый запрос выдаёт «не закуплено» и 0 в колонке «не отгружено»; второй — 0 и количество остатка. Поля переименовывают понятно («НеЗакуплено», «НеОтгружено»; стоимость не нужна).
- Чтобы записи по одной номенклатуре и заказу «схлопнулись» в одну строку, объединение оборачивают **вложенным запросом** «ДанныеОтчета» со сложением (группировка по заказу и номенклатуре). Вложенные запросы удобнее писать вручную.
- Соединять с вложенным запросом не рекомендуется (Е. Хрусталёва), поэтому результат кладут во **временную таблицу `ВТ_ДанныеОтчета`**, а затем левым соединением присоединяют регистр значений характеристик заказов по заказу клиента.

### Характеристика и отбор по ней
Отчёт строится в разрезе значения **выбранной** характеристики: пользователь задаёт характеристику (например, «Регион»). Отбор по характеристике надо записать так, чтобы не потерять заказы без значения.

**Ловушка:** если при левом соединении в условии отбора (ГДЕ) используются поля **правой таблицы** (`Характеристика = &Характеристика`), то левое соединение **превращается во внутреннее** — заказ без значения характеристики исчезает из отчёта.

Решения:
1. (Не очень правильное) ещё одно объединение, чтобы добавить заказы без значения.
2. **Правильное:** вынести отбор по характеристике в **условие соединения**: `ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ЗначенияХарактеристикЗаказов КАК Значения ПО ДанныеОтчета.ЗаказКлиента = Значения.ЗаказКлиента И Значения.Характеристика = &Характеристика`. Соединение остаётся левым, заказ без характеристики выводится с **пустым значением**. Автор впервые в курсе пишет отбор в условии соединения.
Что делать с заказами без характеристики — не ясно из билета: если неясно, решение фиксируют в пояснительной записке (при удалённом экзамене); если такие заказы не нужны, делают внутреннее соединение. Автор выводит их (пользователь сразу видит, что забыл ввести значение).

## Настройка отчёта на СКД
- Ресурсы не нужны (итогов нет).
- Параметры: «Период» (стандартный; здесь — начало завтрашнего дня для «остатков на дату», использование всегда, запрет пустого), «Характеристика» (использование всегда; без неё отчёт не имеет смысла; включается в пользовательские настройки). Вывод параметров — «Не выводить».
- Структура: группировка «Значение характеристики» → группировка «Заказ клиента» → детальные записи (номенклатура, не закуплено, не отгружено); расположение полей группировок — «Отдельно и только в итогах».
- Сортировка: значение характеристики, заказ клиента, номенклатура (пустое значение выводится первым).
- Условное оформление: влево, отступ 1 символ.
- Ошибка образца в билете: «Москва и заказ в одной строке, Новгород — в двух» — опечатка составителя; делают одинаково для всех.

### Номер заказа в представлении
- Для поля «ЗаказКлиента» в выражении представления: `"Заказ № " + НумерацияОбъектов.НомерНаПечать(ЗаказКлиента.Номер) + " от " + Формат(ЗаказКлиента.Дата, "ДФ=dd.MM.yyyy")`.
- **Функция `НомерНаПечать` общего модуля «НумерацияОбъектов»:** `Функция НомерНаПечать(Знач НомерОбъекта) Экспорт; Пока Лев(НомерОбъекта, 1) = "0" Цикл НомерОбъекта = Сред(НомерОбъекта, 2); КонецЦикла; Возврат НомерОбъекта; КонецФункции`. Параметр передаётся **по значению (`Знач`)**; третий параметр `Сред` можно не указывать. В типовых аналогичная функция называется «УдалитьВедущиеНули».

### Заголовок и макеты
Заголовок значения характеристики вычисляется, поэтому штатным «установить заголовок» не обойтись — рисуют макет заголовка группировки «Значение характеристики» (ячейки: «[Характеристика]», «Заказ», «Оборудование», «Не закуплено», «Не отгружено»; жирный, по центру, перенос; шаблон с параметрами «Период» и «Характеристика»; формат даты). Для области макета выбирают тип «Макет заголовка группировки». Границы берутся из макета оформления. Ячейки заголовка можно объединить. Для текста «Характеристика» в параметре используется сам параметр (поле «характеристика» из запроса прячут).

## Прочее
- Настройка характеристик в самом справочнике/документе (чтобы отчёт позволял выбирать характеристики и из «Изменить вариант») для этого отчёта не нужна. Популярный способ «настроить в пользовательском режиме, выгрузить схему и подключить в конфигураторе» автор считает бессмысленной пляской.
- Следующие занятия: билеты (по нумерации автора — № 13), затем оплаты и взаиморасчёты.
