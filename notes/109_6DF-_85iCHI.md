# Урок 109. Расчёт оклада и командировки по табелю (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=6DF-_85iCHI · ~1 ч 5 мин · [полный текст](../transcripts/109_6DF-_85iCHI.md)

## О чём урок
Билет «Табель» (продолжение урока 108): **расчёт оклада и командировки по данным табеля**. Главный вопрос — **в какой план видов расчёта поместить оклад и командировку и нужен ли период действия**.

## Условие
- **Оклад:** оплата пропорционально отработанному времени в часах; **часовая ставка = оклад / количество рабочих часов в том же периоде**; значение оклада — из регистра сведений; **отработанные часы берутся из табеля**.
- **Командировка:** часы командировки (из табеля, вид времени «Командировка»); **часовая ставка = сумма всех начислений за два предыдущих месяца / рабочие часы за эти месяцы**; командировка **не вводится задним числом** (значит, сторно не нужно; база за прошлые периоды, в текущем документе оклад в базу не входит).

## Спорный вопрос: план видов расчёта
Автор разобрал 4 варианта (на форуме нет единого ответа; «в глазах экзаменатора есть несколько правильных решений»):
1. **Решение Прохорова:** оклад — «ОсновныеНачисления» **с периодом действия** (для «ДанныеГрафика»: рабочие часы), командировка — **«ДополнительныеНачисления» без периода действия** (нормо-часы — через базу по ресурсу «НормаДней/Часов», сторно/дробление — проблемы, как в билете про обеды).
2. **Оклад и командировка — без периода действия** (допначисления), нормо-часы и ставка — прямо из регистра сведений: экзаменатор может не оценить; **−2 балла за «ручные» данные графика**.
3. **Период действия включён, но поля дат прятать/заполнять заглушками** (начало и конец месяца) — «зачем тогда период действия».
4. **Рекомендуемое (подсказал зритель Лосяш / Белоусов): оклад и командировка — в «ОсновныхНачислениях» с периодом действия; дата начала и окончания в документе вводятся пользователем и задают интервал, **за который подтягиваются отработанные часы из табеля** (всё в месяце — весь месяц; интервал «с 1 по 15» — для аванса/первой половины).** Мотив: оклад и командировка — «протяжённые во времени»; табель задаёт «факт», интервал — «период расчёта». Автор: «мне показалось наиболее логичным; это то, что реализуем».
- Вытеснение командировки/оклада настраивать **не нужно** (в табеле ячейка — либо число, либо «К»; одновременно оба быть не могут).

## Подготовка
Обычная: `ПериодРегистрации = НачалоМесяца(Дата)`; цикл: `ЗаполнитьЗначенияСвойств`, `ПериодДействияНачало = ДатаНачала`, `ПериодДействияКонец = КонецДня(ДатаОкончания)`; **базовый период — только для командировки:** `БазовыйПериодНачало = ДобавитьМесяц(ПериодРегистрации, -2)`, `БазовыйПериодКонец = ПериодРегистрации − 1`; `Записывать = Истина`; запись.
- В плане «ОсновныеНачисления»: **зависимость от базы — по периоду действия, базовый вид — «Оклад»** (для командировки; **«все начисления» — отмечать все, а не только оклад**: «сумма всех начислений»), «Базовый период» вкл.; флажки «Базовый» у измерений в обоих регистрах.

## Запрос расчёта
1. **`ВТ_ДанныеГрафика`** ← `ДанныеГрафика(Регистратор = &Ссылка, ВидРасчета В (&ВидыРасчета))`: `НомерСтроки`, `Сотрудник`, `Подразделение`, **`ЕСТЬNULL(ЗначениеПериодДействия, 0)` → «НормоЧасов»** (часы), **`ЕСТЬNULL(ЗначениеБазовыйПериод, 0)` → «БазаРабочихЧасов»**, `ПериодДействияНачало`, `ПериодДействияКонец`; индекс по сотруднику, подразделению.
2. **Оклад:** левое соединение со срезом последних «СведенияОСотрудниках» на `&ПериодРегистрации` по сотруднику и подразделению; `ЕСТЬNULL(Оклад, 0)`.
3. **Часы явки из табеля:** **обороты использовать нельзя** (у каждой строки свой интервал дат) → **детальная таблица `РегистрНакопления.ДанныеТабеля`**: соединение по **сотруднику, подразделению**, **`Период >= ДатаНачала И Период <= ДатаОкончания`**; **`ВидВремени = Явка`** (для вида «Оклад») и **`ВидВремени = Командировка`** (для командировки) — отдельными таблицами «ДанныеЯвки» и «ДанныеКомандировки» (группировка по номеру строки, `СУММА(Часов)`) с **левым соединением** (внутреннее — ошибка: терялись строки), активность — `ИСТИНА`. В итоге: **`ВЫБОР КОГДА ВидРасчета = Оклад ТОГДА ДанныеЯвки.Часов КОГДА ВидРасчета = Командировка ТОГДА ДанныеКомандировки.Часов КОНЕЦ` → «ОтработаноЧасов»** (в одном поле — по виду расчёта).
4. **База командировки:** `База(&Измерения, , , Регистратор = &Ссылка И ВидРасчета В (&ВидыРасчета))`: `РезультатБаза` → «БазаНачислений»; левое соединение по номеру строки.
5. Параметры: **массивы** — «ВидыРасчета» (для всех видов, по которым получаем данные), «ВидыРасчетаЯвки» (оклад — присоединяем часы явки), «ВидыРасчетаКомандировки» (командировка — присоединяем часы командировки), «ВидыРасчетаБаза» (для базы) — «на вырост» (появятся больничные и пр.); **два измерения «Сотрудник», «Подразделение»**.
   - Ошибки/нюансы: «поле “период” таблицы данных графика» — условие попадания даты табеля в период действия записи; «всегда сначала пробовать на двух сотрудниках» (Бердыев/Жупиков), «на одном всё нормально, на двух — вылезают недостающие соединения».

## Цикл
```bsl
Если ВидыРасчета.Найти(Движение.ВидРасчета) = Неопределено Тогда Продолжить;
Выборка.Сбросить(); Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки");
Если Движение.ВидРасчета = Оклад Тогда
    Движение.Результат = ?(Выборка.НормоЧасов <> 0, Выборка.Оклад / Выборка.НормоЧасов * Выборка.ОтработаноЧасов, 0);
    ЗаполнитьЗначенияСвойств(Движение, Выборка, "Оклад, НормоЧасов, ОтработаноЧасов");
ИначеЕсли Движение.ВидРасчета = Командировка Тогда
    Движение.Результат = ?(Выборка.БазаРабочихЧасов <> 0, Выборка.ОтработаноЧасов * Выборка.БазаНачислений / Выборка.БазаРабочихЧасов, 0);   // часовая ставка × часы
    ЗаполнитьЗначенияСвойств(Движение, Выборка, "ОтработаноЧасов, БазаНачислений, БазаРабочихЧасов");
КонецЕсли;
Движения.ОсновныеНачисления.Записать(, Истина);
```
- Реквизиты регистра: «Оклад», «НормоЧасов», «ОтработаноЧасов», «БазаНачислений», «БазаРабочихЧасов» (10/2, 5/2); выборка и цикл — **один запрос и один цикл**: сторно нет, оклад в текущем документе в базу командировки не попадает.
- Тест: сентябрь (оклад 100 000; 176 нормо-часов), октябрь: командировка 24 часа → база по двум месяцам; ставка небольшая — «человек, устроившийся в сентябре, имеет базу 0 — у меня всегда два месяца».
- **Табель можно хранить и в регистре сведений** (работает так же, но «регистр накопления — на вырост, для отчётов»).
