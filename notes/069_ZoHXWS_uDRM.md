# Урок 69. Расчёт по кнопке «Рассчитать» (СПР). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=ZoHXWS_uDRM · 33 мин · [полный текст](../transcripts/069_ZoHXWS_uDRM.md)

## О чём урок
Билет № 1 (продолжение): **кнопка «Рассчитать» в форме документа «НачислениеЗарплаты»** — результат расчёта отображается в табличных частях формы, пользователь может его править, а при проведении записи переносятся в регистры (как в типовых «Зарплата и управление персоналом»). База — урок 68.

## Условие
**В форме документа начисления зарплаты должна быть кнопка «Рассчитать»**, при нажатии которой выполняется **предварительный расчёт зарплаты**; **результат расчёта отражается в табличной части** той же формы. (Затем пользователь при необходимости корректирует результат вручную и проводит документ — в движения попадают значения из формы.) Автор: при этом вместе с результатом в таблице выводятся **показатели расчёта** (оклад, рабочие дни, отработанные дни, база, процент, стаж) — «Белоусов так же делает».

## Изменения конфигурации
- В табличных частях «ОсновныеНачисления» и «ДополнительныеНачисления» документа добавить колонки **«Результат»** (точность 10/2 — как в регистре) и показатели расчёта: «Оклад», «РабочихДней», «ОтработанныхДней» (основные); «БазаНачислений», «ПроцентПремии», «Стаж» (дополнительные); на форме — на соответствующих закладках (можно «скрыть/показать показатели» кнопкой, но не обязательно).
- Создать команду формы «**Рассчитать**» (в командную панель формы документа; обработчик на клиенте и на сервере).

## Рефакторинг модуля объекта
Логика проведения разбита на **два экспортных метода объекта** (метки «Этап 1/Этап 2» из урока 67):
1. **`ЗаписатьДанныеВРегистры(ПараметрыРасчета)`** (экспортная) — подготовка записей (основные + дополнительные) в регистры;
2. **`РассчитатьНачисления(ПараметрыРасчета)`** (экспортная) — расчёт (запросы, цикл по движениям); в проведении вызываются **оба** (временно, для проверки).
- **`ПараметрыРасчета`** — **структура** (чтобы не вычислять «период регистрации» в каждой процедуре): `ПараметрыРасчета = Новый Структура("ПериодРегистрации", НачалоМесяца(Дата))` — нужна для обеих процедур; **нужна расширяемость** (в любой момент добавить параметры); «по-человечески» было бы просто `НачалоМесяца(Дата)` в процедурах, но «Белоусов не делает» (метод `Свойство` для проверки поля структуры не нужен).
- Методы **обязательно экспортные**, иначе из формы не доступны (ошибка: «метод объекта не обнаружен»).

## Вызов из формы
- В форме реквизит **«Объект» — не настоящий объект, а `ДанныеФормыСтруктура`** (внешне похож на `ДокументОбъект`, но методов у него нет). Настоящий объект получают **`РеквизитФормыВЗначение("Объект")`** — **только на сервере** (на клиенте объектов нет): `ДокОбъект = РеквизитФормыВЗначение("Объект")` (дополнительные свойства и методы доступны).
- Обработчик команды (на сервере): `Если Объект.Ссылка.Пустая() Тогда Сообщить("Документ должен быть записан"); Возврат; КонецЕсли;` (расчёт использует регистратор в запросах — **нужна ссылка**; запись самостоятельно не делаем: «не просят»; `ПоказатьВопрос` не нужен); затем `ДокОбъект.ЗаписатьДанныеВРегистры(Параметры); ДокОбъект.РассчитатьНачисления(Параметры); ЗначениеВРеквизитФормы(ДокОбъект, "Объект")` — **обратно** (иначе результат в форме не виден: форма хранит данные независимо от настоящего объекта).
- Конструкция: `ПараметрыРасчета` в форме создают заново (период регистрации — `НачалоМесяца(Объект.Дата)`).

## Заполнение табличных частей в расчёте
- В `РассчитатьНачисления` после расчёта результата строки движения (основные):
  `СтрокаТаблицы = ОсновныеНачисления[Движение.НомерСтроки - 1]` (**номера строк в движениях с 1, в табличной части — индексы с 0 → «минус 1»**); `СтрокаТаблицы.Результат = Движение.Результат; ЗаполнитьЗначенияСвойств(СтрокаТаблицы, Выборка)` (оклад, рабочие, отработанные — одноимённые поля); аналогично для дополнительных: база, процент, стаж.
- **Движения после расчёта очищаются**: чтобы «Рассчитать» не оставляло движений в непроведённом документе: **дополнительные начисления — сразу после получения базы** (запрос выполнен — записи больше не нужны: `Движения.ДополнительныеНачисления.Очистить(); …Записать()`); **основные — после расчёта премии** (премия берёт из основных записей базу — **нельзя очищать раньше**, иначе База не получится; тут симметрично нельзя). Итого: после «Рассчитать» в регистрах нет записей, в форме есть результат.
- **Проведение** упрощается до `ЗаписатьДанныеВРегистры(…)` — **переносит из табличных частей в регистры** значения (в том числе результат и показатели, `ЗаполнитьЗначенияСвойств`), без расчёта. Если пользователь не нажал «Рассчитать» — запишется ноль («пользователь захотел нулевую зарплату — его право»).
- Ручное исправление результата в форме (Бердыеву 150 000, Васиной 300 000) — при проведении сохраняется; повторное «Рассчитать» затирает правки (флажок «ручной расчёт» — за рамками экзамена; «кнопка очистить расчёт» — «никто не просил — не делаем»).

## Замечания
- **Транзакции** здесь не нужны (зрители предлагали «начать/отменить транзакцию» для непроведённого документа); Белоусов «категорически против использования транзакций в документах».
- Автор: на экзамене «очень много нужно сделать, не тратьте время на то, о чём не просят».
- В отладке: `Объект` в форме — `ДанныеФормыСтруктура` (показывает «тип ДокументОбъект» в скобках — обман).
- Следующее занятие — отчёт «Премии сотрудников» (урок 70).
