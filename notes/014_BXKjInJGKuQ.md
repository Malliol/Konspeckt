# Урок 14. Списание по приоритетам складов. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=BXKjInJGKuQ · 69 мин · [полный текст](../transcripts/014_BXKjInJGKuQ.md)

## О чём урок
Билет № 4: оптовая торговля, учёт товаров по складам; у каждого склада свой **приоритет**, который может меняться не чаще раза в месяц. Остатки контролируются **по всей компании**, списание идёт по складам в порядке приоритета (сначала склад из шапки документа). Затем отчёт «Движение товаров» с особым требованием к точности числа.

## Работа над ошибками (урок 13)
1. В отчёте на год выводились 4 знака, нужны 2: поправить формат.
2. **Сортировка обязательна:** смотреть образец в билете и настраивать упорядочивание. Упорядочивание делается средствами СКД (в настройках отчёта), **не в запросе**. Для ведомости по партиям: сначала номенклатура, затем партия.
3. Ресурсы в «Движении товаров» нужны: в отчёте есть итоги по группировке «Номенклатура» (не только общий итог внизу). Автор оговорился в прошлом уроке.
4. Функция `НомерНаПечать` в общем модуле «НумерацияОбъектов»: не менять переданный параметр и одновременно возвращать его. Параметры называют понятно (например, «ИсходнаяСтрока»). Чтобы не изменять исходный параметр, перед параметром ставят слово **`Знач`** (передача по значению), тогда функцию можно менять локально.

## Условие билета
- Приходная и расходная накладные, товары и услуги. Услуги: тип реквизита «ВидНоменклатуры», в приходной накладной выбор только товаров (параметры выбора).
- Каждый склад имеет приоритет, который меняется не чаще раза в месяц → **регистр сведений «ПриоритетыСкладов»**: периодичность «в пределах месяца», независимый режим записи, измерение «Склад», ресурс «Приоритет» (число, 2 знака, **точность 0, неотрицательное**). Чем **меньше** число, тем выше приоритет. Склад из шапки документа получает приоритет **−1** (выше максимального), нет записи — **100** (ниже любого).
- При проведении расходной накладной **остатки контролируются по всей компании** (не по складу из шапки). Склад в шапке указывается, потому что с него списывают в первую очередь.
- Себестоимость списывается по складам в порядке приоритета и рассчитывается **как среднее по складу** (себестоимость склада ÷ количество склада).
- Фактически это ФИФО, только очередь определяется приоритетом склада, а не моментом времени партии.
- Ресурс «Стоимость» в регистре остатков для этого билета назван «Себестоимость».

Выгрузка для старта: база после урока 2 (там заготовки регистров). Регистр приоритетов выводят в командный интерфейс (группа команд «Регистры сведений»). Склады справочник — в «Справочники».

## Приходная накладная
В обработке проведения заполняют «Себестоимость» суммой документа (конструктор или запрос со свёрткой — на экзамене не снижают, но запросом лучше).

## Расходная накладная (старая методика)
1. Очистка движений регистра, взвод флага.
2. **Блокировка** регистра остатков: режим «Исключительный», по номенклатуре из табличной части; **по складам не блокируется**, потому что заранее неизвестно, с каких складов будет списание, поэтому блокируются все склады.
3. Запрос: временная таблица `ВТ_Товары` (Номенклатура, Количество, группировка по номенклатуре, условие по ссылке; **только товары**, услуги отбираются условием «ВидНоменклатуры = Товар»); индекс по номенклатуре.
4. Левое соединение `ВТ_Товары` с `Остатки(&МоментВремени, Номенклатура В (...))` по номенклатуре. По складам отбора **нет** (нужны все склады). Поля: номенклатура, её представление (для сообщений), склад, `ЕСТЬNULL(КоличествоОстаток, 0)`, `ЕСТЬNULL(СебестоимостьОстаток, 0)`.
5. **Итоги** по номенклатуре: `МАКСИМУМ(Количество)` (количество по документу) и `СУММА(КоличествоОстаток)` (остаток по компании).
6. **Приоритет** — соединение остатков с регистром сведений: `РегистрСведений.ПриоритетыСкладов.СрезПоследних(&МоментВремени)` по складу **остатков** (в `ВТ_Товары` склада нет). Затем упорядочивание:
   ```
   ВЫБОР КОГДА Остатки.Склад = &Склад ТОГДА -1
        ИНАЧЕ ЕСТЬNULL(Приоритеты.Приоритет, 100) КОНЕЦ
   ```
   `УПОРЯДОЧИТЬ ПО Приоритет`. Для склада без записи берётся 100. Склады с равным приоритетом списываются «как повезёт» (это нормально, по замечанию зрителей).
7. Контроль остатков на уровне итоговых записей: количество по документу больше остатка по компании → `Отказ`, сообщение «Недостаточно товара %1», `Продолжить`.
8. Списание по детальным записям (складам) пока `КоличествоСписать > 0`:
   - `Количество = Мин(КоличествоСписать, КоличествоОстаток)`;
   - **условие последнего списания:** если `Количество = КоличествоОстаток`, себестоимость = `СебестоимостьОстаток`; иначе `СебестоимостьОстаток / КоличествоОстаток * Количество`;
   - `Движение = Движения.ОстаткиНоменклатуры.Добавить()`, `Расход`, период (дата документа), склад, номенклатура, количество, себестоимость;
   - `КоличествоСписать = КоличествоСписать - Количество`.
9. Проверка: при шапке «Основной склад» списывается сначала с основного (если у него приоритет не выше), затем по приоритетам; при шапке «Запасной» — сначала с запасного.

Замечания зрителей:
- Две виртуальные таблицы нежелательно соединять напрямую (лучше во временные таблицы), но на экзамене и в работе это не критично.
- Ctrl+L — удаление строки в модуле.
- В справочнике «Склады» длина названия не важна.

## Отчёт «Движение товаров» (билет № 4)
Тот же приём, что в уроке 13 (виртуальная таблица остатков и оборотов, стандартный период, группа полей с вертикальным расположением, отдельные колонки для склада и номенклатуры), но:
- Группировка по складу, затем детальные записи (номенклатура); итогов по складу и общего нет → **ресурсы не добавляют**. Автор изменил мнение: если задача не требует итогов, экзаменатор ожидает отсутствия ресурсов («зачем вы вытаскиваете ресурсы»).
- Условное оформление — только в группировке, а не на весь отчёт.
- Заголовок/макеты — как в уроке 13 (в уроке не рисуется).
- Сортировка по складу и номенклатуре (иначе могут быть произвольно упорядочены).

### Особое требование: целое число — 0 знаков, вещественное — 1 знак
Если число целое, выводятся 0 знаков после запятой, иначе 1. Автор показал три способа:
1. **Вычисляемое поле** `СебестоимостьНачальныйОстатокЦелая = СебестоимостьНачальныйОстаток = Цел(СебестоимостьНачальныйОстаток)` и условное оформление с условием «Целая = Ложь» → формат 1 знак. Неудобно: много лишних полей (4 поля).
2. **Пользовательское поле** (выражение) — то же, но поле спрятано в группе «Пользовательские поля». Поведение оказалось непонятным (формат применялся не так, как ожидали; оказалось, что причина в неправильной строке формата).
3. **Предпочтительный способ — выражение представления** у поля набора данных:
   ```
   ВЫБОР КОГДА СебестоимостьПриход = Цел(СебестоимостьПриход) ТОГДА Формат(СебестоимостьПриход, "ЧДЦ=0") ИНАЧЕ Формат(СебестоимостьПриход, "ЧДЦ=1") КОНЕЦ
   ```
   Строку формата проще получить конструктором форматной строки: **`ЧДЦ=0`** и **`ЧДЦ=1`** (в видео сначала формат был написан неверно, поэтому «не работало»).
   Условное оформление затем оставляют только с выравниванием влево.
