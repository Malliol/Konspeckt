# Урок 34. Отгрузка в кредит. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=1_7fc6xwW7w · 52 мин · [полный текст](../transcripts/034_1_7fc6xwW7w.md)

## О чём урок
Билет с **кредитом покупателю** (по нумерации автора — № 8): отгрузка без оплаты разрешена, если не превышены **сумма** и **срок** кредита, определённые для контрагента; оплата гасит накладные по ФИФО; авансов и переплат нет. База — выгрузка урока 26 (приход денег по накладным), упрощённая.

## Условие билета
- Для постоянных покупателей может быть предоставлен кредит на некоторый срок; **срок и размер кредита определяются для каждого контрагента индивидуально**.
- Если сумма накладной не превышает кредит, отгрузка возможна без поступления денег.
- Пока размер кредита не превышен, можно оформлять новые накладные; при проведении контролируются **суммарный долг** (не больше суммы кредита) и **срок кредита** (не больше срока, считая от даты самой ранней неоплаченной накладной).
- При поступлении денег долги гасятся с самой ранней недоплаченной накладной; **авансов и переплат нет**.

## Подготовка (из урока 26)
- «Приход денег»: табличную часть накладных убрать. Только контрагент и сумма оплаты.
- Проведение прихода денег (старая методика, ФИФО по накладным):
  - запрос: `Взаиморасчеты.Остатки(&МоментВремени, Контрагент = &Контрагент)` — накладная, сумма остатка; **упорядочить по моменту времени накладной**; итог по сумме остатка (общий итог = долг по всем накладным);
  - блокировка только по контрагенту;
  - если долгов нет (`Неопределено`), долг = 0 (`Если ДолгПоВсемНакладным = Неопределено`); если сумма оплаты больше долга — ошибка «переплат нет», `Отказ`; иначе ФИФО-списание;
  - в запрос добавляют контрагента, период; поля заполняются конструктором «Заполнить значения свойств».
- Расходная накладная формирует приход долга клиента (период, контрагент, накладная, сумма по документу).
- Лишние регистры и реквизиты из предыдущей задачи убирают.

## Регистр сведений «КредитыПокупателям»
- Хранить сумму и срок кредита в **справочнике нельзя**: нет периодичности (изменение кредита «задним числом» нарушит перепроведение старых документов; «это ошибка»). Регистр сведений **периодический, периодичность «в пределах дня»** (в курсах 1С:Образования — «в пределах секунды», автор считает дня достаточным), независимый режим записи.
- Измерение «Контрагент» (ведущее, запрет незаполненных значений, «Выдавать ошибку»).
- Ресурсы: «СуммаКредита» (12/2, неотрицательное, «Выдавать ошибку»; нулевой кредит бессмыслен), «СрокПредоставленияДней» (3 знака, неотрицательное, «Выдавать ошибку»).
- Регистр выводится в командный интерфейс рядом с курсами валют.

## Первая попытка: новая методика (ошибочная)
Идея: записать приход долга в «Взаиморасчёты» (новая методика), затем проверить по остаткам, не превышен ли кредит; если превышен — отказ. Выглядит правильно (автор напоминает: выбор не оптимальной методики проведения — ошибка). Запрос после записи:
- `Взаиморасчеты.Остатки(&Граница, Контрагент = &Контрагент)` — «Долг клиента» = `СуммаОстаток`; **дата самой ранней неоплаченной накладной** = `МИНИМУМ(Накладная.Дата)` (по накладным с положительным остатком); **количество дней долга** = `РАЗНОСТЬДАТ(ДатаСамойРаннейНакладной, &Период, ДЕНЬ)`; `ЕСТЬNULL(..., 0)`.
- Разность дат считается по датам без времени: 1 марта 23:59:59 и 2 марта 00:00:00 дают 1 день, 1 марта 00:00 и 1 марта 23:59 — 0.
- Кредит получают методом `РегистрыСведений.КредитыПокупателям.ПолучитьПоследнее(Дата, Новый Структура("Контрагент", Контрагент))` — всегда возвращает структуру с полями «СуммаКредита» и «СрокПредоставленияДней», при отсутствии записи нули. Получать нужно **до** записи движений/блокировки (не держать блокировку лишнее время).
- Проверка: `Если ДолгКлиента > Кредит.СуммаКредита` → «Превышение долга клиента над разрешённой суммой кредита на %1 руб.», `Отказ`; `Если КоличествоДнейДолга > Кредит.СрокПредоставленияДней` → «Превышение срока кредита на %1 дн.»; `Отказ`. Две проверки без `Возврат`, чтобы пользователь видел обе ошибки.

### Почему новая методика здесь неверна (блокировки)
В новой методике блокировка накладывается автоматически при записи по измерениям записи («Контрагент» и **текущая накладная**). Но для контроля кредита нужен **долг по всем накладным контрагента**, значит блокировать нужно **только контрагента** (все его накладные). Новая методика заблокировала бы меньше, чем нужно, — это ошибка. Решение — старая методика с явной блокировкой.

## Правильное решение: старая методика
1. Очистка движений, флаг записи, **кредит получить до блокировки** (чтобы не держать регистр заблокированным).
2. **Блокировка:** `БлокировкаДанных`, `Добавить("РегистрНакопления.Взаиморасчеты")`, исключительный режим, `УстановитьЗначение("Контрагент", Контрагент)` (накладные не блокируются отдельно: нужны все), `Заблокировать()`.
3. Запрос остатков на **момент времени** (границу «Включая» не используют — движений документа ещё нет): долг клиента, дата самой ранней неоплаченной накладной, количество дней долга; **учёт суммы документа**: `ДолгКлиента + СуммаПоДокументу > Кредит.СуммаКредита` — иначе текущая накладная не учитывалась бы.
4. Проверки без `Возврат` (обе ошибки); `Если Не Отказ` — формируется приходное движение (добавить долг).
5. Пример проверки: кредит контрагента 500 000 на 30 дней; накладная 450 000 проведена; ещё 60 000 — превышение суммы на 10 000; на 2 апреля — превышение срока (1 апреля уже нельзя даже на 1 руб.: «срок 30 дней, а прошло 31»); оба нарушения сообщаются вместе.

## Замечания
- `Возврат` при ошибке в блоке проверок не нужен, чтобы сообщить о нескольких ошибках.
- Метод `Движения.Взаиморасчеты.Записать()` и `Записывать = Истина` с очисткой равноценны.
- Заполнение значений в конструкторе (период, контрагент) — удобно; можно не выбирать поле контрагента запросом, если заполнять отдельно.
- Блокировку, установленную автоматически новой методикой, отменить нельзя.
