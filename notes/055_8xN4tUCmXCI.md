## О чём урок
**Работа над ошибками** по урокам 52–54 и **переработка задачи № 11 (перемещение с задержкой)** — без вида субконто «Даты» и с одной таблицей проводок вместо двух оборотов.

## Исправления по предыдущим урокам
1. **Сборка (урок 54) — условие последней комплектующей.** Альтернативные способы определения последней итерации: (а) накопление количества комплектующих и сравнение с суммой по табличной части (способ урока 54); (б) **номер итерации и `Выборка.Количество()`** — в выборке `Количество` (без скобок — это данные) и `Количество()` (со скобками — число записей): завести переменную «НомерИтерации», увеличивать на 1 в начале цикла и сравнивать с `Выборка.Количество()`; если равны — последняя итерация. Это не ошибка, автор забыл рассказать раньше.
2. **Расходная накладная (урок 54):** опечатка — запрос брал `ВТ_Товары` (все строки) вместо `ВТ_ТоварыТовар` для остатков по товарам; исправлено (нашёл зритель Иванча).
3. **КуплеПродажа (урок 53):** `ВЫРАЗИТЬ(Субконто3 КАК Документ.ПриходнаяНакладная).МоментВремени` в запросе остатков для ФИФО. После того как **тип партии стал составным** (добавлен документ «КуплеПродажа»), для субконто-партии «КуплеПродажа» значение приведения = `NULL` → момент времени меньше всех приходных → порядок списания неверный (партия «купля-продажа» списывается первой). Нашла зрительница «буковка». Исправление: `ВЫБОР КОГДА Субконто3 ССЫЛКА Документ.ПриходнаяНакладная ТОГДА ВЫРАЗИТЬ(Субконто3 КАК Документ.ПриходнаяНакладная).МоментВремени КОГДА Субконто3 ССЫЛКА Документ.КуплеПродажа ТОГДА ВЫРАЗИТЬ(Субконто3 КАК Документ.КуплеПродажа).МоментВремени КОНЕЦ`.
   - **Рекомендация:** для потенциально составных типов (партия, покупатель) явное приведение `ВЫРАЗИТЬ` делает код хрупким: при расширении типа сломаются многие места (запросы, отчёты, внешние печатные формы, обработки). Для типов, которые точно не расширят (номенклатура), приведение допустимо; экзаменатор, по наблюдению автора, не против обращения через точку.
4. **Отчёт «Задержки товара» (урок 52):** ошибка Иванчи — отчёт «на период» показывал только товары, у которых и **отправка, и прибытие** попали в период (в «ОборотахДтКт» без явных параметров начало/конец периода подставляются автоматически в **обе** таблицы). Исправление: в таблице **отправки** параметр начала периода — «пустая дата», но СКД подменяет пустую дату на начало периода; **чтобы запретить подмену — взять параметр в фигурные скобки** (`{&НачалоПериода}`), чтобы он не подставлялся. Конец периода можно оставить (отправка раньше получения). Отчёт — «задержки товара, **поступившего за период**».

## Переделка задачи № 11 (идея зрителей буковки s и «АйВиДжей»)
Замечание Айви Джи: «товар прибыл 10 мая, а на счёте „Товары“ оказался 15 мая (дата документа)» — период проводки прибытия должен быть **фактической датой прибытия**. Тогда **отдельная «дата прибытия факт» не нужна**: можно считать, что **дата документа «Прибытие» и есть фактическая дата** (так же, как у «Приходной накладной» дата документа = дата поступления).
1. В «Прибытии» **удалить реквизит «ДатаПрибытияФакт»**; период проводок — `Дата` документа.
2. Удалить вид субконто **«ДатыПрибытия»** (и из составного типа «Дата») — спорного примитива больше нет; из плана счетов, из документов «Отправление» и «Прибытие» (обновить обработки проведения; максимум субконто на «Товарах в пути» — 2).
3. **Дату плана** берут **из документа отправления через точку** (один раз, по индексу «Ссылка» — «три сотых секунды»): `ДокументОтправления.ДатаПрибытияПлан`, `ДокументОтправления.Склад` — склад отправителя (два поля одним соединением).

## Новый запрос отчёта «Задержки товара»
- **Одна таблица** — `Управленческий.ДвиженияССубконто(…)` (**с условием на регистратор — для периода**: при выборе «Регистратор»/«Период» появляется поле «Период» — дата документа): проводки **Дт «Товары» — Кт «Товары в пути»** (условие `СчетДт = &Товары И СчетКт = &ТоварыВПути`).
- Поля: склад получателя — `СубконтоДт2` (выразить в «Склады»), документ отправления — `СубконтоКт2` (**`ВЫРАЗИТЬ(СубконтоКт2 КАК Документ.Отправление)` — тут выражение допустимо: тип документа отправления точно не расширят**), через него — `Склад` отправителя и `ДатаПрибытияПлан`; **дата прибытия факт = Период проводки**.
- **Задержка** = `РАЗНОСТЬДАТ(ДатаПрибытияПлан, ДатаПрибытияФакт, ДЕНЬ)`; условие «только при задержке»: `ДатаПрибытияПлан < НАЧАЛОПЕРИОДА(Период, ДЕНЬ)` (период приводят к началу дня).
- Поля отчёта те же: отправитель, получатель, дата прибытия, задержка → СКД не меняется (отчёт именно по полученным за период товарам, без подмены параметров).
- Преимущества нового решения: **одна таблица вместо двух оборотов с соединением**, нет примитивного типа в субконто, нет проблемы с границами периода (отбор только по таблице получения). Решение Прохожего (со вспомогательным субконто-датой) — «купился на все ошибки».
