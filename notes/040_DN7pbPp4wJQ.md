# Урок 40. Индексирование таблиц — 2. MS SQL Profiler. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=DN7pbPp4wJQ · 52 мин · [полный текст](../transcripts/040_DN7pbPp4wJQ.md)

## О чём урок
Факультативное занятие (не обязательно для экзамена): как смотреть **план выполнения запроса** в SQL Server Profiler и на фактах ответить на вопросы, звучавшие в чатах — когда используется индекс, влияет ли порядок условий, дорого ли брать поля через точку.

## Инструменты
- **Консоль запросов с сайта ИТС** имеет флажок «Показывать план запроса» — только **текстовый** план (в файловой базе — упрощённый; удобнее переключить вывод на «колонки и таблицы БД»). Текстовые планы больших запросов читать трудно.
- **SQL Server Profiler** даёт **графический** план. Нужна **клиент-серверная** база на MS SQL Server (файловая не подходит; для домашних опытов нужен серверный ключ; для сдавших «Специалиста» — льготное предложение). Файловую базу в клиент-серверную переносят через выгрузку/загрузку `.dt`.
- Настройка трассировки: подключиться к СУБД; события — `SQL:BatchCompleted` (текст запроса без параметров), `RPC:Completed` (с параметрами), в разделе Performance — **`Showplan Statistics Profile`** (текстовый план) и **`Showplan XML Statistics Profile`** (графический план); фильтр по имени приложения («1CV8…»). Масштабирование Windows может ломать окно Profiler — шрифт уменьшают.
- Обработка «Структура хранения метаданных» — сопоставление объектов 1С и таблиц/полей/индексов СУБД (`_Reference15` → справочник «Номенклатура»; `_Description`, `_Code`, `_Folder`, `_Marked`, `_IDRRef`).
- **Показатели:** «Index Scan» (просмотр индекса — читается весь индекс/таблица, не быстро), «Index Seek» (поиск по индексу — быстро), «Table Scan». **«Стоимость оператора»** — в условных единицах; сравнивают **проценты** между операторами (какой дольше всех), а не абсолютные значения. «Предполагаемая стоимость поддерева» — стоимость оператора вместе с вложенными; у самого левого оператора — стоимость всего запроса.

## Что выяснили (выводы)
1. **Поля через точку по ссылке — практически бесплатно.** Получение шапки по ссылке из табличной части — быстрый поиск по индексу «Ссылка» (≈13 % запроса; группировка и вставка во временную таблицу дольше в ~3 раза). **Количество полей, получаемых через ссылку, не влияет на скорость** (проверено: 1 поле и несколько — одинаковая стоимость). Параметры запроса — бесплатны. Не стоит фанатично экономить на соединении по проиндексированным полям (левое соединение по ссылке — не страшно); но получить склад параметром вместо соединения — тоже допустимо.
2. **Группировка дорогая:** платформа неявно добавляет **сортировку** (на ~78 % времени группировки), затем группировку и вычисление скалярного значения. **Помещение во временную таблицу** тоже заметная операция (до 41 %). Не стоит злоупотреблять временными таблицами.
3. **Виртуальная таблица остатков на момент времени** превращается в громоздкий запрос (настройки хранения итогов + таблица итогов + доборка по таблице движений); **актуальные остатки** (без даты) дают простой план (сканирование таблицы итогов, если выводятся все). Если нужны именно текущие остатки — дату не указывать.
4. **Индексы по полям временной таблицы** меняют план: без индекса по «Номенклатура» — сканирование таблицы итогов, с индексом — поиск по индексу.
5. **Отбор по номенклатуре и складу** (способ Павла Белоусова — условие `Номенклатура В (…) И Склад = &Склад` в параметрах таблицы остатков): индекс используется, если в таблице итогов хоть сколько-нибудь записей (оптимизатор не использует индекс на таблицах менее ~10 записей — быстрее пробежать целиком; это не проблема реальной базы). Вариант «склад — через левое соединение/второе условие по индексированному полю складу» тоже даёт поиск по индексу; нужно **проиндексировать склад** во временной таблице. Белоусовский способ предпочтителен (нет лишнего соединения).
6. **Порядок условий в отборе не влияет** на план и стоимость: оптимизатор SQL Server и агент 1С сами выбирают порядок (проверено: одинаковые 51 % и одинаковая стоимость при перестановке «склад/номенклатура»). Авторы книг (Белоусов, «Язык запросов 1С» и др.) тоже пишут, что порядок не важен — утверждение «сначала склад, потом номенклатура» в чате ошибочно; бездоказательное «отбор по колонкам в порядке следования обязателен» — «бредово».
7. На практике автор Profiler использует при подготовке к экзамену и редко — в работе с типовыми конфигурациями (оптимизировать типовые запросы не имеет смысла, усложняет обновление).
