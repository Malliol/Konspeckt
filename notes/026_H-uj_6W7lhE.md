# Урок 26. Взаиморасчёты. Начало. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=H-uj_6W7lhE · 53 мин · [полный текст](../transcripts/026_H-uj_6W7lhE.md)

## О чём урок
Продолжение задачи урока 25: документ **«Приход денег»**, регистр **взаиморасчётов** и распределение оплаты по накладным **по ФИФО** (с самой ранней недооплаченной). Первый в курсе регистр взаиморасчётов. Основа — решение урока 25.

## Условие билета (суть)
- Оплата покупателя поступает **общей суммой по нескольким накладным**; накладные указываются в табличной части, сумма — в шапке. Документ должен называться «Приход денег».
- При проведении оплата **автоматически распределяется по накладным**, начиная с самой раннего недооплаченного документа.
- Оплачивать нужно **фактически принятый** товар (сумма получено), а не отгруженный.
- **Переплат и авансов нет.**

## Конфигурация
- Документ **«ПриходДенег»**: реквизиты «СуммаОплаты» (число 12/2, неотрицательное, проверка заполнения), «Контрагент» (проверка заполнения); табличная часть «СписокНакладных»: «Накладная» (ссылка на расходную накладную, проверка заполнения). В интерфейсе он идёт после расходной накладной.
- В расходной накладной **реквизит «Контрагент»** (справочник «Контрагенты», проверка «Выдавать ошибку»), выведенный на форму. Без него нельзя определить, кто должен.
- Регистр накопления **«Взаиморасчёты»** (вид «Остатки»): измерения «Контрагент» и «Накладная» (запрет незаполненных значений: переплат/авансов нет, пустая накладная не бывает), ресурс «Сумма» (12/2). **«Неотрицательное» не ставить** (возможны сторно-записи — автор вообще ни разу не видел запрета на неотрицательные в таких регистрах).
- **Связь параметров выбора** у реквизита «Накладная» в табличной части: «Отбор.Контрагент» = «Контрагент» из шапки — в форме выбора показываются только накладные этого контрагента.
- Приход делает расходная накладная (долг клиента растёт), расход — приход денег (долг гасится). «Положительный остаток во взаиморасчётах» — долг клиента перед нами.
- Желательно журнал/форма выбора накладных с суммой отгружено и суммой по документу (для удобства).

## Расходная накладная: долг клиента
В обработке проведения расходной накладной после движений по отгрузкам: если **«СуммаПоДокументу» (сумма полученного) > 0** — приходная запись в «Взаиморасчётах»: период — дата документа, контрагент — из шапки, накладная — ссылка на документ, сумма — сумма по документу; **`Записывать = Истина`**.
- Ошибка из урока: автор сначала взводил флаг только внутри условия `Если Сумма > 0`. Тогда при перепроведении с суммой 0 набор не очищается (регистр остаётся с прежним долгом). **Флаг нужно взводить всегда**, а не условно. Если отказ — дальше не продолжать.
- Долг фиксируется в момент получения товара покупателем (когда введена сумма получено).

## Приход денег (старая методика, как ФИФО по накладным)
1. Очистка движений регистра взаиморасчётов, флаг записи, блокировка.
2. Пакет запросов:
   - `ВТ_Накладные`: накладная из табличной части, отбор по ссылке; индекс по накладной.
   - `ВТ_ДолгиПоНакладным`: левое соединение `ВТ_Накладные` с `Взаиморасчеты.Остатки(&МоментВремени, Контрагент = &Контрагент И Накладная В (...))` — по накладной; `ЕСТЬNULL(СуммаОстаток, 0)`. Левое соединение нужно, чтобы **накладные с нулевым долгом не терялись**.
   - Для контроля: итоговый запрос с общим итогом `СУММА(СуммаОстаток)`; отдельный запрос накладных с нулевым долгом.
3. **Контроль:**
   - сумма оплаты не должна превышать суммарный долг по накладным (переплат нет): сообщение «Сумма оплаты не должна превышать суммарный долг по накладным (он равен %1)», `Отказ`, `Возврат`;
   - накладные с нулевым долгом (уже оплачены или долг не сформировался) — ошибка: «По накладной %1 нет долга», `Отказ`, `Возврат`. Мнения расходились (проще игнорировать), автор считает нужным сообщить пользователю.
4. Распределение по ФИФО: `СуммаКОплате = СуммаОплаты` (переменная; реквизит не меняют). Цикл по детальным записям (накладные), пока `СуммаКОплате > 0`:
   - `Сумма = Мин(СуммаКОплате, СуммаОстаток)`;
   - `Движения.Взаиморасчеты.ДобавитьРасход()`: контрагент, накладная, сумма, период;
   - `СуммаКОплате = СуммаКОплате - Сумма`.
   Пример: оплата 5000, долги по накладным 4750 и 4750: 4750 уходит на первую, 250 — на вторую.
5. **Упорядочить накладные по моменту времени** (самые ранние первыми) — важный пункт, подсказанный зрителем: `УПОРЯДОЧИТЬ ПО Накладная.МоментВремени`.
6. **Блокировка:** исключительная, по накладной из источника данных (табличная часть) и (по замечанию зрителя) по контрагенту.
7. Остатки считаются на **момент времени** (границу «Включая» не используют: движения документа очищены).

## Индексы и параметр «Контрагент»
- В таблице остатков взаиморасчётов есть составной индекс «период + контрагент + накладная». Если при отборе указана только накладная, индекс используется не полностью. Поэтому контрагента передают **параметром** (отбор по двум полям: `Контрагент = &Контрагент И Накладная В (...)`), а не получают через точку/соединение из табличной части.
- Автор считает параметр «экзаменационной фишкой»: проще получить контрагента через ссылку, но Белоусов и курсы 1С передают параметр. В реальной работе — через ссылку.
- Временную таблицу накладных индексируют по контрагенту и накладной (порядок индексов в данном случае не важен, но удобнее совпадать с таблицей регистра: сначала контрагент, потом накладная).
- Ошибка из урока: не был заполнен «Контрагент» в движении расхода (регистр падал: «Значение поля контрагент не может быть пустым») — в расход нужно добавить контрагента из шапки.
