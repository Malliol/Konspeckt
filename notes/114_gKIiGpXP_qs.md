# Урок 114. Функциональные опции и параметры функциональных опций (УФ). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=gKIiGpXP_qs · ~45 мин · [полный текст](../transcripts/114_gKIiGpXP_qs.md)

## О чём урок
Билет № 16 по УФ: **«Доступ для пользователей по основным подсистемам нужно ограничить с помощью функциональных опций; возможность работы с подсистемой устанавливается в соответствии с должностью сотрудника; пользователь не должен получить доступ к секретному регистру этой подсистемы»**. Решение — **функциональные опции + параметр функциональных опций «Должность»**.

## Простейшая функциональная опция (на складах)
- **Функциональная опция** — «флажок, включающий/выключающий функционал». Сама данные не хранит: **место хранения** — константа (булева) или регистр сведений (ресурс).
- Пример: константа «ИспользоватьСклады» (булева) + ФО «ИспользоватьСклады» (хранение — в константе; **«Состав»**: справочник «Склады», реквизит «Склад» в ТЧ «Приходной накладной» и в шапке «РасходнойНакладной» — они пропадают из интерфейса/форм при выключении; объекты — в подсистему).
- **Обновление интерфейса при изменении константы** — **не появляется само**: после изменения нужно вызвать **`ОбновитьИнтерфейс()`** (клиентская процедура); в менеджере константы нельзя («это клиентская штука»). Решение: **форма «ДополнительныеНастройки»** (форма констант, «ПриЗаписиНового…»/после записи вызвать `ОбновитьИнтерфейс()`); у константы **снять «Использовать стандартные команды»** (иначе рисуется в интерфейсе автоматически), форму — в подсистему.
- «**Использовать стандартные команды**» — флажок у объекта (справочника/константы), включающий автоотрисовку в интерфейсе (за счёт него справочник «Должности» виден, а у константы выключаем).

## Решение билета: ФО на должность
**Значения ФО различаются для разных пользователей (должностей)** → **общая константа не подходит**: «параметризуемая» ФО:
1. **Регистр сведений «ДоступКПодсистемам»** (непериодический), подсистема «УправляемыеФормы»; **измерение «Должность»** (справочник «Должности»); **ресурсы-флажки**: «ДоступКОУ», «ДоступКБУ», «ДоступКРасчётам» (булевы).
2. **Три функциональные опции**: «ДоступКОперативномуУчёту», «ДоступКБухгалтерскомуУчёту», «ДоступКРасчётам» — **«Хранение» — регистр сведений «ДоступКПодсистемам», соответствующий ресурс**; «Состав»: **подсистема** (оперативный учёт / бухгалтерский учёт / расчёты) **и регистры этой подсистемы** (чтобы «пользователь не получил доступ к секретному регистру»): регистр накопления «ТоварыНаСкладах» (для демонстрации создали: измерения «Номенклатура», «Склад», ресурс «Количество»; регистратор — документ), регистр бухгалтерии, регистр расчёта и их регистры.
3. **Параметр функциональных опций «Должность»** (в конфигурации: «Общие → Параметры функциональных опций»): тип «СправочникСсылка.Должности», **«Использование» — измерение регистра «ДоступКПодсистемам» → поле «Должность»**; затем в каждой ФО **«Хранение» — ресурс**; система **сама** выбирает запись регистра по параметру (поиск «значения ФО по параметру»).
   - **Если у параметра совпадающих записей несколько/нет — берётся максимум (Истина, если хоть в одной)**: замечание зрителя Юрия Зайцева (проверено на директоре).
4. **Установка параметров** — в **модуле управляемого приложения** (корень → «Модуль управляемого приложения» → `ПередНачаломРаботыСистемы()` / `ПриНачалеРаботыСистемы()`):
```bsl
Процедура ПередНачаломРаботыСистемы(Отказ)
    Параметры = Новый Структура("Должность", ОбщегоНазначенияВызовСервера.ДолжностьТекущегоПользователя());
    УстановитьПараметрыФункциональныхОпцийИнтерфейса(Параметры);          // параметры ФО интерфейса — структура
КонецПроцедуры
```
   - Модуль приложения — **клиент**, параметры сеанса — **сервер** → **общий модуль с флажком «Вызов сервера»** (по стандарту имя заканчивается на «ВызовСервера», например «ОбщегоНазначенияВызовСервера»); функция **экспортная**:
```bsl
Функция ДолжностьТекущегоПользователя() Экспорт
    Запрос = Новый Запрос("ВЫБРАТЬ Должность ИЗ Справочник.ФизическиеЛица ГДЕ Ссылка = &Ссылка");
    Запрос.УстановитьПараметр("Ссылка", ПараметрыСеанса.ТекущийПользователь);
    Выборка = Запрос.Выполнить().Выбрать();
    Если Выборка.Следующий() Тогда Возврат Выборка.Должность; КонецЕсли;
    Возврат Неопределено;
КонецФункции
```
   (запрос — «более правильный для экзамена», чем `Ссылка.Должность` через объектную модель — по правилам экзамена).
5. **Обновление интерфейса при изменении регистра «ДоступКПодсистемам»:** форма записи регистра → после записи `ОбновитьИнтерфейс()` — «в реальном времени» видно появление/исчезновение подсистем.

## Тест
- В регистре: «Бухгалтер» — все три подсистемы (потом оставить «БУ»), «Директор» — расчёты и т.д., «Менеджер» — ОУ; пользователь без должности («Новиков») не видит ни одной подсистемы — «так и должно быть».
- Автор ошибся: строка «директор» ставил на «бухгалтера» (в записи «параметр = должность» не указана должность); после заполнения должностей — Бельдыев — «бухгалтер», Жупиков — «директор» (расчёты). Мелочи: проверка заполнения у складов — убрать.
