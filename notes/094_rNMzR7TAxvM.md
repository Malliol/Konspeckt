# Урок 94. Премия и «произвольная сумма денег» — вытеснение, базовый период по периоду действия (СПР). Подготовка к специалисту по платформе 1С

## О чём урок
Стрим пришлось перезапустить (запутался в запросе). Работа над ошибками по запросу из урока 93 и продолжение билета «меняющийся оклад»: **премия в процентах от оклада за период действия** и **«произвольная сумма денег», вытесняющая премию**.

## Работа над ошибками (запрос разбивки оклада)
1. **Проиндексировать все поля соединений** в каждой временной таблице пакета: в `ВТ_НачисленияСОкладом` и `ВТ_ДатаСреза` — **«НомерСтроки», «Период»**.
2. **Отсев «Период <= ДатаОкончания» — в условие первого соединения** с регистром сведений (раньше стоял в итоговой таблице): иначе сотрудник без ставки (Бердыев) **теряется** совсем. В условие/выражение: `ЕСТЬNULL(Период, ДАТАВРЕМЯ(1,1,1)) <= ДатаОкончания` — тогда Бердыев «возвращается» с нулевым окладом.
3. **Идея зрителя (воробей бородатый):** вместо двух запросов (срез + «Период > ДатаНачала») — один запрос с условием **`Период >= ДатаСреза`** и подменой даты: `ВЫБОР КОГДА Период = ДатаСреза ТОГДА ДатаНачала ИНАЧЕ Период КОНЕЦ` («ПериодДействияНачало»). Работает, но **теряет сотрудников, у которых на дату начала ставки ещё нет** (дата среза для строки не нашлась). Автор вернул вариант со срезом — «как было».
4. Если ставка по сотруднику установлена **не с первого числа** (с 15-го): считается с 15 числа, **ошибка не выводится** (в билете такого условия нет — «не додумывать»).
5. **Улучшение проверки ошибок** (по замечанию Степана Позднякова): ошибку «**не указана ставка оклада на дату начала**» выводить, если **для номера строки не найдена дата среза**: запрос — `ВТ_НачисленияСОкладом` (левое соединение) `ЛЕВОЕ СОЕДИНЕНИЕ ВТ_ДатаСреза ПО НомерСтроки` и `ДатаСреза ЕСТЬ NULL` — сообщение: «Не указана ставка оклада у сотрудника … на дату ДД.ММ.ГГГГ»; `Отказ = Истина`. Проверка по нулевому окладу — отстой, новая — лучше (но «не делайте то, о чём не просят» — автор сомневается, что нужно на экзамене).
6. Условия по запросам для всех пакетов — **все поля, нужные в итоговом запросе, «протаскивать» (параметр, базовые периоды)** через все три части `ОБЪЕДИНИТЬ ВСЕ`, иначе будут `NULL`.

## Условие (продолжение билета)
«**Дополнительно сотруднику может быть начислена премия в процентах от начисленного ему в том же расчётном периоде оклада.** Процент премии **в течение периода начисления не меняется и задаётся в документе «НачислениеЗарплаты»**. **Период премии задаётся с точностью до дня** в документе. **Вместо премии за любой отработанный день сотруднику может быть выплачена произвольная сумма денег**» (→ «произвольная сумма» **вытесняет премию**).
- **Оклад, премия, «произвольная сумма денег» — все в плане «ОсновныеНачисления»** (у всех — период действия; вытеснение только внутри одного плана с периодом действия): «Премия» — **вытесняется «ПроизвольнойСуммойДенег»** (на закладке «Вытесняющие» у премии отметить произвольную сумму).
- Зависимость премии от базы — **по периоду действия, базовый вид — «Оклад»**; регистр расчёта — «Базовый период» включить.
- **Параметр (процент/сумма)** — реквизит «Параметр» (10/2) в табличной части «ОсновныеНачисления» документа (**проверку заполнения не включать** — для оклада параметр не нужен) и в регистре расчёта. Для премии — процент, для произвольной суммы — сумма, для оклада — «ничего».
- **Параметр в запрос нужно «протащить»** (автор: «протащить параметр» — не профессиональный термин, на собеседовании так не говорить) — через все части объединения.

## Базовый период премии
- Заполнять **только для премии**: `БазовыйПериодНачало = ДатаНачала`, `БазовыйПериодКонец = КонецДня(ДатаОкончания)` — в запросе: `ВЫБОР КОГДА ВидРасчета = Премия ТОГДА ДатаНачала ИНАЧЕ ПУСТАЯДАТА КОНЕЦ` (и аналогично для конца).
- **Но**: при вытеснении премии произвольной суммой **базовый период не вытесняется** (он «не знает» про вытеснение). Решение — флажок **«Период действия является базовым периодом»** в плане видов расчёта «Основные начисления» (для расчёта базы **по периоду действия, а не по базовому периоду**; «по-моему, единственная задача экзамена, где нужен этот флажок»). Тогда база считается за **фактический период действия премии** (который вытеснением разбит на части). Поля «БазовыйПериодНачало/Конец» заполнять **не нужно**, но **флажок «Базовый период» в регистре расчёта приходится оставить включённым** (иначе нет виртуальной таблицы «База»; поля остаются «пустыми одинокими»).
- Эффект: премия 1–9 и 21–31 октября (произвольная сумма 10–20) — база меньше; если вытеснена полностью — 0. Проверка — виртуальная таблица «ФактическийПериодДействия».

## Расчёт премии (после оклада!)
Премия **считается после оклада** (приоритетов в билете нет, оклад должен быть уже посчитан) — отдельный цикл/блок:
1. Запрос: основная таблица `ОсновныеНачисления` (`Регистратор = &Ссылка`, `ВидРасчета В (&ВидыРасчета)` — номер строки) **левое соединение** с `База(&Измерения, , , Регистратор = &Ссылка И ВидРасчета В (&ВидыРасчета))` по НомеруСтроки; `ЕСТЬNULL(РезультатБаза, 0)` → «БазаНачислений». Параметры: `ВидыРасчета = {Премия}` (массив «на будущее»), `Измерения = {Сотрудник}`; **отборы в обеих таблицах одинаковые**.
   - Соединяем основную и базу, чтобы заполнялись показатели расчёта даже при отсутствии базы (метод 1С.рф), либо только база (метод Белоусова) — автор выбирает соединение; **достаточно соединения по номеру строки** (регистратор в условии соединения не нужен — отбор уже есть в каждой таблице; **номер строки уникален**).
2. Цикл: `Если ВидыРасчета.Найти(Движение.ВидРасчета) = Неопределено Тогда Продолжить`; `Выборка.Сбросить(); Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки")`; **`Если Движение.ВидРасчета = Премия Тогда Движение.Результат = Выборка.БазаНачислений * Движение.Параметр / 100; ЗаполнитьЗначенияСвойств(Движение, Выборка, "БазаНачислений")`** (реквизит «БазаНачислений» 10/2 в регистре); запись **`Записать(, Истина)`**.
3. **Произвольная сумма денег:** результат = параметр: `Движение.Результат = Движение.Параметр` — считают **в том же цикле** (общая схема): массив `ВидыРасчета` для получения базы содержит **только премию**, а для «произвольной суммы» база не нужна → условие в цикле: **`Если ВидыРасчетаДляБазы.Найти(Движение.ВидРасчета) <> Неопределено Тогда … (премия) ИначеЕсли Движение.ВидРасчета = ПроизвольнаяСуммаДенег Тогда Движение.Результат = Движение.Параметр`**. Альтернатива — результат произвольной суммы заполнять в подготовке записей («некоторые так делают»; автору не нравится: «подготовка — в одном месте, расчёт — в другом»).
- Пример: оклад 200 000 + 70 042 → база 270 042? (в видео — суммы по сегментам), премия 20 % = 14 208…; арифметика сверяется калькулятором.

## Ответы зрителям
- «Достаточно ли соединения только по номеру строки?» — да, строка однозначно определяет сотрудника, график, вид расчёта.
- «Почему нельзя взять одну таблицу базы без соединения?» — из-за заполнения показателей при отсутствии базы.
- «Зачем массив видов расчёта, если вид один?» — «общая схема: сегодня один, завтра пять».
- Общий модуль для расчётов (идея зрителя) — полезно, но не обязательно.
- Следующее занятие — **выплата зарплаты** (95).
