# Урок 36. Отчёт «Исполнение бюджета». Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=0I3OVQcAxhE · 28 мин · [полный текст](../transcripts/036_0I3OVQcAxhE.md)

## О чём урок
Завершающее занятие блока «Оперативный учёт»: отчёт «ИсполнениеБюджета» по регистру «Бюджет» (урок 35) на СКД с **таблицей**: в строках подразделения → статьи затрат, в колонках месяцы, под каждым месяцем — **План / Факт / Процент исполнения**.

## Вопрос про сообщения (с урока 35)
Вывод сообщения при «Провести и закрыть» остаётся открытым: варианты — параметр сеанса (заполняется при проведении, сообщение показывается после закрытия формы; автору не нравится), проверка в `ПередЗаписью`, оповещение/предупреждение (работают только на клиенте). Автор считает, что экзаменаторы сами не знают об этой проблеме; решение «Сообщить» в обработке проведения принимается.

## Запрос (отладка в консоли запросов)
- Регистр `Бюджет.Обороты(&НачалоПериода, &КонецПериода, Месяц, )`: подразделение, статья, `СуммаПлан`, `СуммаФакт` (суммы превышения в отчёте не нужны).
- **Периодичность — «Месяц»** (иначе нет разбивки по периодам); поле периода — `ПериодМесяц`.
- **Процент исполнения:** `ВЫРАЗИТЬ(СуммаФакт / СуммаПлан * 100 КАК ЧИСЛО(15, 4))`; перед делением — проверка `СуммаПлан <> 0`, иначе значение-заглушка (бюджет не задан, а затраты есть) — автор выбрал **три прочерка** «---» (в билете ничего не сказано; «0» неправильно, «100%» неверно).
- Проверка на тестовых данных: приход 543… → 69,25 %; превышение 510 на 500 — 102 %, и т. д.; для тестов с датой 900 год и 2010 год — по периодичности видно период.

## Схема компоновки
1. Набор данных «запрос»; параметр **«Период»** — стандартный период, флаг «всегда использовать»; выражения параметров: `&Период.ДатаНачала`, `&Период.ДатаОкончания`; параметр «НачалоПериода/КонецПериода» скрыты.
2. Настройка: **«Таблица»**; в строках «Подразделение» → вложенная «СтатьяЗатрат»; в колонках «Период» (число колонок заранее неизвестно).
3. Параметры вывода — «Не выводить»; расположение общих итогов по горизонтали и вертикали — «Нет»; расположение итогов группировок — «Отдельно и только в итогах» (для колонок «План/Факт/Процент»). **Итоги по подразделению отключить** — иначе процент бессмысленный («154 %»: сумма процентов).
4. **Ресурсы нужны** (иначе числа на пересечении не выводятся): `СуммаПлан`, `СуммаФакт`, `ПроцентИсполнения` (в этом порядке); «Заголовки» у полей — «План», «Факт», «Процент исполнения»; в таблице процент — выражение ресурса без суммирования.
5. **Условное оформление:** выравнивание влево, формат 0 знаков (область — только для группировок), без отступа (в образце его нет).
6. Заголовок месяца: условное оформление «для заголовков полей» с форматом даты `ДФ=MMMM` и полужирным/по центру; для столбца «Период» — по центру.
   - Чтобы месяц был **по центру над тремя колонками**, нужен **макет** (а не условное оформление): макет группировки (не заголовка!) для колонки «Период»: ячейка с параметром «Период» (жирный, форматирование) над строкой «План / Факт / Процент исполнения»; ширина подставляется из макета. Привязка — по **имени группировки** (в колонках — «макет группировки»; в строках — «макет заголовка»).
   - Если формат даты не применился: условное оформление отчёта с пустым форматом перебивает формат из макета. Формат лучше задавать только в одном месте — в условном оформлении для даты.
7. Заголовок статьи — поле «СтатьяЗатрат» вынести в поля отчёта и задать заголовок «Статья».
8. Общий заголовок отчёта: «Исполнение бюджета за период с [НачалоПериода] по [КонецПериода]» — группировка «детальные записи» (вариант использования «дополнительная информация»), макет группировки, шаблон с параметрами; таблицу подчиняют заголовку (чтобы не было пустой строки). Ячейки в заголовках в таблице могут не рисоваться — не страшно.
9. В пользовательские настройки включается «Период» (по умолчанию — год).
