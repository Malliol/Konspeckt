# Урок 67. Расчёт оклада (СПР). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=GxHelAObIxU · 45 мин · [полный текст](../transcripts/067_GxHelAObIxU.md)

## О чём урок
Первая расчётная задача (билет № 1): **оклад пропорционально отработанному времени в днях** + «хвост» шаблонных формулировок. База — выгрузка занятия 66 (совместительство **не допускается** — подразделение убрано).

## «Хвост» шаблонных формулировок
- **Все начисления вносятся документом «НачислениеЗарплаты»; в расчётном периоде может быть один документ на все виды расчёта или несколько (по одному на вид)** — результат расчёта не должен зависеть от разбиения; на пункт «можно не обращать внимания».
- **«Все данные вводятся только в пределах одного месяца»** — запись не переходит из месяца в месяц; контролировать не нужно (если пользователь ввёл иначе — «сам дурак»); есть **один билет**, где переход интервала между месяцами придётся учитывать.
- **«В одном документе могут быть данные только за текущий расчётный период»:** нельзя вводить оклад за июль в документе августа; больничный/отпуск может быть введён задним числом **только если сказано в задаче**.
- **Период регистрации** (месяц, за который начисляется зарплата): в курсах 1С.рф — отдельное поле «ПериодРегистрации» в документе; у **Прохорова и Белоусова** — отдельного поля нет: **период регистрации = начало месяца даты документа** (`НачалоМесяца(Дата)`). Автор следует им (иначе «белоусов минусует»).

## Задача (билет № 1)
- Сотрудники получают **оплату по окладу пропорционально отработанному времени в днях**; **дневная ставка = первоначальное значение оклада / количество рабочих дней в том же периоде**; оклад рассчитывается за **фактически отработанные дни**. Первоначальное значение оклада — регистр сведений **«СведенияОСотрудниках»**, меняется **не чаще раза в день**, **берётся на начало расчётного периода**.
- (Совместительства нет → подразделение удаляют из документа, регистра расчёта, регистра сведений.)
- Тестовые данные: Бердыев — оклад 100 000 (с 1 января; позже 150 000 с 10 августа и 180 000 с 20 августа — для задач с изменением в месяце), Васина — 120 000; в документе «НачислениеЗарплаты» август: Бердыев — оклад на весь месяц; Васина — с 10 по 31 августа; график «Пятидневка» (22 рабочих дня в августе, у Васиной 16).

## Две стадии проведения расчётного документа
1. **Подготовка записей** («заполнение регистра расчёта предварительно»): в `ОбработкаПроведения`: `Движения.ОсновныеНачисления.Записывать = Истина`; `Для Каждого Строка Из ОсновныеНачисления Цикл Движение = Движения.ОсновныеНачисления.Добавить(); ЗаполнитьЗначенияСвойств(Движение, Строка)` (скопируются сотрудник, график, вид расчёта и т. п. — одноимённые поля); **`Движение.ПериодДействияНачало = Строка.ДатаНачала`, `Движение.ПериодДействияКонец = КонецДня(Строка.ДатаОкончания)`** (**приводить к концу дня — частая ошибка**; «период действия» (начало месяца и др.) система вычислит сама при записи по начальной дате); **`Движение.ПериодРегистрации = НачалоМесяца(Дата)`**; `Движения.ОсновныеНачисления.Записать()` — результат пока **не заполняется**.
2. **Расчёт**: через «платформенные механизмы» — **виртуальные таблицы регистра расчёта**; поле «Результат» заполняют вторым проходом (в том же обработчике, тот же модуль — «чаще всего в одном модуле, как Белоусов»; альтернатива — общий модуль «РасчётОсновныхНачислений», как в курсах 1С.рф/у Прохорова).

## Виртуальная таблица «ДанныеГрафика» (обязательно)
- **`РегистрРасчета.ОсновныеНачисления.ДанныеГрафика(Регистратор = &Ссылка)`** — таблица регистра с **левым соединением с графиком работы**; **использовать её вместо ручного соединения** с «ГрафикомРаботы» (за ручное соединение — **−2 балла**). В ней все записи документа (левое соединение), поля:
  - **`НомерСтроки`** (уникально идентифицирует строку документа/записи регистра);
  - **`ЗначениеПериодДействия`** (сумма значений графика за **весь период действия** — «норма»/«рабочих дней»; соответствует всему месяцу при периоде регистрации и действии = месяц);
  - **`ЗначениеФактическийПериодДействия`** (сумма за **фактический интервал** действия — «отработано»);
  - `ЗначениеПериодРегистрации` — сумма за весь месяц регистрации (не используется: «используем период действия, не период регистрации»);
  - сотрудник, вид расчёта и т. п. можно не выбирать — `НомерСтроки` достаточно.
  - Поля называют «РабочихДней» и «ОтработанныхДней» (можно «Норма»/«Факт»).
  - Все выражения для этих полей — через **`ЕСТЬNULL(…, 0)`** (левое соединение с графиком; нет записей → NULL; «без ЕСТЬNULL снизят оценку»).
- **Величины — часы или дни:** по умолчанию в «Значении» графика стоят 8 (часы); **в этой задаче — дни** → график заполняют **1 для рабочего дня** (обработка «Заполнение графика» с единицей; правка при подготовке: «значение» = 1); если в задаче нужны и дни, и часы — тогда добавляют новые поля/переименовывают; **если в задаче не нужны — новых полей не создают**.

## Запрос расчёта (пакет)
1. `ВТ_ДанныеГрафика` ← `РегистрРасчета.ОсновныеНачисления.ДанныеГрафика(Регистратор = &Ссылка)`: `НомерСтроки`, `Сотрудник`, `ЕСТЬNULL(ЗначениеПериодДействия, 0) КАК РабочихДней`, `ЕСТЬNULL(ЗначениеФактическийПериодДействия, 0) КАК ОтработанныхДней`; **индекс по сотруднику**.
2. **Оклад — срез последних только по нужным сотрудникам:** левое соединение `ВТ_ДанныеГрафика` с `РегистрСведений.СведенияОСотрудниках.СрезПоследних(&ПериодРегистрации, Сотрудник В (ВЫБРАТЬ Сотрудник ИЗ ВТ_ДанныеГрафика))` по сотруднику; `ЕСТЬNULL(Оклад, 0)`. (**Нельзя получать срез по всем сотрудникам** — в базе их тысячи.)
3. Результат запроса — построчно, номер строки/сотрудник/график/оклад/рабочих/отработанных.

## Цикл расчёта
- Бегут **по таблице движений** (`Для Каждого Движение Из Движения.ОсновныеНачисления Цикл`), а не по выборке запроса: `Выборка.Сбросить(); Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки")` — поиск выполняется **с текущего места**, поэтому **перед каждым поиском сбрасывать выборку**; нужная строка **всегда найдётся** (левое соединение), проверка не нужна.
- **Результат** = `Выборка.Оклад / Выборка.РабочихДней × Выборка.ОтработанныхДней` (**сначала деление, потом умножение — как у Белоусова**; обязательна проверка `РабочихДней <> 0`, иначе результат 0 — деление на ноль). Нулевой оклад — результат 0, «нормальная ситуация» (ничего предусматривать не нужно).
- **Реквизиты для наглядности:** добавить в регистр расчёта реквизиты «РабочихДней» (5/2), «ОтработанныхДней» (5/0 — в днях?), «Оклад» (10/2) — «поля, легшие в основу расчёта» (нужно для проверки экзаменатору); `ЗаполнитьЗначенияСвойств(Движение, Выборка)` копирует оклад, рабочие и отработанные дни и номер строки.
- **Повторная запись:** `Движения.ОсновныеНачисления.Записать(, Истина)` — **второй параметр «ТолькоЗапись» = Истина**: «**только запись** — не пересчитывать фактический период действия и перерасчёты»; без него записываются перерасчёты и пересчитывается фактический период действия → **−1 балл**. Если в регистре есть период действия — **второй параметр Истина обязательно** (в курсах 1С.рф третий параметр «Ложь» вместо 2-го; у Белоусова — Истина). (Справка: «`ТолькоЗапись` — Истина: только записи без вычисления фактического периода действия».)
- Флажок `Записывать = Истина`: после записи набор **сбрасывает его в Ложь**; на момент непосредственного `Записать()` флаг можно не ставить (автор любит взводить флажок «по привычке»).
- Расчёт: Бердыев — 100 000 (22/22), Васина — 120 000 / 22 × 16 = 87 272,73.

## Ответы зрителям
- Сергей: **таблицу движений на форму добавлять нельзя** («никто так не делает»).
- Иван Андреевич: в срезе последних ради совместительства нужны пары «сотрудник + подразделение» — когда совместительство допускается; сейчас подразделения нет.
- Автор записан на экзамен («метод Афанасьева» — жёсткий короткий срок подготовки).
