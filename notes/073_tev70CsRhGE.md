# Урок 73. Отчёт «Анализ начислений за период» (СПР). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=tev70CsRhGE · 22 мин · [полный текст](../transcripts/073_tev70CsRhGE.md)

## О чём урок
Две части: (1) исправление сторно оклада — брать **старое значение оклада**; (2) отчёт **«Анализ начислений»** — встречается в 4–5 билетах.

## 1. Исправление сторно
Проблема: при расчёте сторно оклад брался из регистра сведений на начало **текущего** периода регистрации — получались абсурдные суммы (оклад «приснился» вырасти до миллиона → командировка уходит в большой минус).

Решение: в регистре расчёта уже хранится **реквизит «Оклад»** (поле, легшее в основу расчёта). В запросе вытаскиваем из движений **«Оклад» и флаг «Сторно»**:
- **не сторно** → оклад из регистра сведений (на текущий период регистрации);
- **сторно** → оклад **берём из записи (параметр/реквизит «Оклад»)**, т. е. значение, по которому оклад считался изначально.
Итог: сторно считается по старому окладу, значение небольшое и согласованное.

## 2. Отчёт «Анализ начислений»
**Условие:** «Для анализа сделанных сотрудникам начислений необходимо предусмотреть отчёт»: строки — **подразделение, сотрудник, вид расчёта**; колонки — **периоды (период регистрации)**; на пересечении — результат; **отбор по периоду** (начало/конец).

**Запрос:** обычная таблица регистра расчёта (не «База», не «ДанныеГрафика»): подразделение, сотрудник, вид расчёта, **период регистрации**, результат. **Не период действия!** Зарплата начисляется за период регистрации («зарплата за июнь» = период регистрации июнь, даже если командировка была в мае). Условия: период регистрации между `&НачалоПериода` и `&КонецПериода` и **`Активность = ИСТИНА`** (Белоусов любит).

**СКД:** отчёт «АнализНачислений» в подсистеме «Расчёты».
- Набор данных-запрос; параметр **«Период»** — стандартный период, «Всегда использовать», выражения: `Период.ДатаНачала` / `Период.ДатаОкончания` для начала/конца периода; в вариант отчёта — флажок пользовательских настроек, период по умолчанию — год; **выводить параметры = Ложь**.
- Структура — **таблица**: строки — группировка «Подразделение → Сотрудник → Вид расчёта» (**составная группировка**, поля группировок в **отдельной колонке**, а не в разных столбцах — «расположение полей группировок — отдельно в одном столбце»), колонки — группировка «ПериодРегистрации».
- **Результат должен быть ресурсом** — иначе значение на пересечении не выведется.
- **Расположение общих итогов по горизонтали — «Нет»** (итоги по горизонтали не нужны).
- Условное оформление: мин/макс ширина **15 символов**.
- **Сортировка:** подразделение, сотрудник, вид расчёта, **период регистрации (для колонок — по возрастанию)**.
- **Заголовок колонок:** для настройки заголовка **колонок** создают **«макет группировки»** (а не «макет заголовка группировки»): указывают поле группировки, параметр подставляется автоматически; **формат даты `ММММ гггг`** (латиницей: `MMMM yyyy`). Условное оформление: область — «заголовок полей», **полужирный, по центру**.
- Двоеточие после слов в заголовке, границы таблицы, цветные рамки — **не требуются**, время не тратить.

## Диалог с зрителем: период регистрации vs период действия
Расчётный листок за август показывает командировку, которая была в июле, но оплачена в августе — **в отчёте начислений показывается период регистрации**. Если нужен период действия — задача должна это явно сказать.
