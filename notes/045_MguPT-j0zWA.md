# Урок 45. Расчёт себестоимости без учёта сроков годности (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=MguPT-j0zWA · 88 мин · [полный текст](../transcripts/045_MguPT-j0zWA.md)

## О чём урок
Бухгалтерская задача (билет № 1 по системе Михаила Прохожего): учёт товаров **в разрезе сроков годности**; списание ФИФО по сроку годности (раньше истекающий — первым), а **себестоимость — средняя по товару без учёта сроков годности**. Склады не ведутся. База — выгрузка занятия 41.

## Условие
- Учёт товаров **в разрезе сроков годности** (срок годности — календарная дата); приход товара — документ, в табличной части которого **указывается срок годности**; склады не ведутся.
- Расходная накладная: списывать **в первую очередь товар с наименьшим сроком годности**; **себестоимость — средняя по товару по всем срокам годности** (т. е. срок годности при расчёте себестоимости не учитывается).
- Проводки как в прошлой задаче (приход Дт «Товары» — Кт «Поставщики»; расход Дт «Прибыли и убытки» — Кт «Товары» на количество и себестоимость; Дт «Покупатели» — Кт «Прибыли и убытки» на сумму документа), контроль остатков.
- Отчёт: «Остатки товаров» (номенклатура, срок годности, количество, сумма); **сумма по сроку годности считается расчётным образом: общая сумма товара / общее количество × количество по сроку годности** (в билете оговорено).

## Настройка плана счетов
- ПВХ «ВидыСубконто» → составной тип: добавить **«Дата»**; предопределённый вид субконто **«СрокиГодности»** (тип «Дата»). **Примитивные типы в составном типе субконто — нежелательно**: каждый тип добавляет поля хранения (ссылочный тип — 3 поля, примитив — ещё по полю, итого для «Дата» значительно больше), индекс по субконто ограничен **16 полями**, и третье/вторые субконто «не влезут» в индекс. В типовой «Бухгалтерии» срок годности хранят в справочнике «Серии номенклатуры» (ссылочный тип). Но в экзаменационной задаче **требование «только регистр бухгалтерии»** (построение учётной схемы не на регистрах бухгалтерии — −3 балла), других вариантов нет → **допустимо** указать «Дата» в составном типе, снижения оценки не будет.
- Счёт «Товары»: максимум субконто 2 (номенклатура, сроки годности). Для «Прибылей и убытков» субконто **не нужны** (отчёта по продажам в билете нет).
- В приходной накладной: реквизит табличной части «СрокГодности» (дата, проверка заполнения).
- Обновить документ «Операция» (удалить таблицу движений с формы и добавить заново) — иначе колонок субконто будет меньше.

## Проводка прихода
Дт «Товары»: `СубконтоДт[Номенклатура]`, `СубконтоДт[СрокиГодности] = Выборка.СрокГодности`, `КоличествоДт`, `Сумма`; Кт «Поставщики» (без субконто). Табличная часть сворачивается запросом (отбор по ссылке).

## Критически важно: суммовой учёт не должен вестись по сроку годности
Если оставить, остатки по сроку годности получат суммы, которые не сойдутся с «средней себестоимостью» (например, списано 20 000 при приходе по сроку на 10 000 → «минус»). Нужно **выключить суммовой учёт по субконто «Срок годности»**:
1. В плане счетов создать **признак учёта субконто «Суммовой»** и связать его с ресурсом «Сумма» регистра бухгалтерии (свойство ресурса «Признак учёта субконто» — для ресурса «Сумма» указывается признак учёта субконто).
2. В настройке счёта «Товары»: у субконто «Номенклатура» — суммовой **да**, у «Срок годности» — **нет** (количественный учёт — по обоим).
- Результат: суммы хранятся **только в разрезе номенклатуры**, количество — в разрезе номенклатуры и срока годности (аналог двух регистров накопления).
- **Подводный камень:** после добавления признака учёта субконто в конфигураторе пользовательский режим **не переносит настройки**: колонка «Суммовой» появляется, но флажок не стоит и суммовой учёт «выключается» полностью → субконто счёта нужно **удалить и добавить заново**, затем поставить признак.
- **Запрос:** если в `Остатки` выбрать **«Субконто2» (срок годности)** — таблица не содержит сумм (по этому разрезу их нет), приходится получать суммы **второй таблицей остатков без субконто2**: тогда отдаёт сумму и количество по товару в целом.

## Запрос расходной накладной
1. `ВТ_Товары` (номенклатура, количество) по ссылке документа, индекс по номенклатуре.
2. Соединение с двумя таблицами регистра:
   - **«ОстаткиПоСрокамГодности»**: `Управленческий.Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконтоСрокГодности, Субконто1 В (номенклатура))` — по номенклатуре, **срок годности = Субконто2**, **количество остатка по сроку**;
   - **«ОстаткиПоТоварам»**: тот же регистр, виды субконто — только номенклатура, **без** субконто2: количество и **сумма остатка по товару** целиком (по компании).
   - Для каждой таблицы свой массив видов субконто (**не передавать лишние виды**, иначе медленнее): `ВидыСубконтоСрокГодности` — только срок годности (или оба), `ВидыСубконтоНоменклатура` — номенклатура.
   - Левое соединение для товаров; внутреннее — допустимо во втором (остатки по сроку без общих остатков — значит ошибка данных).
3. Итоги по номенклатуре: количество, остатки по товару — `МАКСИМУМ`; количество остатка по сроку — `СУММА`.
4. Порядок: **по сроку годности** (`Субконто2` без `ВЫРАЗИТЬ`: обращения через точку нет).
5. Блокировка: `Блокировка.Добавить("РегистрБухгалтерии.Управленческий")`, исключительный, **блокируется счёт «Товары»** (обязательно, иначе ошибка; блокировка регистра без счёта — косяк) и вид субконто «Номенклатура» из списка номенклатуры документа (источник данных — табличная часть). Сроки годности не блокируют (вычисляются из остатков).

## Алгоритм списания
- Контроль: `КоличествоПродажи > КоличествоОстатокПоТовару` → «Недостаточно товара %1 в количестве %2», `Отказ = Истина`, `Продолжить`.
- Цикл по номенклатуре и срокам годности (по возрастанию срока): `КоличествоСписать = Выборка.Количество` (**количество из документа — не переменная от предыдущей итерации**: ошибка автора — «списалось 30 вместо 15»); пока `> 0`: `Количество = Мин(КоличествоСписать, КоличествоОстатокПоСроку)`; `КоличествоСписать -= Количество`.
- **Себестоимость = СуммаОстатокПоТовару / КоличествоОстатокПоТовару × Количество** (средняя по товару без учёта срока); `Окр(…, 2)` не нужен — округление ресурса.
- Движение: Дт «Прибыли и убытки» — Кт «Товары», `СубконтоКт[Номенклатура]`, `СубконтоКт[СрокиГодности] = срок годности`, `КоличествоКт = Количество`, `Сумма = Себестоимость`.
- Вторая проводка (вне цикла): Дт «Покупатели» — Кт «Прибыли и убытки», `Сумма = СуммаПоДокументу` (разрез по номенклатуре не нужен — отчёта по продажам нет).
- **Различие сумм:** проводка Дт «Прибыли и убытки»/Кт «Товары» фиксирует **себестоимость** (сумма — себестоимость); проводка «Покупатели»/«Прибыли и убытки» — **сумму в продажных ценах** («сумму по документу»). Как запомнить — по условию: «проводка делается на количество и сумму себестоимости».

## Копеечная погрешность (условие последнего списания)
Деление средней себестоимости даёт погрешность: если себестоимость 7000 на 30 штук, списания 3 × ~… теряют 0,01. Нужно, чтобы **при полном списании товара сумма списаний равнялась остатку**. Способы:
1. **Накопление и корректировка последнего движения:** накапливать округлённую себестоимость, а в последней записи цикла прибавить разность `СуммаОстатокПоТовару − СебестоимостьИтого` (после цикла к последней детальной записи обращаются через переменную `Движение` — у итоговой записи всегда есть детальная). Автор считает его допустимым («не такой плохой»).
2. **Условие последнего списания (лучше):** если **списывается весь остаток по товару** (`Количество документа = КоличествоОстатокПоТовару`) **и** это **последняя итерация** (`Количество = КоличествоСписать` в текущей итерации, т. е. оставшееся к списанию равно списываемому), то себестоимость = `СуммаОстатокПоТовару − накопленная себестоимость`; иначе — по формуле. Проверка на примере с остатками 70 000 / 30 шт.: три итерации; в последней добавляется «копейка». «Запомните — это ходовой приём, он повторится в других задачах».
- Тест на погрешность: подобрать сумму, не делящуюся на 3 (например, 7000 вместо 6000).

## Отчёт «Остатки товаров по срокам годности»
- Две виртуальные таблицы: остатки по срокам годности и остатки по товарам (суммы) — **внутреннее соединение** по номенклатуре.
- **Сумма по сроку = СуммаОстатокПоТовару / КоличествоОстатокПоТовару × КоличествоОстатокПоСроку** (формула дана в билете).
- Виды субконто: для остатков по срокам — массив (номенклатура и срок), для остатков по товарам — один вид «Номенклатура» (не лишний массив).
- `ВЫРАЗИТЬ(Субконто1 КАК Справочник.Номенклатура)`, `ВЫРАЗИТЬ(Субконто2 КАК Дата)` — иначе при выводе тянутся лишние соединения и неверный формат даты.
- СКД: параметры периода — «Начало завтрашнего дня»; группировка по номенклатуре, детальные записи; ресурсы — количество, сумма; расположение группировок — отдельно в итогах; формат даты и суммы; итоги по вертикали — отключить; поле количества в запросе нужен псевдоним (ошибка «повторяющийся псевдоним»).
- Чтобы не вводить в заблуждение расчёты (копейки не «схлопнулись»), можно **округлить сумму в запросе** `ВЫРАЗИТЬ(… КАК ЧИСЛО(12, 2))`; автор приводит к целым при показе (формат 0 знаков), чтобы не провоцировать экзаменатора.

## Замечания
- Белоусов спрашивает «когда в проводке `Сумма` = себестоимость, а когда сумма документа» — решается формулировкой условия (см. выше).
- Следующее занятие — в среду (праздники), две задачи с **инвентарными номерами** (билет № 2). Никаких свободных тем, пока не закончен бухучёт.
