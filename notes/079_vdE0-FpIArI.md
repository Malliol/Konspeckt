# Урок 79. Премия руководителю: база в разрезе (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=vdE0-FpIArI · ~35 мин · [полный текст](../transcripts/079_vdE0-FpIArI.md)

## О чём урок
**Билет № 4** (часовой тариф, смены — из урока 78): **руководителям подразделений выплачивается премия в виде процента от суммы оплат по тарифу за предыдущий месяц сотрудников его подразделения, за исключением оплаты самого руководителя.** Ключевой приём — **«разрезы» при получении базы**. Отчёт «Анализ премий» — просто записи регистра (подразделение, сотрудник, процент, сумма; **не забывать проверку активности**).

## План видов расчёта и регистр
- Премия — вид расчёта **«ПремияРуководителю»** в **«ДополнительныхНачислениях»** (процент от базы, нет начала и конца). **Зависимость от базы — по периоду действия** (почти всегда: зарплату за август могут **доначислить** в сентябре — этот кусок обязан попасть в базу; по периоду регистрации он бы выпал). Базовый вид расчёта — **«ОплатаПоЧасовомуТарифу»** (план «ОсновныеНачисления»). Зависимость по периоду регистрации обычно у удержаний, но на экзамене удержаний практически не бывает (штрафы Белоусов кладёт в основные).
- **Регистр расчёта «ДополнительныеНачисления»**: период действия — нет, **базовый период — есть**; измерения «Сотрудник», «Подразделение» (**совместительство**), ресурс «Результат»; реквизиты «БазаНачислений» и **параметр «Процент»** (10/2, неотрицательный) — «наглядность» (необязательно); график, отработанные часы, тарифная ставка — удалить; **флажок «Базовый»** у измерений в **обоих** регистрах.
- Где хранить процент — условие не говорит. Бывают билеты, где одновременно «задаётся в документе» и «хранится в базе, меняется не чаще раза в день» — противоречие; здесь — в документе (самое простое).
- Документ: табличная часть **«ДополнительныеНачисления»** (сотрудник, подразделение, вид расчёта, процент); **без графика, дат** — копия основных; проверку заполнения у процента — не включать (на будущее), неотрицательный.
- **Проверка пустого документа** — в **`ОбработкаПроверкиЗаполнения`** (или флажками «Выдавать ошибку» у **основных** начислений): но **не обязательно оба раздела**: премию можно ввести отдельным документом без основных начислений → вариант: ошибка, только если **обе** части пусты (`Если ОсновныеНачисления.Количество() = 0 И ДополнительныеНачисления.Количество() = 0`). Объекты регистров не забыть вынести в подсистему («расчётные регистры» — в самом конце пройтись по всем подсистемам, чтобы не было «зависших» объектов).

## Данные для проверки
Руководитель «Зубиков» (зарплата 720 000/мес), подчинённые Бердыев и Васина (по 444 000 за июль → 888 000), премия 10 % → ожидаем 88 800; при отдельном документе премии 20 % за август от ≈ 840 000 → 168 000. Тестовые документы за июль и август (не забыть **менять период действия** в копиях).

## Подготовка записей
```bsl
Движения.ДополнительныеНачисления.Записывать = Истина;
Для Каждого Строка Из ДополнительныеНачисления Цикл
    Движение = Движения.ДополнительныеНачисления.Добавить();
    ЗаполнитьЗначенияСвойств(Движение, Строка);
    Движение.ПериодРегистрации    = ПериодРегистрации;
    Движение.БазовыйПериодНачало  = ДобавитьМесяц(ПериодРегистрации, -1);
    Движение.БазовыйПериодКонец   = ПериодРегистрации - 1;   // период регистрации — начало месяца
КонецЦикла;
Движения.ДополнительныеНачисления.Записать();
```

## Расчёт: База + разрезы
1. Запрос `РегистрРасчета.ДополнительныеНачисления.База(&Измерения, , , Регистратор = &Ссылка)`: `НомерСтроки`, `РезультатБаза` (**без ЕСТЬNULL**; левого соединения нет).
2. **Измерения базы — только «Подразделение»** (сотрудника **убрать**): база считается по подразделению целиком (сумма оплат всех работавших в подразделении). Если оставить «Сотрудник» — база будет собственная зарплата сотрудника (получилось 720 000 у самого руководителя, «двоение» — из-за забытого периода действия).
3. **Исключить руководителя — через «разрезы»:** в параметры таблицы добавить массив **`Разрезы`** (= «Сотрудник»); тогда таблица возвращает поле **`СотрудникРазрез`** (база **в разрезе сотрудников**, но суммы считаются по подразделению), и **отбор по разрезу ставится в условиях (после получения базы)**, а не в параметрах таблицы: `Сотрудник <> СотрудникРазрез` (убираем записи, где сотрудник совпадает с разрезом, т.е. самого руководителя). Затем **сгруппировать по `НомерСтроки` с `СУММА(РезультатБаза)`** (сам запрос не суммирует; в запросе — группировка по номеру строки).
   - В консоли запросов разрезы задаются **списком значений/массивом** («список значений: Сотрудник»).
   - Без параметра «Разрезы» поля `…Разрез` не получить («системе непонятно, что вы хотите»).
4. Цикл: `Выборка.Сбросить(); Если Выборка.НайтиСледующий(Движение.НомерСтроки, "НомерСтроки") Тогда` (**база может не найтись** — условие обязательно) `Движение.Результат = Выборка.БазаНачислений * Движение.Параметр / 100; ЗаполнитьЗначенияСвойств(Движение, Выборка)` — **`ЗаполнитьЗначенияСвойств` внутри условия** (вне условия выборка не позиционирована).
5. Запись: **`Движения.ДополнительныеНачисления.Записать()`** — без «Истина»: у регистра нет периода действия.
6. Параметры в запросе — `Параметры.Измерения = Новый Массив` (подразделение), `Параметры.Разрезы = Новый Массив` (сотрудник); процент брать из `Движение.Параметр`, а не из выборки.

## Ответы зрителям / замечания
- Условность экзамена: руководитель — тот, кому назначена премия руководителя; подчинённые — все остальные сотрудники того же подразделения.
- Премию можно вводить **отдельным документом** — решение работает (отдельный документ в сентябре за август, 20 %).
- Представление ссылки (полное наименование номенклатуры) — задаётся в модуле менеджера (подробнее не разбиралось).
- В дальнейшем: приоритет — 4-й билет, возможно табель.
