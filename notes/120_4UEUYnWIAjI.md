# Урок 120. Цены номенклатуры и форма выбора (УФ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=4UEUYnWIAjI · 45 мин · [полный текст](../transcripts/120_4UEUYnWIAjI.md)

## Исправление ошибки (урок 118)
При привязке сообщения к строке через ВТ «Товары» + остатки **внутреннее соединение подходит лучше левого** (отбор в регистре идёт по товарам из ВТ; не нужно писать `ЕСТЬNULL`); левое тоже работает правильно и на экзамене не наказывается.

## Условие (очень полезная задача)
Хранить **продажные цены деталей в разрезе типов цен** (оптовая, розничная). В «РасходнойНакладной» в шапке указывается **тип цен**. В **форме выбора** номенклатуры для каждой детали дополнительно выводить **цену** по типу цен документа и **текущий остаток** на складе документа; при выборе в документ добавляется не только деталь, но и **цена**.

## Структура данных
- Справочник «ТипыЦен» (в управляемых формах).
- Регистр сведений **«ЦеныНоменклатуры»**: периодичность — в пределах дня, регистратор не нужен; измерения «Номенклатура» (ведущее, запрет незаполненных) и «ТипЦены» (ссылка на справочник, те же флажки), ресурс «Цена» 10/2 (как в накладной; «неотрицательное» в регистре сведений можно, но не обязательно; «выдавать ошибку» — заполняется интерактивно).
- Подсистема: регистр доступен в УФ; флажок **«Использовать стандартные команды»** оставить — получаем стандартную команду «Цены номенклатуры» в форме элемента (ввод цен: кинокамера опт 10 000 / розн 20 000, куртка 5 000/7 500).
- В документе «РасходнаяНакладная» реквизит шапки **«ТипЦены»** (ссылка, «Выдавать ошибку»), вынести на форму.

## Новая форма выбора справочника «Номенклатура»
- **Не делать основной** (иначе откроется везде, где вызывается стандартный выбор: поступления, обработки).
- В динамическом списке формы — **«произвольный запрос»**: все поля номенклатуры + **левое** соединение со **срезом последних цен без указания периода** (нужны актуальные) с условием по **параметру «ТипЦены»**, `ЕСТЬNULL(Цена, 0) КАК Цена`; остатки — виртуальная таблица остатков (период не указывать), параметр «Склад»; `ЕСТЬNULL(КонечныйОстаток, 0) КАК Остаток`. Во вкладке «Связи» **основной таблицей должна быть «Справочник.Номенклатура»**, остальные — «ПРАВОЕ соединение» от неё (настройка может слетать — проверять). Включить «**динамическое считывание данных**». Вывести поля «Цена» и «Остаток» на форму.
- **Остатки:** если нет регистра «ТоварыНаСкладах» — брать **управленческие остатки из регистра бухгалтерии** (`Остатки(&Период, Счет = &Счет, &ВидыСубконто, Субконто2 = &Склад)`; виды субконто — массив: номенклатура — Субконто1, склад — Субконто2; параметры `Счет` = план счетов «Товары», `ВидыСубконто` задаются в `ПриСозданииНаСервере`). Не создавать регистр «только ради остатков» — выдаст непонимание бух. регистров.
- Нюанс: остаток отражает состояние с учётом уже проведённого документа (проведённый документ «съел» остаток) — на экзамене не делают.

## Вызов формы выбора из документа (НачалоВыбора поля «Номенклатура»)
```bsl
&НаКлиенте
Процедура СписокНоменклатурыНоменклатураНачалоВыбора(Элемент, ДанныеВыбора, СтандартнаяОбработка)
    СтандартнаяОбработка = Ложь;
    ПараметрыФормы = Новый Структура;
    ПараметрыФормы.Вставить("Склад", Объект.Склад);
    ПараметрыФормы.Вставить("ТипЦены", Объект.ТипЦены);
    ПараметрыФормы.Вставить("ТекущаяСтрока", Элементы.СписокНоменклатуры.ТекущиеДанные.Номенклатура);
    ОткрытьФорму("Справочник.Номенклатура.Форма.ФормаВыбораРасширенная", ПараметрыФормы, Элементы.СписокНоменклатуры);
КонецПроцедуры
```
- Отключили стандартную обработку (иначе откроется основная форма выбора) — **поведение прописываем вручную**.
- **Параметры формы — структура** (не массив). Склад/тип цены берём из документа и **передаём параметрами**; параметр **«ТекущаяСтрока»** (зарезервированный) — позиционирование на выбранной номенклатуре; **`ТекущиеДанные`** — текущая строка табличной части (`Элементы.СписокНоменклатуры.ТекущиеДанные.Номенклатура`).
- **Третий параметр — «Владелец»** — табличная часть `Элементы.СписокНоменклатуры` (чтобы документ получал оповещение). Режим открытия окна по умолчанию — «блокировать окно владельца» (для формы выбора переопределять не надо).
- **В форме выбора** `ПриСозданииНаСервере`: параметры динамического списка устанавливаются безопасно:
```bsl
Склад = Неопределено; Параметры.Свойство("Склад", Склад);
ТипЦены = Неопределено; Параметры.Свойство("ТипЦены", ТипЦены);
Список.Параметры.УстановитьЗначениеПараметра("Склад", Склад);
Список.Параметры.УстановитьЗначениеПараметра("ТипЦены", ТипЦены);
```
(проверка `Параметры.Свойство` — чтобы не получить исключение, если форма открыта без параметров).

## Возврат выбранного значения вместе с ценой
- В форме выбора обработчик **«ВыборЗначения»** списка (универсальнее «Выбор» — работает и по двойному клику, и по Enter, и по кнопке «Выбрать»; **«Выбор» вручную не нужен**): `СтандартнаяОбработка = Ложь;` и вызов **`ОповеститьОВыборе(Данные)`**, где `Данные = Новый Структура("Номенклатура, Цена", Элементы.Список.ТекущиеДанные.Ссылка, Элементы.Список.ТекущиеДанные.Цена)` (структура вместо одного значения).
- В документе — обработчик **«ОбработкаВыбора»** поля «Номенклатура»/табличной части: `Элементы.СписокНоменклатуры.ТекущиеДанные.Номенклатура = ВыбранноеЗначение.Номенклатура; …Цена = ВыбранноеЗначение.Цена;` (`ЗаполнитьЗначенияСвойств(ТекущиеДанные, ВыбранноеЗначение)`); после изменения цены вызвать **пересчёт суммы строки** (замечание зрителя Юрия Зайцева).
- Документ получает оповещение только если форма выбора открыта **с владельцем**.
- **Ловушка:** если пользователь убрал поле «Цена» из формы выбора, в `ТекущиеДанные` цены не будет (ошибка) → у поля **«Цена» в списке включить «Использовать всегда»** (данные считываются независимо от отображения).
- Пересчитывать цены при смене типа цены в шапке **не нужно** — в условии не сказано, пользователи раздражаются от автоматических пересчётов, на экзамене это может быть минусом.
