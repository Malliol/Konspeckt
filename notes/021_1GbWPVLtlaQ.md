# Урок 21. Свойства и характеристики. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=1GbWPVLtlaQ · 97 мин · [полный текст](../transcripts/021_1GbWPVLtlaQ.md)

## О чём урок
Первое знакомство с **планом видов характеристик (ПВХ)** на задаче билета № 9 (по нумерации автора): учёт товаров в разрезе «свойств» (наборов характеристик), реализованный с использованием плана видов характеристик. Основа — выгрузка после урока 4 (списание по средней). Складов нет.

## Условие билета
- Складской учёт не ведётся, списание себестоимости по средней (способ не указан, берётся самый простой), только товары (без услуг).
- «Для описания товаров существуют **характеристики**, набор которых составляет **свойства**» (пример: характеристика «цвет — чёрный», «размер — 42» → свойство). В билете **терминология перевёрнута** (обычно наоборот): автор пользуется именно билетной терминологией («на время экзамена формулировка билета — закон»).
- Учёт ведётся в разрезе свойств; набор характеристик у товара произвольный (ботинки — цвет, размер; жёсткий диск — вид, объём, цвет…), количество не ограничено.
- **Механизм должен быть реализован с использованием плана видов характеристик.**

## Первая реализация (без ПВХ) и её недостаток
1. Справочник **«СвойстваНоменклатуры»** (длина наименования побольше). Измерение «Свойства» в регистре остатков (тип — этот справочник), запрет незаполненных значений; реквизит «Свойства» в табличных частях приходной и расходной накладной (проверка заполнения «Выдавать ошибку»), вывод на форму.
2. Подчинение справочника «СвойстваНоменклатуры» **справочнику «Номенклатура»** (владелец), чтобы свойства нельзя было указать «не к тому» товару (размер 44 для жёсткого диска).
3. В формах накладных у поля «Свойства» — **связь параметров выбора**: отбор «Владелец = Номенклатура» из той же строки табличной части.
4. Учёт в запросе проведения: **добавить «Свойства» везде, где используется номенклатура**: блокировка (по номенклатуре и свойствам), запрос (поле, соединение по свойствам, отбор в параметрах виртуальной таблицы), представление свойств в сообщениях («Не хватает товара ботинки со свойством цвет белый размер 44 в количестве 1»), движения.
Теперь «товар» — это «номенклатура + свойства».

Недостаток: характеристики остаются частью наименования, поэтому по ним нельзя построить отчёт (по всем белым товарам, по производителю Samsung). Для этого и нужен ПВХ.

## План видов характеристик
- Создаётся ПВХ и переименовывается в **«ХарактеристикиОбъектов»** (в задаче именно так называются характеристики). ПВХ — по сути справочник с дополнительным реквизитом **«Тип значения»**.
- В конфигураторе задаётся **набор допустимых типов значения** (составной тип: строка, число, дата, булево, ссылки на справочники, кроме «СвойстваНоменклатуры», перечисления и др.). В пользовательском режиме для каждого элемента ПВХ (цвет, размер, производитель, объём диска, вид диска) указывается один из этих типов: цвет — «Дополнительные значения», размер обуви — число (неотрицательное), вид диска — «Дополнительные значения», производитель — «Контрагенты» и т. д.
- Для типов вроде цвета неудобна строка (чёрный/чорный/Чёрный), удобнее справочник. Но заводить справочник под каждую характеристику нельзя (конфигурацию пришлось бы менять). Принято создавать **один справочник «ДополнительныеЗначенияХарактеристик»** («куча-мала»), в котором лежат все значения: цвета, объёмы дисков, виды дисков и т. п. Его **подчиняют плану видов характеристик** (владелец — ПВХ, тогда можно задать отбор значений по характеристике) и указывают в свойстве ПВХ «Дополнительные значения характеристик» (система разрешает выбрать только справочники, подчинённые ПВХ), а также в типах значения.
- Справочник «ДополнительныеЗначенияХарактеристик» добавляется в подсистему и группу команд; значения создаются в пользовательском режиме (владелец — характеристика: «Цвет — Чёрный» и т. д.).

## Как хранить набор характеристик свойства — два способа
### Способ 1: табличная часть справочника «СвойстваНоменклатуры»
- Табличная часть **«НаборХарактеристик»**: реквизит «Характеристика» (тип — ПВХ «ХарактеристикиОбъектов», «Выдавать ошибку») и «Значение» (**тип — флажок «Использовать тип значения из плана видов характеристик»**, то есть составной тип ПВХ).
- Чтобы тип значения подставлялся автоматически: у поля «Значение» **«Связь по типу»** → «Характеристика»; чтобы выбор значения ограничивался нужным владельцем: **«Связь параметров выбора»** («Отбор.Владелец» = «Характеристика»). Без обеих настроек пользователь вручную указывает тип и видит всю «кучу».
- Проблемы:
  - **Контроль уникальности**: можно ввести два цвета у одного свойства (чёрный и белый) или повторить. Нужна проверка в обработчике **`ПередЗаписью`**. Подводные камни: по ссылке читается старая версия из базы (до изменений формы), поэтому проверять нужно **табличную часть самого объекта**, а не обращаться к базе по ссылке (иначе для нового объекта проверка проходит, а на второй записи — нет).
  - Решение: в запросе используется временная таблица, описанная **«Описанием временных таблиц»** (источник — обработчик в консоли без таблицы в базе): `ВТ_НаборХарактеристик` с полями «Характеристика» и «Значение», передаётся таблица значений, выгруженная из табличной части: `НаборХарактеристик.Выгрузить(, "Характеристика, Значение")` в параметр. Выгрузка только нужных колонок — лучше (в табличной части обычно много полей).
  - Запрос: `ВЫБРАТЬ Характеристика, КОЛИЧЕСТВО(Значение) ИЗ ВТ_НаборХарактеристик СГРУППИРОВАТЬ ПО Характеристика ИМЕЮЩИЕ КОЛИЧЕСТВО(Значение) > 1` (агрегатная функция в условиях даёт секцию «Имеющие»), затем сообщение `СтрШаблон("Задано более одного значения для характеристики %1", ПРЕДСТАВЛЕНИЕ(Характеристика))` и `Отказ`.
  - В `ПриЗаписи` проверки делать нежелательно: объект к этому моменту уже записан (оптимальнее до записи).
- В современных типовых конфигурациях характеристики хранят в табличных частях объекта (права доступа на объект распространяются на характеристики).

### Способ 2: регистр сведений «ЗначенияСвойств» (проще, рекомендуется на экзамене)
- Измерения: «Свойство» (справочник «СвойстваНоменклатуры»; ведущее, запрет незаполненных значений, проверка заполнения), «Характеристика» (ПВХ; те же флажки); ресурс «Значение» (составной тип ПВХ; проверка заполнения).
- Нужны тот же **связь по типу** («Значение» — по «Характеристике») и **связь параметров выбора** (отбор по владельцу).
- **Уникальность контролируется самим регистром** (записи уникальны в разрезе измерений): два значения одной характеристики для свойства ввести нельзя, код писать не нужно. И индексы по измерениям создаются автоматически. Минус: требуется отдельный ввод; у списка появляется гиперссылка «Значения характеристик свойств» (переход в регистр).

## Отчёт «Ведомость товаров по характеристике»
Билет требует остатки и обороты **в разрезе значений выбранной характеристики** (например, «Цвет»).
- Запрос: `РегистрНакопления.ОстаткиНоменклатуры.ОстаткиИОбороты` (начальный остаток, приход, расход, конечный остаток), внутреннее соединение со **справочником свойств (табличной частью набора характеристик) или регистром значений** по свойству; поля: номенклатура, **ЗначениеХарактеристики**, остатки и обороты; условие **«Характеристика = &Характеристика»** (параметр обязателен; отбор по характеристике принудительный).
  - Группировка (хлопнуть дубли) по номенклатуре и значению характеристики с суммированием: например, разные размеры чёрных ботинок складываются.
  - Для соединения по свойству нужен **индекс по измерению «Свойства»** регистра накопления (для виртуальной таблицы индексируются «период + измерения»; свойство нужно добавить в индекс — ставится «Индексировать» у измерения).
- Параметры: «Период» (стандартный период; параметры начала/конца скрыты), «Характеристика» (пользователь выбирает из ПВХ; использование всегда, запрет пустого значения; порядок параметров — характеристика после периода).
- Структура: группировка «Значение характеристики» → детальные записи; выбранные поля: номенклатура (товар), начальный остаток, приход, расход, конечный остаток. Расположение полей группировок — «Отдельно и только в итогах».
- Ресурсы не нужны (итогов нет).
- Оформление: заголовки полей — жирные и по центру, числа — влево, минимальная ширина; **область использования условного оформления — группировка** (замечание зрителя).
- Заголовок: группировка «Заголовок», макет «Ведомость по характеристике [Характеристика] за период с [НачалоПериода] по [КонецПериода]», параметры шаблона: начало и конец периода (формат даты), характеристика — представление параметра. Слово «Характеристика» в образце с маленькой буквы — можно сделать функцией общего модуля «РаботаСКД.НижнийРегистр(Строка)»; на экзамене «это перебор».
- На экзамене желательно добиваться полного совпадения с образцом, но мелкие расхождения (точка после заголовка, отступ) на оценку не повлияют.
- Дополнительные характеристики объекта метаданных («Использовать дополнительные характеристики» в справочнике) в этом билете не нужны — разберут в следующем занятии.

## Прочее
- Проблему с повторяющимися характеристиками (два цвета) на экзамене обычно решают регистром сведений.
- Блокировка по свойствам нужна по тем же причинам, что и по номенклатуре.
