# Урок 126. Программное добавление элементов на форму (УФ, «главный босс»). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=b4p-16bYj1E · 83 мин · [полный текст](../transcripts/126_b4p-16bYj1E.md)

## Условие
**Для каждого менеджера реализовать список дополнительных сведений, которые он вводит для своего контрагента.** Контрагенту назначается менеджер (физлицо); в форме контрагента в зависимости от выбранного менеджера появляются дополнительные поля (например, у Васиной: регион, контактное лицо, категория; у Бердыева: контактное лицо и тип контрагента). Список дополнительных сведений менеджера — **с помощью плана видов характеристик**. По экзамену задача считается «главной», но её **нерешение не мешает получить «4»** (малый вес).

## Структура метаданных
- Контрагент — реквизит **«Менеджер»** (`СправочникСсылка.ФизическиеЛица`, «Выдавать ошибку»).
- **План видов характеристик «СвойстваОбъектов»** (составной тип значений, «дополнительные значения характеристик» → справочник **«ДополнительныеЗначенияСвойств»**: владелец — ПВХ «СвойстваОбъектов»; во ПВХ этот справочник отметить в типе значений). Свойства: «Регион» (допзначения: Москва, Тюменская область…), «ТипКонтрагента» (допзначения), «КонтактноеЛицо» (физлицо), «Надёжность» (булево). ПВХ нужен потому, что хранит **тип значения** — по нему рисуется поле (флажок/ввод/выбор).
- Справочник физических лиц — **табличная часть «СписокСвойств»** (колонка «Свойство» — `ПВХ.СвойстваОбъектов`, «Выдавать ошибку»): какие свойства менеджер указывает.
- **Регистр сведений «ЗначенияСвойствКонтрагентов»**: измерения «Контрагент» (ведущее), «Свойство» (ведущее; запрет незаполненных), ресурс «Значение» (тип — характеристики свойств; **связь параметров выбора**: владелец — свойство; **связь по типу**). Рисует поля стандартная настройка ПВХ; регистр потом **скрыть** — снять «Использовать стандартные команды».

## Форма контрагента: добавление реквизитов и элементов программно
1. Запрос: свойства менеджера — `ВЫБРАТЬ Свойство, Свойство.Наименование, Свойство.ТипЗначения ИЗ Справочник.ФизическиеЛица.СписокСвойств ГДЕ Ссылка = &Менеджер`.
2. **Реквизиты формы** (`ДобавляемыеРеквизиты`) — массив `Новый РеквизитФормы(Имя, Тип, Путь, Заголовок)`; метод **`ИзменитьРеквизиты(Добавляемые, Удаляемые)`** (на сервере). Имя должно быть идентификатором, а наименование свойства содержит пробелы и спецсимволы → **имена генерируем сами**: `"Реквизит" + Счетчик` (счётчик с 1). Заголовок — наименование свойства.
3. **Таблица соответствия** (реквизит формы, таблица значений: «ИмяРеквизита» — строка, «Свойство» — ссылка на ПВХ): при создании реквизита добавляем строку «имя ↔ свойство». Без неё невозможно связать безымянный реквизит со свойством (чтение/запись значения).
4. **Элементы:** `Элемент = Элементы.Добавить(ИмяРеквизита, Тип("ПолеФормы"), Элементы.ГруппаДополнительныеРеквизиты); Элемент.Вид = ВидПоляФормы.ПолеВвода; Элемент.ПутьКДанным = ИмяРеквизита;` Реквизит без элемента на форме не виден; группа «ДополнительныеРеквизиты» (вертикальная группировка, создана заранее в конфигураторе).
5. **Значения на форме:** `ЭтотОбъект[ИмяРеквизита] = Значение` (доступ к реквизиту по имени; точкой — нет).
   - Контрагент не новый (`Объект.Ссылка` не пустая) → запрос к регистру по контрагенту; для каждой пары (свойство, значение): `НайденныеСтроки = ТаблицаСоответствия.НайтиСтроки(Новый Структура("Свойство", Выборка.Свойство)); Если НайденныеСтроки.Количество() > 0 Тогда ЭтотОбъект[НайденныеСтроки[0].ИмяРеквизита] = Выборка.Значение` (ошибка по ходу — условие «ссылка заполнена» было инвертировано).
6. **Параметры выбора** (иначе в поле «Регион» открывается «сборная солянка» всех допзначений): только если тип реквизита содержит `Тип("СправочникСсылка.ДополнительныеЗначенияСвойств")`: `ПараметрВыбора = Новый ПараметрВыбора("Отбор.Владелец", Свойство); Массив = Новый Массив; Массив.Добавить(ПараметрВыбора); Элемент.ПараметрыВыбора = Новый ФиксированныйМассив(Массив);` — свойство найти по имени реквизита через таблицу соответствия; в справке по параметрам выбора есть пример кода; **на экзамене допустимо опустить**.

## Сохранение (`ПослеЗаписиНаСервере`)
- «После» — запись значений только если объект успешно записан.
- **Сначала очистить значения контрагента**: `Набор = РегистрыСведений.ЗначенияСвойствКонтрагентов.СоздатьНаборЗаписей(); Набор.Отбор.Контрагент.Установить(Объект.Ссылка); Набор.Записать();` (**отбор обязателен**, иначе очистится весь регистр) — чтобы не оставались значения свойств, которые у нового менеджера недоступны.
- Затем **для каждой строки таблицы соответствия**: если значение заполнено (`ЗначениеЗаполнено(ЭтотОбъект[Строка.ИмяРеквизита])`) — `Менеджер = РегистрыСведений.…СоздатьМенеджерЗаписи(); Менеджер.Контрагент = Объект.Ссылка; Менеджер.Свойство = Строка.Свойство; Менеджер.Значение = ЭтотОбъект[Строка.ИмяРеквизита]; Менеджер.Записать();` **Пустые значения не пишем**.
- Спор с зрителями: удалять ли значения невидимых свойств — автор: удалять («не раздувать базу, нет задачи показывать полный список»); не удалять тоже, вероятно, не снизит оценку.

## Смена менеджера (`МенеджерПриИзменении`)
- Вынести всё в серверную процедуру **`ОбновитьДополнительныеРеквизиты()`** (из `ПриСозданииНаСервере` и из `ПриИзменении` менеджера).
- **Перед добавлением — удалить прежние**: по таблице соответствия собрать массив **имён** (`Строка.ИмяРеквизита`, **массив строк**, не массив реквизитов!), для каждой найти `Элементы.Найти(Имя)` и `Элементы.Удалить(Элемент)`; затем **очистить таблицу соответствия** (иначе путаница).
- **Ловушка `ИзменитьРеквизиты`:** если в одном вызове передать удаляемые реквизиты и добавляемые с теми же именами — совпадающие **не удаляются** (не пересоздаются). Решение: сначала **отдельным вызовом** `ИзменитьРеквизиты(, УдаляемыеРеквизиты)` удалить, затем второй вызов — добавить. Второй параметр — **массив строк** (имена), первый — массив `РеквизитФормы`.
- (Альтернативный метод — `ПолучитьРеквизиты()` и отбор по префиксу «Реквизит»; автор предпочёл таблицу соответствия.)
