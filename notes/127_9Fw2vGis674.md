# Урок 127. Бизнес-процессы, часть 1. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=9Fw2vGis674 · 40 мин · [полный текст](../transcripts/127_9Fw2vGis674.md)

## О чём урок
Задачи по бизнес-процессам **очень однотипны** (в отличие от остальных разделов): достаточно научиться делать один процесс. Разобран **билет № 1**. Автор не будет решать целиком все билеты «ради них самих»: решения Михаила Прохорова (в чате/по описанию) можно купить; на экзамене комбинации задач могут быть другими, поэтому надо «включать голову». База — **выгрузка после занятия 113** (в ней только параметр сеанса «ТекущийПользователь»; он нужен для всех задач по бизнес-процессам — отбор списка задач по исполнителю).

## Минимум метаданных
1. **Задача «ЗадачаИсполнителю»** (подсистема «Бизнес-процессы») — обязательна для бизнес-процесса.
2. **Бизнес-процесс «БизнесПроцесс…»** (подсистема «Бизнес-процессы»), в нём указать задачу.
3. **Карта маршрута** — рисуется мышью; без неё стартовать бесполезно.

## Настройка адресации в задаче (закладка «Адресация»)
- **Регистр адресации «АдресацияЗадач»** (из каркаса): измерения **«Исполнитель»** (запрет незаполненных значений — можно), **«Должность»**, **«Подразделение»** — **запрет незаполненных значений у должности и подразделения НЕ ставить** (нужны пустые значения).
- **Реквизиты адресации задачи**: «Исполнитель» (`Справочник.ФизическиеЛица`, основной реквизит адресации), «Должность», «Подразделение».
- **Обязательно сопоставить** каждый реквизит адресации с соответствующим **измерением** регистра адресации (иначе работать будет неправильно).
- **Текущий исполнитель** — параметр сеанса **«ТекущийПользователь»** (нужен для списка невыполненных задач пользователя; указать в настройках адресации).
- Справочник должностей: создать «Менеджер», «Кладовщик», «Бухгалтер».
- **Принцип:** если в действии указан основной реквизит адресации (исполнитель) — регистр адресации не используется; иначе система по должности/подразделению ищет исполнителей в **регистре адресации**.

## Карта маршрута (билет № 1)
Старт → действие «**ЗаявкаПокупателя**» (адресация: должность «Менеджер», подразделение «Отдел продаж»; **не групповое** — любой менеджер, кто успел) → **разделение (элемент «Разделение»)** на два действия параллельно:
- «**ПолучениеОплаты**» — **исполнитель Петров** явно (регистр адресации не нужен);
- «**Отгрузка**» — **групповая задача** (флажок **«Групповая»** — для каждого исполнителя, соответствующего должности, создаётся своя задача; на схеме рисуется «с тенью»), должность «Кладовщик», **подразделение — пустое**;
→ **слияние (элемент «Слияние»)** — следующее действие активируется только после выполнения обеих веток →
- «**СверкаВзаиморасчётов**» — должность «Бухгалтер» (подразделение пустое), любой бухгалтер → конец.
- Ограничение платформы: из точки разделения может выходить несколько линий, но в **одну и ту же точку нельзя входить** несколькими линиями (поэтому после разделения — по линии на каждое действие; лишнюю стрелку удалить). Масштабирование Windows ломает отображение схемы.

## Регистр адресации: что заполнять (ловушки)
- **Не копировать всю таблицу сотрудников в регистр**: лишние записи караются штрафами; заносить **только нужное**.
- **Менеджеры отдела продаж** (Галкин, Палкин, Малкин): исполнитель + должность «Менеджер» + подразделение «Отдел продаж».
- **Кладовщики** (Залкинд, Лоханкин, Жупиков — «Бердыев командовал, а на самом деле кладовщик»): **подразделение оставлять пустым**, даже если в исходной таблице оно указано — задача адресуется «кладовщику с пустым подразделением», а при заполнении подразделения система не найдёт ни одной записи.
- **Бухгалтеры** (Мишина, Кротов): должность «Бухгалтер», подразделение пустое.
- Если у групповой задачи не определены кладовщики в регистре — исполнителя нет → «глючная» задача. Предопределённые элементы-неработники удалить.

## Список невыполненных задач пользователя
- Для задачи — форма списка **«ФормаСпискаНевыполненныхЗадач»** (не основная): основная таблица — задача исполнителям, отбор в настройках списка **«Выполнена = Ложь»**; отбор по текущему пользователю система делает сама благодаря параметру сеанса из настроек адресации.
- Вывести на **рабочую область начальной страницы** (подсистема → правая кнопка → «Рабочая область начальной страницы»).
- Тестирование: создать пользователей (Палкин, Мишина, Жупиков) с полными правами и физлицами; под каждым в своём сеансе видны только его задачи; Бердыев не видит.
- Прогон: старт процесса → менеджер создаёт заявку → Петров получает оплату и все кладовщики отгружают → после **последней** выполненной задачи кладовщика создаётся задача для бухгалтера → Мишина согласует → процесс завершён.
