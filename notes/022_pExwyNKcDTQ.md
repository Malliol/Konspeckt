# Урок 22. Поступления и отгрузки по заказам. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=pExwyNKcDTQ · 60 мин · [полный текст](../transcripts/022_pExwyNKcDTQ.md)

## О чём урок
Задача с **заказами покупателей** (билет по нумерации автора — № 12): закупка и продажа только на основании заказа, остатки заказанного контролируются, себестоимость считается по средней **в разрезе заказов**, к заказу добавляются характеристики. Выгрузка — после урока 4 (средняя). Склада нет.

## Дополнения к прошлому занятию (характеристики, урок 21)
- **Передача табличной части в проверку уникальности:** передавать можно либо саму табличную часть (в запрос попадут служебные колонки: индекс, значение элемента, тип элемента, номер строки), либо **выгрузку** нужных колонок `Выгрузить(, "Характеристика, Значение")`. Выгрузка избавляет от лишних колонок (когда в табличной части 10–15 полей, выигрыш существенный), но создаёт таблицу значений в памяти. Требование экзамена «запрещается создавать таблицы значений без необходимости» — можно считать выполненным, если выгрузка реально сокращает данные. Это спор «ни о чём»: **на экзамене проще хранить значения в регистре сведений** (уникальность контролируется системой, код не нужен); при желании можно хранить в табличной части и вообще не делать проверку.
- **Дополнительные характеристики в отчётах и отборах** (нужен ли «танец с бубном»): чтобы в настройках отчёта в отборе можно было выбрать характеристики объекта (цвет, объём диска) как поля, есть два способа: (1) в конструкторе запроса на закладке «Характеристики» прописать источник; (2) **в свойствах справочника «Номенклатура»** → закладка «Данные» → «Характеристики»: указать ПВХ, и поля значения, значения (табличная часть/регистр). Работает только если в **запросе отчёта вытащено поле «Свойства»** (в уроке 21 оно не было вытащено, и характеристик в отборе не было). Автор считает это бессмысленным для экзамена.

## Условие билета
- Оборудование (номенклатура). Закупка — на основании заказов покупателей: **покупать можно только то, что заказано**; в поступлении для каждой позиции (в табличной части) указывается заказ.
- Один заказ может поставляться несколькими документами поступления; остатки по заказу контролируются: нельзя закупить больше, чем заказано.
- Отгрузка по заказу несколькими накладными, **только на основании заказа** (нельзя отгрузить больше, чем закуплено под заказ).
- **Себестоимость — среднее в рамках закупок под заказ покупателя** (в разрезе заказов).
- «Следует считать, что оборудование по заказу будет отгружено полностью» — значит, записи регистров всегда выйдут в ноль; специально обрабатывать частичную отмену не нужно.
- К заказу покупателя нужны **произвольные характеристики** (ПВХ), например регион, срочность.

## Конфигурация
1. Склад убирается (регистр, обе накладные, код).
2. Документ **«ЗаказКлиента»** (оперативный учёт): табличная часть «СписокНоменклатуры» — **«Номенклатура» и «Количество»** (цену и сумму можно не вводить — на алгоритм не влияют). Проведение разрешено, оперативное тоже.
3. Регистр накопления **«ТоварыКЗакупке»** (остатки): измерения «Номенклатура», «Заказ клиента» (запрет незаполненных значений), ресурс «Количество» (без стоимости). Заказ клиента **приходует**, поступление **расходует**.
4. В регистре «ОстаткиНоменклатуры» **добавить измерение «ЗаказКлиента»** (вместо склада) — себестоимость по средней в разрезе заказа.
5. В приходной накладной: реквизит табличной части **«ЗаказКлиента»** (проверка «Выдавать ошибку») — «для каждой позиции». В расходной накладной: реквизит шапки **«Заказ»** (в условии не сказано, где он должен быть; в шапке проще).
6. Регистры и документ — в командный интерфейс.

## Заказ клиента
Обработка проведения: запрос по табличной части (номенклатура, количество, заказ — ссылка как параметр, период — дата), группировка с отбором по ссылке (конструктор допустим, но строки схлопывают); `Движения.ТоварыКЗакупке.ДобавитьПриход()`; **`Записывать = Истина`**. Если не взвести флаг — движения не запишутся (проверка: «Не задано значение параметра Период» — забыли параметр).

## Приходная накладная (новая методика)
1. Запрос по табличной части: номенклатура, количество, заказ клиента, **стоимость (сумма)**, группировка → `ВТ_Товары`; индексируются **«Номенклатура» и «ЗаказКлиента»** (поля используются в условии второго запроса, т. е. «вложенный» отбор).
2. Расходные движения по «ТоварыКЗакупке»: номенклатура, заказ, количество, период; `Записывать = Истина`; `БлокироватьДляИзменения`; `Записать()`.
3. **Приходные движения по «ОстаткамНоменклатуры»** (с заказом и стоимостью): те же данные уже есть; поэтому набор записей **заполняют сразу из той же выборки**, но **флаг записи не взводят** до контроля: набор запишется в конце процедуры, если контроль пройден. Так не нужен второй запрос. (Зритель предложил `Возврат` при ошибке вместо ветвления — принято: при отказе флаг записи вообще не взводится.)
4. Контроль остатков по «ТоварыКЗакупке»: `Остатки(&Граница, (Номенклатура, ЗаказКлиента) В (...))`; граница «Включая»; только отрицательные остатки; менеджер временных таблиц общий для запросов. Сообщение: «Недостаточно товара %1 по заказу %2 в количестве %3»; `Отказ`.
Проверка: заказ на 10; поступления 5 + 3 проходят, 6 сверх заказа не проходят.

## Расходная накладная (старая методика, средняя в разрезе заказа)
Практически тот же код, что в уроке 4, только вместо склада — заказ из шапки:
- блокировка по полю «ЗаказКлиента» (в документе реквизит «Заказ»);
- в запросе: параметр «заказ» из шапки (в регистре — измерение «ЗаказКлиента»);
- остатки только по заказу из шапки и номенклатуре из табличной части;
- себестоимость по средней (условие последнего списания).
Продать больше, чем закуплено под заказ, нельзя; под заказ, по которому ничего не закупали, продать нельзя.

## Характеристики заказа
Как в уроке 21: ПВХ («ХарактеристикиОбъектов» — переименован из «Свойства объектов»), составной тип значений, справочник **«ЗначенияХарактеристик»** (подчинён ПВХ, длина 100), регистр сведений **«ЗначенияХарактеристикЗаказовКлиентов»**: измерения «ЗаказКлиента» (ведущее, запрет незаполненных, проверка заполнения) и «Характеристика» (ПВХ); ресурс «Значение» (составной тип ПВХ, проверка). Настройки: **связь по типу** («Значение» ← «Характеристика»), **связь параметров выбора** (значение подчинено характеристике), у ресурса и справочника «Создание при вводе — использовать». Примеры: «Регион» — Москва/Питер, «Срочность» — число (15, 30 дней).
