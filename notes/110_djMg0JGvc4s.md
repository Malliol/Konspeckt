# Урок 110. Билет № 11 (Табель, невыход) — повторение и «оборотная» схема (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=djMg0JGvc4s · ~40 мин · [полный текст](../transcripts/110_djMg0JGvc4s.md)

## О чём урок
Билет № 11 по СПР (**табель + невыход**), «по сути повторение» урока 109 с одним отличием: вместо командировки — **невыход** (премия — в следующем уроке); небольшая «новая фишка» — **таблица оборотов регистра накопления** вместо детальной таблицы.

## Условие
- Совместительство допускается; несколько графиков; **документ «Табель»** (как в 108); **оплата по часовому тарифу** (**не «оклад»**: оклад — зарплата за месяц, тарифная ставка — за час; регистр сведений «СведенияОСотрудниках»: «ТарифнаяСтавка»); **невыход на работу без уважительной причины должен быть зафиксирован в базе, но не оплачен**; премия — в следующем уроке.
- Формулировка «зафиксирован в базе» — трактуется по-разному: автор **фиксирует количество дней невыхода** как параметр записи (вид расчёта «Невыход», результат 0; параметр — «ДнейНевыхода»), чтобы можно было вывести в отчёт; «популярное» решение — просто добавляют строку «Невыход» без расчёта (Белоусов — допначисление без периода действия, «пусть делает как хочет»).

## Изменения заготовки (выгрузка 109)
- В табеле вместо буквы «К» — **«Н» (невыход)**; в справочнике «ВидыВремени»: «Явка», **«Невыход»** (элемент «Командировка» удалить); в модуле «Табеля»: `Если Значение = "Н" Тогда ВидВремени = Невыход; Часы = 0; Иначе Попытка Часы = Число(Значение); … Исключение Сообщить("Некорректный ввод данных…"); Отказ = Истина; КонецПопытки`; запрос часов пятидневки (для командировки) — убрать. **Для невыхода в движении «ДанныеТабеля»: `Часов = 0`, + новое поле/ресурс «Дней» = 1** (в регистре накопления добавить ресурс «Дней»: «ради невыхода» — учёт дней; можно писать и для явки 0).
- План «ОсновныеНачисления»: вид расчёта «**Невыход**» (период действия — да; **база не нужна** — убрать зависимость от базы, «Базовый» у измерений и «Базовый период» — временно отключить), «ОплатаПоЧасовомуТарифу». Вытеснения не настраиваются (в табеле «Н» вместо часов).
- Регистр расчёта: реквизиты «ТарифнаяСтавка» (10/2), «ОтработаноЧасов» (5/2), **«ДнейНевыхода»** (5/2).

## Расчёт: схема с оборотами (новая «фишка»)
В 109 «ДанныеТабеля» присоединялись детальной таблицей (интервал дат разный у строк). Здесь — **таблица оборотов** за **весь месяц** (интервал — период регистрации) с **периодичностью «День»**:
1. `ВТ_Начисления` — основная таблица допначислений (`Регистратор = &Ссылка`, `ВидРасчета В (&ВидыРасчета)`, `Активность = ИСТИНА` — в этой задаче Белоусов тоже учитывает активность): `НомерСтроки`, `Сотрудник`, `Подразделение`, `ВидРасчета`, `ПериодДействияНачало`, `ПериодДействияКонец`; индекс по сотруднику.
2. **Явка:** `РегистрНакопления.ДанныеТабеля.Обороты(&НачалоПериодаРегистрации, &КонецПериодаРегистрации, День, ВидВремени = &Явка И (Сотрудник, Подразделение) В (ВЫБРАТЬ Сотрудник, Подразделение ИЗ ВТ_Начисления))` — **отбор по сотрудникам/подразделениям из табличной части прямо в параметрах таблицы**; **левое соединение** по сотруднику и подразделению; **условие `ПериодДействияНачало <= Период И ПериодДействияКонец >= Период`**; группировка по номеру строки, `СУММА(ЧасовОборот)` → «ВТ_ДанныеЯвки» (индекс по номеру строки). **Только для видов расчёта явки** (условие `ВидРасчета В (&ВидыРасчетаЯвки)` — «не цеплять лишнее»).
3. **Невыход:** отдельная таблица **`ВТ_ДанныеНевыходов`** — **вторую таблицу оборотов к той же основной нельзя присоединить в одном соединении (данные задублируются)** → отдельная временная таблица (вид времени = «Невыход», `СУММА(ДнейОборот)` → «ДнейНевыхода»; для видов расчёта «Невыход» — `ВидыРасчетаНевыхода`).
4. Соединения: `ВТ_Начисления` ЛЕВОЕ с `ВТ_ДанныеЯвки`, ЛЕВОЕ с `ВТ_ДанныеНевыходов` по номеру строки (в обоих); `СрезПоследних(&ПериодРегистрации, (Сотрудник, Подразделение) В (…))` «СведенияОСотрудниках» → «ТарифнаяСтавка» (`ЕСТЬNULL`); **все `ЕСТЬNULL`**; **связи сразу прописывать** («лайфхак: заводите в документе как минимум двух сотрудников — увидите ошибки соединений»).
5. Параметры: `ВидыРасчета` (оплата + невыход — для которых получаем показатели), `ВидыРасчетаЯвки` ({оплата}), `ВидыРасчетаНевыхода` ({невыход}), `ПериодРегистрации`, `КонецПериодаРегистрации = КонецМесяца(ПериодРегистрации)`, `Ссылка`.

```bsl
Если Движение.ВидРасчета = ОплатаПоЧасовомуТарифу Тогда
    Движение.Результат = Выборка.ОтработаноЧасов * Выборка.ТарифнаяСтавка;
    ЗаполнитьЗначенияСвойств(Движение, Выборка, "ОтработаноЧасов, ТарифнаяСтавка");
ИначеЕсли Движение.ВидРасчета = Невыход Тогда
    Движение.Результат = 0;                       // «демонстративно»
    ЗаполнитьЗначенияСвойств(Движение, Выборка, "ДнейНевыхода");
КонецЕсли;
Движения.ОсновныеНачисления.Записать(, Истина);
```
- Ошибки по ходу: забытый массив видов расчёта невыхода; «поле не обнаружено» из-за не созданного реквизита; **«отработано дней / дней невыхода»** — автор: «в других решениях “дней невыхода” пишут в “ОтработаноДней” (в ЗУП именно так); для экзамена прозрачнее — отдельное поле».
- Отчёт «Анализ начислений»: **невыход в отчёте не выводить** (нулевые начисления обычно не показывают — «ты при анализе с его помощью ничего не увидишь»; если задача модифицируется — пригодится).
- Тест: Бердыев 1 500 ₽/ч × 64,5 = 96 750; Жупиков — 2 000 × 64,5 = 129 000; невыход у Жупикова 5 дней.

## Прочее и замечания
- В **«фактическом периоде действия»** при отсутствии вытеснения смысла нет («для меня тайна»).
- **Индексирование полей при неравенствах** — «не уверен, нужно ли».
- Экзамен проверяют разные люди (не только Белоусов), оценки отличаются: «пытаемся впарить решение экзаменатору».
- Дальше: «премия» — следующим стримом (последний по СПР); затем **управляемые формы**, «для просмотра предыдущие не нужны», независимые блоки.
- Выгрузка «после занятия 110».
