# Урок 15. Дополнительные затраты. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=sP2_Qd6E1oo · 51 мин · [полный текст](../transcripts/015_sP2_Qd6E1oo.md)

## О чём урок
Билет, очень близкий к пройденному (ФИФО/ЛИФО по партиям, учётная политика раз в год, услуги, отчёт по продажам), с новым элементом — **документом «Дополнительные затраты»**, увеличивающим себестоимость продаж. Основа — выгрузка после урока 5 (старая методика, ФИФО/ЛИФО). Номера билетов в разных версиях разные, важна суть задачи.

## Подготовка (повторение)
- Услуги: реквизит «ВидНоменклатуры»; в приходной накладной выбор только товаров (параметры выбора).
- Ещё раз: ФИФО — first in, first out (первым пришёл, первым ушёл), ЛИФО — last in, first out; сортировка партий по моменту времени (по возрастанию/убыванию).
- Наличие отчёта о продажах → нужен **регистр продаж**.
- Регистр накопления «Продажи» (вид «Обороты»): измерение «Номенклатура» (без склада и партии), ресурсы «Количество», «Себестоимость», «Сумма» (сумма продажи). Подсистема «Оперативный учёт», регистратор — расходная накладная, вывести в группу команд.
- Принцип проектирования регистров автор объясняет по ходу решения; рекомендует курс по 1С:Образованию и сам процесс подготовки как способ научиться.

## Доработка расходной накладной
1. Взвести флаг записи для регистра «Продажи». **Блокировки по продажам нет**: остатки не контролируются, регистр — «записная книжка». Очищать движения по нему тоже не требуется.
2. В запросе: остатки считать только по товарам (условие `ВидНоменклатуры = Товар` в параметрах виртуальной таблицы), вытащить поле «ВидНоменклатуры» и «Сумма» (сумма продажи). Услуги нельзя исключать из табличной части: по ним нужны движения регистра продаж.
3. **Итоги:** на уровне итоговых записей — `МАКСИМУМ(Количество)`, `МАКСИМУМ(Сумма)` и `МАКСИМУМ(ВидНоменклатуры)` (максимум допустим и для перечисления: одинаково во всех строках группы).
4. Обход:
   - в итоговой записи (по номенклатуре): **если товар** — контроль остатков и формирование движений регистра остатков (на уровне детальных записей); независимо от вида — движение регистра продаж;
   - движение продаж: `Движения.Продажи.Добавить()` (оборотный регистр без вида движения), период — дата документа, номенклатура, количество, сумма из итоговой записи;
   - **себестоимость продажи** накапливается в переменной `ИтогоСебестоимость`: прибавляется `Движение.Стоимость` (округлённое по точности ресурса, а не вычисленное значение); для услуг она остаётся 0. Затем она записывается в движение продаж.
5. Проверка: себестоимость в продажах совпадает с суммой списанной стоимости в регистре остатков (например, 10 + 10 = 20 — как в Excel); для услуги себестоимость 0.

## Документ «Дополнительные затраты»
Условие: доп. затраты вводятся отдельным документом, в нём указывается расходная накладная, номенклатура и сумма затрат по каждой позиции; себестоимость в отчёте должна отражаться с учётом распределённых затрат **независимо от месяца ввода документа**.

- Реквизит «Накладная» (тип — расходная накладная); табличная часть «СписокНоменклатуры»: «Номенклатура», «Сумма» (запретить пустые значения). Услуги в документе допустимы (например, доставка), поэтому **параметры выбора по виду очищают**.
- Проведение разрешено; движение — по регистру «Продажи» (оборотный): номенклатура, **количество = 0, сумма = 0, себестоимость = сумма затрат**.
- Движения не очищаются и не блокируются (остатки не контролируются); флаг записи нужен.
- **Контроль соответствия:** позиция затрат должна присутствовать в накладной. Проверку делают по **движениям накладной по регистру продаж**, а не по её табличной части (чтобы затраты не относились к непроведённой накладной): временная таблица `ВТ_Товары` (номенклатура, сумма из табличной части доп. затрат, индекс по номенклатуре) и временная таблица `ВТ_ДвиженияНакладной` (номенклатура из движений регистра «Продажи» по `Регистратор = &Накладная`, индекс); левое соединение; поле `ЕстьСоответствие`: `ВЫБОР КОГДА ДвиженияНакладной.Номенклатура ЕСТЬ NULL ТОГДА ЛОЖЬ ИНАЧЕ ИСТИНА КОНЕЦ`.
  Если соответствия нет: сообщение `СтрШаблон("В накладной не найдена номенклатура %1", НоменклатураПредставление)`, `Отказ`, `Продолжить`; при отказе движения не формируются. Не забыть установить параметр `Накладная` запроса.
- **Период движения** берётся из движений накладной (поле периода из соединения), а не из даты документа затрат: так затраты относятся к периоду продажи. Обращение через точку (`Накладная.Дата`) нежелательно: система читает все данные документа, а при запросе в цикле это ещё хуже. Решение: вытащить период в соединении.
- Спорное решение: добавить в регистр продаж **поле «Накладная»** (тип — расходная накладная) и заполнять его в движениях расходной и доп. затрат, если в условии сказано «затраты относятся к расходной накладной». Отчёт это поле не использует; экзаменатор может ожидать, что его не будет. Автор склоняется к тому, чтобы добавить (в сборниках есть задачи, где в отчёте есть накладная).
- Нужно ли контролировать распроведение расходной накладной при существующих затратах — на экзамене не требуется (автор перечислил варианты, но советует «ничего не делать там, где не сказано»).

## Отчёт «Продажи» (по затратам)
Как в уроке 11: запрос к `РегистрНакопления.Продажи.Обороты` (номенклатура, количество, себестоимость, продажа), вычисляемое поле «Прибыль» (`Продажа - Себестоимость`), стандартный период, детальные записи.
- Ресурсы **не добавляются** (итогов нет).
- Условное оформление в детальных записях: влево, 0 знаков; заголовки жирные.
- Ширину колонок можно задать «Минимальная ширина» (в наборе данных, оформление) — на экзамене не требуется.
- **Сортировка:** сначала вид номенклатуры, затем номенклатура.
- Отчёт работает для **любого периода**, а не только того, что указан в образце (квартал, месяц, год).
- Расшифровка отчёта не требуется.

## Прочее
- На экзамене задача оперативного учёта — одна из четырёх и самая простая; идеальную проработку мелочей делать не нужно.
- Следующее занятие (билет № 7 в нумерации автора) — двухвалютный учёт.
