# Урок 48. Продажи по проектам. Дополнительные затраты (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=egNBylhuBd4 · 70 мин · [полный текст](../transcripts/048_egNBylhuBd4.md)

## О чём урок
Бухгалтерская задача (по счёту автора — следующая после № 5/8): **расходная накладная со складом и проектом**, себестоимость — **средняя по номенклатуре по всей компании** (без учёта складов), документ **«Затраты»** на проекты, отчёт «Продажи по проектам» с разбивкой себестоимости и затрат и **группами номенклатуры** (родители). **Приходной накладной в условии нет.** Начальные остатки вводятся документом «Операция» через вспомогательный счёт. База — выгрузка занятия 41.

## Условие
- «Операция» (ручной ввод проводок) — как всегда.
- Расходная накладная: **склад в шапке**, **проект в шапке** (поле обязательно, продажи — в разрезе проектов); проводка **Дт «Покупатели» — Кт «Прибыли и убытки»** (сумма продажи, разрез: номенклатура, проект) и себестоимость **Дт «Прибыли и убытки» — Кт «Товары»**; при проведении — контроль наличия товара **на складе** (на указанном в шапке); себестоимость — **средняя по каждой номенклатурной позиции по всей компании** (склады при расчёте не учитываются).
- Документ **«Затраты»** (табличная часть — проект, сумма) — дополнительные затраты по проектам; считаются затратами **текущего дня** (период движения = дата документа); контроль наличия продаж по проекту **не нужен**. Проводка: **Дт «Прибыли и убытки» (проект) — Кт «Общехозяйственные затраты»**.
- Отчёт «Продажи по проектам»: проект → **группа номенклатуры** → количество, себестоимость, затраты, сумма продажи.

## Начальные остатки без приходной накладной
Если в условии нет приходной накладной, **не создавать её** — вводить остатки **документом «Операция»** и **вспомогательным счётом «00»** («без признаков»): Дт «Товары» (номенклатура, склад, количество, сумма) — Кт «00». Позиция автора: «приходная накладная составляет цепочку документов закупочной деятельности» (довод Прохожего — «в каркасе уже есть») — «бредово»: в требованиях такого нет, экзаменаторы не вправе требовать; на экзамене решают по-разному. Вопрос зрителя Михаила Попова.

## План счетов и настройки
- ПВХ «ВидыСубконто» → составной тип: «Справочник.Склады», «Справочник.Проекты»; предопределённые виды «Склады», «Проекты».
- Счёт «Товары»: субконто «Номенклатура», «Склады» (максимум субконто 2); **суммовой учёт только по номенклатуре, по складам не ведётся** (признак учёта субконто «Суммовой» + снять у «Склады»; **после изменения в пользовательском режиме — удалить и добавить субконто заново**). Иначе списание по средней: 100 шт. × (100 000 основной + 300 000 дополнительный)/200 = 200 000 уйдёт с основного склада, где только 100 000 → минус.
- Счёт «Прибыли и убытки»: субконто «Проекты» (первым — **порядок субконто важен: чаще используемый в отборах ставят ближе**; у «Затрат» номенклатуры нет — поэтому проект первым, номенклатура вторым), «Номенклатура»; «Только обороты»; суммовой учёт — по обоим.
- Счета: «Общехозяйственные затраты», «00» — предопределённые.
- Обновить документ «Операция» (таблицу с формы заново).

## Расходная накладная — запрос и проведение (старая методика)
1. `ВТ_Товары` (номенклатура, количество, сумма; отбор по ссылке; индекс по номенклатуре).
2. **«ОстаткиПоСкладу»**: `Управленческий.Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконтоСклад, Субконто1 В (номенклатура) И Субконто2 = &Склад)` — только количество остатка (**суммы по складам нет** — «в отборе задействовано субконто2»).
3. **«ОстаткиПоКомпании»**: тот же регистр **без Субконто2** (`&ВидыСубконтоНоменклатура`): количество и сумма по компании в целом. Соединения левые; `ЕСТЬNULL` — для остатков.
4. Итоги не нужны (все строки — по товару).
5. **Контроль:** `Количество > КоличествоНаСкладе` → «Недостаточно товара …», `Отказ`.
6. **Блокировка:** счёт «Товары» + **только номенклатура** (источник данных: табличная часть, вид субконто «Номенклатура»). **Склады блокировать нельзя** («лучше вообще ничего не блокировать, чем заблокировать склады»): себестоимость считается по компании.
7. Себестоимость: если `Количество = КоличествоОстатокКомпании` → `СуммаОстатокКомпании`; иначе `СуммаОстатокКомпании / КоличествоОстатокКомпании × Количество`. (В этой задаче погрешность не возникает — условие последнего списания простое.)
8. Проводки: Дт «Прибыли и убытки» (`СубконтоДт[Проекты] = Проект`, `СубконтоДт[Номенклатура]`) — Кт «Товары» (`СубконтоКт[Номенклатура]`, `СубконтоКт[Склады] = Склад`), `КоличествоКт`, `Сумма` = себестоимость; Дт «Покупатели» — Кт «Прибыли и убытки» (проект, номенклатура), `Сумма = Выборка.Сумма`.
9. **Зачем `Движения.Управленческий.Записывать = Истина` с очисткой:** при перепроведении движения документа остаются в базе (свойство «Удалять автоматически» при отмене не очищает при перепроведении); в запросе остатков на момент времени документа его собственные движения не видны, **но если дату документа сдвинули вперёд — они попадут в остатки**. Поэтому сначала очищают движения, затем флаг записи (чтобы запись произошла). Вопрос зрителя Рамзеса.

## Документ «Затраты»
- Табличная часть «СписокЗатрат»: «Проект» (проверка заполнения), «Сумма» (12/2, неотрицательная). Запрос со свёрткой по проекту (`СГРУППИРОВАТЬ ПО Проект`), отбор по ссылке (конструктор не годится — нужна свёртка).
- Движение: `СчетДт = Прибыли и убытки`, `СубконтоДт[Проекты] = Выборка.Проект` (номенклатура остаётся пустой — **поэтому порядок субконто**: проект первым), `СчетКт = Общехозяйственные затраты`, `Сумма`.

## Отчёт «Продажи по проектам»
- Запрос: `Управленческий.Обороты(&Начало, &Конец, , Счет = &ПрибылиИУбытки, &ВидыСубконто, , КорСчет В (&Товары, &Покупатели, &Затраты))` — **корсчета обязательно перечислить** (при появлении нового корсчёта запрос придётся менять осознанно); субконто 1 — проект (`ВЫРАЗИТЬ(… КАК Справочник.Проекты)`), субконто 2 — номенклатура (`ВЫРАЗИТЬ(… КАК Справочник.Номенклатура)`).
- **Разделение по корсчёту:** `Себестоимость = ВЫБОР КОГДА КорСчет = &Товары ТОГДА СуммаОборотДт ИНАЧЕ 0 КОНЕЦ`; `Затраты = ВЫБОР КОГДА КорСчет = &Затраты ТОГДА СуммаОборотДт ИНАЧЕ 0 КОНЕЦ`; `СуммаПродажи = СуммаОборотКт` (по кредиту корреспондирует только «Покупатели»). Поле `КорСчет` потом убрать; `СуммаОборот` (обороты без разделения Дт/Кт) не нужен.
- **Количество:** `КоличествоОборотДт`; общий для себестоимости.
- СКД: параметры «Период» (+ выражения `ДатаНачала/ДатаОкончания`), счета — параметры, **виды субконто — список из двух видов**; «Только корсчета» — в параметрах нет списка значений; структура: группировка **«Проект»** → группировка **«Номенклатура»** с **«Только иерархия»** («только папки»: вывод только групп-родителей, а не самой номенклатуры; строка «пустая номенклатура» исчезает) — получается результат по группам номенклатуры (нужны ресурсы: количество, себестоимость, затраты, сумма продажи).
  - Итоги по вертикали — «Нет»; итог по проекту оставлен (там строка затрат без номенклатуры); **ресурсы — только для группировки «Номенклатура»** (во вкладке «Ресурсы» — «Рассчитывать по…»: убрать группировку «Проект», иначе итог по проекту удвоит); параметры — не выводить.
  - Заголовки/упорядочивание: по проектам, затем по номенклатуре; порядок возрастания.
- Параметры вывода «Расположение полей группировок» — «Отдельно и только в итогах».

## Замечания
- Дата расчёта не нужна: вопросы зрителей про привязку затрат к расходной накладной — в условии нет (затраты привязаны только к проекту и дню).
- Автор итожит: решено 5 из 16 бухгалтерских билетов; в субботу — ещё 1–3 билета.
