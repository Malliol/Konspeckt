# Урок 86. Ручные и автоматические перерасчёты (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=SCDo_wXB3yg · ~55 мин · [полный текст](../transcripts/086_SCDo_wXB3yg.md)

## О чём урок
Последнее условие **билета № 6** («про автомобили»): **«отчёт “Перерасчёт зарплаты”, в котором пользователь должен увидеть записи регистра расчёта, которые требуется пересчитать; в отчёте помимо прочего должна отражаться информация о необходимости перерасчёта надбавки при исправлении суммы оплат пассажиров»**. Автоматические перерасчёты (между регистрами расчёта) + **ручные** (регистр накопления → регистр расчёта).

## Противоречие условий
Раньше в условии: «после расчёта сумма оплат корректировке **не подлежит**» — а здесь «при исправлении суммы оплат… должен возникать перерасчёт». **При противоречии выполняем то, что сложнее (делать, а не «не делать»)** → ручной перерасчёт надбавки.

## 1. Автоматические перерасчёты (повтор урока 81)
Для регистра «ОсновныеНачисления» (там живёт «Отпуск»; база = все начисления за 3 месяца):
- В плане «ОсновныеНачисления» у вида «Отпуск» на закладке **«Ведущие»** отметить виды, при изменении которых нужен перерасчёт: **«Отпуск», «Надбавка», «ФиксированнаяСумма»** (закладки «Базовые» и «Ведущие» часто, но не обязаны совпадать; без флажков не работает).
- В регистре расчёта «ОсновныеНачисления» → **Перерасчёт «ПоСотруднику»** (имя): измерение «Сотрудник» (**измерения перерасчёта чаще всего совпадают с измерениями регистра**, но не всегда); в «Ведущих регистрах» (и «ОсновныеНачисления», и «ДополнительныеНачисления») отметить поле «Сотрудник» как соответствующее.
- Проверка: перепровели июньский документ → в таблице перерасчёта появилась запись «августовский документ, Отпуск, сотрудник»; перепровели августовский — запись исчезла.

## 2. Ручные перерасчёты (из регистра накопления)
Платформа **не умеет** автоматически создавать записи перерасчёта при изменении **регистра накопления**; надо создавать **вручную** при проведении документа «ОплатаПассажиров».

### Подготовка
- В регистре расчёта **«ДополнительныеНачисления»** создать перерасчёт **«ПоСотруднику»** (с измерением «Сотрудник», ведущие регистры можно не указывать — ведущих видов расчёта нет). Система потребует **«зависимость от базы» у вида расчёта в плане «ДополнительныеНачисления»** — указать **любой** план-заглушку (флажки на закладке «Базовые» не ставить) — иначе конфигурацию не обновить.
- Перерасчёт «ПоСотруднику» для основных начислений нужен для отпуска (п. 1), для допначислений — для надбавки.

### Способ 1 — как в курсах 1С.рф (в `ОбработкаПроведения` документа «ОплатаПассажиров»)
1. **Период регистрации** документов, которые надо пересчитать, = **начало следующего месяца** от даты документа: `НачалоМесяца(ДобавитьМесяц(Дата, 1))` (надбавка считается по оплатам за **прошлый** месяц).
2. Запрос по регистру «ДополнительныеНачисления»: **`Регистратор`** (→ «ОбъектПерерасчёта»), «Сотрудник», «ВидРасчёта», где `Сотрудник = &Сотрудник`, `ПериодРегистрации = &ПериодРегистрации`, `ВидРасчета = &Надбавка`.
3. В цикле по выборке: `НаборЗаписей = РегистрыРасчета.ДополнительныеНачисления.Перерасчеты.ПоСотруднику.СоздатьНаборЗаписей(); НаборЗаписей.Отбор.ОбъектПерерасчета.Установить(Выборка.ОбъектПерерасчета); НаборЗаписей.Прочитать();` (**читать набор обязательно**: иначе `Записать()` сначала удалит всё по отбору — перерасчёты по другим сотрудникам этого документа пропадают); `Запись = НаборЗаписей.Добавить(); ЗаполнитьЗначенияСвойств(Запись, Выборка); НаборЗаписей.Записать();`
   - **Дубли** (`Бердыев` дважды) — ошибка «запись с такими ключами существует»: в курсах 1С.рф набор выгружают в таблицу значений, **сворачивают по всем колонкам** и загружают обратно (автор: «белоусов не любит таблицы значений, создаваемые без необходимости»).

### Способ 2 — «белоусовский», без таблицы значений (рекомендуется автором)
- Вместо `Прочитать()` — **`НаборЗаписей.Записать(Ложь)`**: параметр **«Замещать»** = Ложь — записи **добавляются**, а не замещают (по умолчанию «Истина» — всё удаляется по отбору и пишется заново).
- Дубли отсекают **левым соединением**: во временной таблице — нужные «параметры перерасчёта» (сотрудник, период регистрации, вид расчёта); из регистра расчёта берём записи (внутреннее соединение с параметрами); затем **левое соединение с таблицей перерасчёта** по трём полям (**объект перерасчёта, вид расчёта, сотрудник**) с условием **`Перерасчёты.ОбъектПерерасчёта ЕСТЬ NULL`** — создаём только те записи, которых ещё нет. **Флажок «Без повторяющихся» (`РАЗЛИЧНЫЕ`)** — если в документе начисления несколько строк надбавки на одного сотрудника.
- Индексы по полям соединения во временных таблицах; **активность** записей регистра расчёта в модуле набора записей — не проверять (автор: «надуманно», у Белоусова может быть).
- Пользователь «дурак» (несколько надбавок в одном документе) — не запрещаем, но чтобы ошибок не было: `РАЗЛИЧНЫЕ`.

### Способ 3 — модуль набора записей регистра накопления (метод Белоусова «в чистом виде»)
- Тот же код — в обработчике **`ПриЗаписи`** модуля **набора записей регистра накопления «ОплатыПассажиров»**; документ-регистратор берётся как **`Отбор.Регистратор.Значение`** («этот объект → Отбор → Регистратор → Значение»; **«ЭтотОбъект»** — набор записей).
- Запрос: из набора записей (регистр накопления «ОплатыПассажиров» — записи по отбору регистратора) → «Сотрудник», **период регистрации** = `НачалоПериода(ДобавитьМесяц(Период, 1), "Месяц")` (в запросе: `ДОБАВИТЬКДАТЕ(КОНЕЦПЕРИОДА(Период, МЕСЯЦ), СЕКУНДА, 1)` — «начало следующего месяца»), вид расчёта — `&Надбавка`; во вторую очередь соединение с «ДополнительныеНачисления» (внутреннее), затем левое соединение с перерасчётами — как в способе 2; далее: `НаборЗаписей = …СоздатьНаборЗаписей(); Отбор.ОбъектПерерасчёта.Установить(Выборка.ОбъектПерерасчёта); Запись = НаборЗаписей.Добавить(); ЗаполнитьЗначенияСвойств(Запись, Выборка); НаборЗаписей.Записать(Ложь)`.
- Преимущество: перерасчёт создаётся при **любой записи** набора (в том числе из другого документа или программно) — «как делает платформа для регистров расчёта».

**Что выбрать:** автор считает, что на экзамене безопаснее **способ Белоусова (3)**, но «способ 2 — идеально работающий и более наглядный».

## Отчёт «Перерасчёт зарплаты»
СКД-запрос: объединение таблиц перерасчёта **основных** и **дополнительных** начислений (объект перерасчёта, сотрудник, вид расчёта) — через **«ОБЪЕДИНИТЬ ВСЕ»**; колонки в образце не указаны — как есть; помощником создания списка не пользоваться («классная штука», но не нужна). Подсистема «Расчёты».
