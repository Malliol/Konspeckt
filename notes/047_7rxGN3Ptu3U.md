# Урок 47. Себестоимость без учёта инвентарных номеров (БУ). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=7rxGN3Ptu3U · 45 мин · [полный текст](../transcripts/047_7rxGN3Ptu3U.md)

## О чём урок
Билет № 5 (по нумерации автора) — вариант предыдущего (урок 46): те же инвентарные номера, но **себестоимость — средняя по номенклатурной позиции по всем инвентарным номерам**. Отчёт по продажам проще (сотрудников нет). База — выгрузка занятия 46.

## Эксперимент: без количественного учёта
Автор пробовал убрать количество (план счетов, приход, расход) и нигде не считать условие последнего списания: приход «4 кинокамеры» одной строкой схлопывается в сумму 40 000; расход «4 кинокамеры» даёт выручку 200 000 за одну камеру — деньги можно «накручивать» разбиением строк. Вывод: **без количественного учёта нельзя** — оставляем количество (см. урок 46).

## Условие
Как билет № 8, но:
- в документе поступления каждая единица — отдельная строка (количество = 1), каждой позиции присваивается уникальный инвентарный номер;
- расходная накладная: контроль наличия товара **по инвентарному номеру**; **себестоимость — средняя по номенклатурной позиции по всем её инвентарным номерам** (инвентарные номера при расчёте не учитываются);
- проводки как раньше; отчёт по продажам (номенклатура, инвентарный номер, себестоимость, сумма продажи) — без сотрудников.

## Изменение плана счетов
Пример: кинокамера №001 за 10 000 и №002 за 30 000 (итого 40 000 / 2 шт.). Списание «по средней» = 20 000 за каждую; если оставить суммовой учёт по инвентарным номерам — на номере 001 получится «минус».
1. В плане счетов создать **признак учёта субконто «Суммовой»** и связать с ресурсом «Сумма» регистра бухгалтерии (то же, что в уроке 45).
2. В настройке счёта «Товары»: у субконто **«Номенклатура» — суммовой учёт да; у «Инвентарные номера» — нет**. Количественный учёт — по обоим.
3. Для «Прибыли и убытки» суммовой учёт нужен по обоим субконто (отчёт по продажам); только обороты.
4. **Подводный камень (подтверждение):** после создания признака в пользовательском режиме флажки **не видны и не действуют** (суммовой учёт «выключается» полностью). Решение: **удалить субконто счёта и добавить заново**, затем поставить флажки. «Если вы знаете, как снять блокировку с этих флагов, скажите» — автор не знает.
5. Лишнее убрать: вид субконто «ФизическиеЛица», регистр свойств, настройки характеристик справочника физлиц; максимальное количество субконто = 2.

## Запрос расходной накладной (старая методика)
1. `ВТ_Товары` (номенклатура, инвентарный номер, количество, сумма) по ссылке; индексы по номенклатуре и инвентарному номеру.
2. **Таблица 1 — «ОстаткиПоИнвентарнымНомерам»**: `Управленческий.Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконтоИнвентарные, (номенклатура, инвентарный номер) В …)` — **есть только количество** (суммы по инвентарному номеру не ведутся: **если использовать `Субконто2` — суммы пропадают**).
3. **Таблица 2 — «ОстаткиПоТоварам»**: `Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконтоНоменклатура, Субконто1 В (…))` — **без `Субконто2`**: тут есть и **количество, и сумма остатка по товару в целом** («только коснёшься субконто 2 — суммы пропадают»).
4. Соединение: левое по номенклатуре и инвентарному номеру, **`ЕСТЬNULL` для остатков** (обязательно, иначе платформа выдаёт непонятную ошибку вместо сообщения о нехватке).
5. Итоги по номенклатуре: количество остатка и сумма остатка по товару **выводят на уровень итоговой записи** (`МАКСИМУМ`) — читабельнее («данные по всей номенклатуре, а не по строке»); детальные записи — по инвентарным номерам. Курсы 1С.рф используют итоговые записи, автор делает так же (допускается брать из детальных).
6. Виды субконто: **два отдельных массива/значения** — для таблицы остатков по инвентарным номерам, для таблицы по товарам — просто вид «Номенклатура» (если вид один, массив не нужен: можно передать сам вид). Не передавать лишнего.
7. Блокировка: **инвентарные номера блокировать нельзя** (суммы и количество считаются по всему товару — блокируется товар целиком); только вид субконто «Номенклатура» по списку номенклатуры + счёт «Товары».

## Алгоритм
- Цикл по итоговым записям (номенклатура), внутри — по детальным (инвентарные номера): `Выборка = ВыборкаНоменклатура.Выбрать()` (вложенный обход по группировке).
- **Контроль остатков:** `Выборка.Количество > Выборка.КоличествоОстатокИнвентарногоНомера` → «Недостаточно товара …», `Отказ`.
- **Себестоимость единицы** = `ВыборкаНоменклатура.СуммаОстатокТовара / ВыборкаНоменклатура.КоличествоОстатокТовара`; себестоимость = единица × `Выборка.Количество`.
- Примечание: на тесте получилось, что вторая кинокамера списывается по 20 000, портсигар по 40 000 (средняя), потом при добавлении третьей камеры (30 000) средняя стала 70 000 / 3.

## Копеечная погрешность (условие последнего списания по товару)
Пример: себестоимость 100 на 3 штуки → 33,33 + 33,33 + 33,33 теряет копейку. Как и в уроке 45, но **без ФИФО**:
- Переменная **«СебестоимостьИтого»** (накопление `Движение.Сумма` — **округлённая сумма**, записанная в ресурс), переменная **«КоличествоСписано»** (накапливается `Выборка.Количество` по номенклатуре, сбрасывается при смене номенклатуры).
- Если `КоличествоСписано = КоличествоОстатокТовара` (по номенклатуре списывается весь остаток — в этой итерации списывается последняя единица) → **`Себестоимость = СуммаОстатокТовара − СебестоимостьИтого`**; иначе — по формуле средней.
- Проверка: две продажи по 33 и 34 копейки: вторая, последняя, получает недостающую копейку.
- Автор: «впервые встретилось такое последнее списание» (накопление количества и сравнение с остатком); вариант с `запрос.Количество()` — неверный: он считает **строки**, а не количество единиц.

## Отчёт
- Из отчёта прошлого занятия убрать физические лица и «образование»; параметры: счета (покупатели, прибыли и убытки, товары), период, виды субконто (номенклатура, инвентарный номер); корреспонденция счетов обязательна; `ВЫРАЗИТЬ` субконто. Название «Продажи». Упорядочивание — по инвентарному номеру, затем по товару (инфо автора: «возможно, закономерность экзаменатора не такая»).
