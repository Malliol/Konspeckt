# Урок 18. Индексирование таблиц. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=sX9uc5zAJZA · 34 мин · [полный текст](../transcripts/018_sX9uc5zAJZA.md)

## О чём урок
Теоретическое занятие без экзаменационной задачи: что такое индексы в 1С, какие создаются автоматически, когда нужно индексировать **временные таблицы** и как это связано с требованиями экзамена. Разбор ошибок урока 17.

## Требование экзамена
В задачах получения данных из информационной базы **установка отборов по неиндексированным полям** — снижение на 0,5 балла. Других требований про индексы нет, поэтому нужно понимать механику.

## Автоматические индексы
- **Составной индекс** используется, только если условие покрывает его **левую часть без пропусков**: индекс «Код + Ссылка» работает при отборе по коду, но не по одной ссылке; индекс «Подразделение + Сотрудник» при отборе только по сотруднику не используется.
- Справочник: по ссылке; по коду (если длина кода не 0, составной «код + ссылка»); по наименованию («наименование + ссылка»).
- Документ: по ссылке, по номеру, по дате.
- Регистры сведений: для **непериодического** — составной индекс по измерениям («измерение 1 + измерение 2 + …»); для **периодического** — «период + измерения» и обратный «измерения + период».
- Регистр накопления: индекс по **самой таблице движений** по комбинации измерений не создаётся (только по периоду, регистратору, номеру строки). Зато у **виртуальных таблиц остатков и оборотов** есть индексы «период + измерения», поэтому отбор по номенклатуре и складу в параметрах виртуальных таблиц выполняется быстро (в запросах к самой таблице движений поля не индексируются — поэтому нет смысла вручную индексировать измерения).
- Ресурсы индексов **не получают**.
- Статья про индексы таблиц базы данных (ИТС, открытый доступ) перечисляет, какие индексы в каких случаях создаются; общие реквизиты ([х]) можно игнорировать.

## Свойство «Индексировать»
- Для реквизитов справочников и т. д.: «Индексировать» создаёт индекс «поле + ссылка» (составной, но этого достаточно). «Индексировать с дополнительным упорядочиванием» нужно для динамических списков (отбор/упорядочивание), для запросов — достаточно обычного индекса.
- Флажок **«Ведущее»** у измерения регистра сведений индексирует поле (поэтому свойство «Индексировать» становится недоступным).
- У нескольких индексируемых полей создаётся **один составной индекс**, а не по отдельному на каждое (отбор только по второму полю его не использует).

## Временные таблицы
Автоматически индексы в них не создаются — это ответственность разработчика (закладка «Индексы» в конструкторе или `ИНДЕКСИРОВАТЬ ПО`). Источники правил:
- **Е. Хрусталёва, «Язык запросов 1С:Предприятия»** — поля индексируют в условиях: в предложении ГДЕ (отбор), в условиях соединения, в параметрах виртуальных таблиц, в предложении ИМЕЮЩИЕ.
- **Система стандартов и методик разработки (ИТС), статья об использовании временных таблиц** (раздел 3.1): индексы стоит строить, если **большая** временная таблица участвует в соединении (поля, участвующие в условиях соединения), и если обращение к временной таблице выполняется в подзапросе оператором `В`. Маленькие таблицы (до ~1000 записей) индексировать не нужно. Если условий несколько, а часто проверяется одно, индекс строят по часто проверяемому.

**Принятая автором политика для экзамена:**
- Требование «отбор по неиндексированным полям» относится к **обычным таблицам информационной базы**, а не к временным (временные таблицы находятся в памяти/на диске, а не в базе).
- Индексировать поля временной таблицы: **в условиях соединения** и **когда таблица используется во вложенном запросе (оператор `В`)**.
- **Не индексировать «ради отбора»** (автор не нашёл ни одного такого случая в типовых конфигурациях — УТ, УНФ).
- Размер таблицы игнорируют (табличные части документов всегда маленькие), иначе бы нигде не нужно было индексировать; на экзамене демонстрируют знание механизма. Белоусов в одном из занятий сказал, что индексы по номенклатуре — «для продвинутых», новичкам знать не обязательно (карт-бланш), но автор всё же индексирует.

## Разбор ошибок урока 17 (стеллажи)
1. Соединение временной таблицы `ВТ_Товары` с регистром «СоставСтеллажей» по полю «Стеллаж»: поле «Стеллаж» — **ресурс**, индекса не имеет. Нужно его индексировать (свойство регистра), иначе это ошибка.
2. Во вложенном запросе используется поле «Номенклатура» таблицы `ВТ_Комплектующие` — его нужно было проиндексировать, а индекса не было.

## Вопрос про индексирование «ВидНоменклатуры» (урок 10)
Зрители спрашивали, не нужно ли индексировать поле «ВидНоменклатуры» в запросе остатков (отбор по виду). Автор приводит три причины **не** делать этого:
1. Индекс составной (например, «Номенклатура + Партия + Вид»): если отбор только по виду, левая часть индекса не покрыта, и он не используется.
2. Индексировать «ради отбора» не требуется (см. политику выше).
3. «ВидНоменклатуры» — **низкоселективное поле** (мало разных значений — товар/услуга, как булево): по таким полям индексы создавать не следует. Индекс строится по полям, участвующим в соединении (номенклатура, партия).

## Ответы на реплики из чата
- Практика — критерий истины: эффективность индекса проверяют замерами с индексом и без.
- Для маленьких таблиц индекс, вероятно, только вреден (его создание и использование стоит времени), но на экзамене нужно показать знание механизма.
- Следующее занятие в тот же день — задача, где много временных таблиц, чтобы применить теорию на практике.
