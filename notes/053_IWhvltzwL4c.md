## Условие (билет № 4)
- Учёт товаров в разрезе **организации, места хранения (склад), партии** (плюс номенклатура); **баланс формируется отдельно для каждой организации**.
- **Склады общие** (без привязки к организации; «как в типовых»); **товар принадлежит одной организации**.
- Приход — обычная приходная накладная (с организацией).
- Документ **«КуплеПродажа»** — перемещение между **собственными организациями** с возможным изменением склада (склад может не меняться): в шапке — организация-**поставщик**, организация-**покупатель**, склад поставщика, склад покупателя; табличная часть (товар, количество, цена, сумма).
- Проводки: **организация-поставщик:** Дт «Прибыли и убытки» — Кт «Товары» (себестоимость), Дт «Покупатели» — Кт «Прибыли и убытки» (продажа); **организация-покупатель:** Дт «Товары» — Кт «Поставщики» (закупка).
- Себестоимость — по ФИФО в разрезе организации, партии и склада по каждой позиции; контроль остатков.
- Отчёт: продажи между организациями (таблица «получатель × отправитель»).

## Организация — **измерение регистра бухгалтерии**
- «Организация» — не субконто (нельзя больше 3 субконто, четвёртое — «не в том направлении»), а **измерение регистра бухгалтерии** «Организация» (справочник «Организации»): **«Балансовый» — да** (указывается и по дебету, и по кредиту: у каждой проводки каждая сторона по организации), **«Запрет незаполненных значений» — да**; признак учёта — не нужен (организация во всех счетах).
- Добавить справочник «Организации» в подсистему бухгалтерского учёта.
- Каждая проводка обязана указывать организацию: `Движение.Организация = …`.

## Субконто
- ПВХ «ВидыСубконто» → составной тип: «Склады», «Партии» (документы «ПриходнаяНакладная» и **«КуплеПродажа»** — партия новой организации = документ купли-продажи); предопределённые виды «Склады», «Партии».
- Счёт «Товары»: номенклатура, склады, партии (3 субконто, количественный учёт). **В предопределённых данных вида «Партии» нужно добавить в тип «КуплеПродажа»** (иначе подставится пустая ссылка).
- Порядок субконто: чем чаще отбор — тем ближе к счёту; ответ зрителю Виктору Зуеву (индексы и порядок измерений — в уроке 40 порядок условий в отборе не влияет, порядок субконто влияет на индекс).

## Документы
- **Приходная накладная:** реквизиты «Организация», «Склад» (обязательные; на форме); запрос с свёрткой; проводка: Дт «Товары» (`СубконтоДт`: номенклатура, склад, партия = `Ссылка`) — Кт «Поставщики»; `Движение.Организация`, `КоличествоДт`, `Сумма`.
- **КуплеПродажа:** реквизиты «ОрганизацияПоставщик», «ОрганизацияПокупатель», «СкладПоставщика», «СкладПокупателя» (все обязательны), табличная часть «СписокНоменклатуры» (номенклатура, количество, цена, сумма) с пересчётом (события изменения количества/цены; итог «СуммаПоДокументу» — `Объект.СписокНоменклатуры.Итог("Сумма")` в подвале; сумму по документу сохраняют в переменной в `ПередЗаписью`). Пересчёт цены/суммы автор считает обязательным («надо — я быстро расставляю»).

## Проведение «КуплиПродажи» (старая методика)
1. `ВТ_Товары` (номенклатура, количество, сумма; свёртка; отбор по ссылке; индекс по номенклатуре).
2. Остатки: `Управленческий.Остатки(&МоментВремени, Счет = &Товары, &ВидыСубконто (номенклатура, склады, партии), Субконто1 В (номенклатура) И Субконто2 = &СкладПоставщика, , Организация = &ОрганизацияПоставщик)` (отбор по организации — условие измерения регистра), `ЕСТЬNULL`; порядок — по моменту времени партии (`ВЫРАЗИТЬ(Субконто3 КАК Документ.ПриходнаяНакладная).МоментВремени` — здесь **`ВЫРАЗИТЬ` нужен**, обращение через точку; **партией может быть и «КуплеПродажа»** — в ФИФО-порядок включить оба типа; в уроке выражается только приходная накладная — условие билета «партии» — приходные).
3. Итоги по номенклатуре (количество, сумма документа — `МАКСИМУМ`; остатки — `СУММА`).
4. Блокировка: регистр бухгалтерии, исключительный; счёт «Товары»; склад **поставщика**; номенклатура (из списка); **организация блокируется как измерение** (по организации поставщика) — «блокируем то, по чему отбор» (замечание зрителя «шамиль»).
5. Контроль: `Количество > КоличествоОстаток` → «Недостаточно товара …», `Отказ`, `Продолжить`.
6. ФИФО-цикл: `КоличествоСписать` — **по номенклатуре**; в цикле `Количество = Мин(КоличествоСписать, КоличествоОстаток)`, себестоимость (если количество = остатку партии → `СуммаОстаток`, иначе пропорционально), `КоличествоСписать -= Количество` (ошибка в уроке: не уменьшили; ещё `Мин`/`Макс` перепутаны).
7. Проводки **организации-поставщика:**
   - списание себестоимости (в цикле по партиям): Дт «Прибыли и убытки» — Кт «Товары» (`СубконтоКт`: номенклатура, склад поставщика, партия); `Организация = ОрганизацияПоставщик`, `КоличествоКт`, `Сумма` = себестоимость;
   - продажа (вне цикла, одна проводка на документ): Дт «Покупатели» — Кт «Прибыли и убытки», `Сумма = СуммаПоДокументу`, `Организация = ОрганизацияПоставщик`.
8. Проводка **организации-покупателя** — **по итоговым записям** (в цикле по номенклатуре, не по партиям): Дт «Товары» (`СубконтоДт`: номенклатура, склад покупателя, **партия = документ «КуплеПродажа» (Ссылка)**) — Кт «Поставщики», `Организация = ОрганизацияПокупатель`, `КоличествоДт = Выборка.Количество`, `Сумма = Выборка.Сумма`.
- **Итоги в запросе нужны:** «по номенклатуре» — чтобы закупку отразить на уровне товара, а не партий (у покупателя нет понятия «партии продавца»); автор подробно не объясняет — «первый раз показывал на консоли в занятиях про ФИФО» (ответ Белоусову: итоги нужны, когда по одному товару несколько строк/партий и нужно сгруппировать).
- Ошибка: «недопустимое значение параметра, колонка не принадлежит коллекции» — отсутствие поля в запросе.

## Отчёт «Продажи между организациями»
- Добавить на счёт **«Покупатели»** вид субконто **«Покупатели»** (составной тип: организации — позже и контрагенты; **остатки нужны**: долг покупателя) — к проводке продажи: `СубконтоДт[Покупатели] = ОрганизацияПокупатель` (не на «Прибыли и убытки» и не на «Поставщиков» — при покупке несколько строк и в приходной нет поставщика).
- Запрос: `Управленческий.Обороты(&Начало, &Конец, , Счет = &Покупатели, &ВидыСубконто, , КорСчет = &ПрибылиИУбытки …)` — `Организация` (поставщик/отправитель), `Субконто1` (организация-получатель), `СуммаОборотДт` (сумма). Если затрудняетесь с Дт/Кт — вытащите оба и выберите.
- **«Каждый с каждым»:** чтобы в таблице были и пустые пары, соединить **декартово произведение** справочника «Организации» с самим собой (получатель × отправитель) с обороты — **левое соединение с `ЕСТЬNULL(Сумма, 0)`**; индексы по получателю и отправителю; выражать не нужно (организации — ссылочный тип).
- СКД: параметры «Период» (+ выражения), «ВидыСубконто» (список из одного вида), счета; **таблица**: строки — получатель, колонки — отправитель, ресурс — сумма; итоги по горизонтали/вертикали — «Нет»; параметры вывода — «не выводить»; условное оформление: стиль границы «сплошная», цвет чёрный (совет зрителя Кирилла); **«X»** на пересечении «отправитель = получатель» — оформление «текст» с условием `Отправитель = Получатель` (область — только группировка, а не заголовки); выравнивание влево, отступ; заголовок колонки — **макет группировки** (не заголовка группировки): ячейка с параметром «Отправитель».
- Тест: три организации, перепродажи 1→2, 2→3, 3→1 и т. д.
