# Урок 91. Перерасчёт зарплаты: четыре способа (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=9IdtZy3hXQg · ~1 ч 30 мин · [полный текст](../transcripts/091_9IdtZy3hXQg.md)

## О чём урок
«Самое сложное, что было за год». Билет № 16, последнее условие: **отчёт «Перерасчёт зарплаты», в котором пользователь должен иметь возможность увидеть записи регистра расчёта, которые, возможно, требуется пересчитать**, **и пересчитать их** (кнопка в отчёте). Четыре способа реализации — от «в лоб» до «белоусовского» (метод Прохорова/Белоусова).

## Исправление ошибки урока 90
В запросе расчёта компенсации в урока 90 **не было отбора по регистратору для основной (детальной) таблицы** `ДополнительныеНачисления` (только для «Базы») — нужно `Регистратор = &Ссылка`.

## 1. Автоматическая настройка перерасчёта (повтор)
- В регистре «**ДополнительныеНачисления**» — **перерасчёт «ПоСотруднику…»** (имя произвольное): измерения «Сотрудник» (регистр расчёта ↔ измерение «Сотрудник»; **«ведущий регистр» — «ОсновныеНачисления»**, поле «Сотрудник»), «Подразделение» (аналогично).
- В плане видов расчёта «ДополнительныеНачисления», у вида «**КомпенсацияЗаМобильный**»: закладка «Ведущие» → ведущий вид — «**Оклад**» (часто совпадает с базовым, но не обязан).
- Таблица перерасчёта создаётся автоматически при перепроведении документа с окладом: объект перерасчёта (документ), вид расчёта, сотрудник, подразделение.

## Отчёт «Перерасчёт зарплаты»
СКД, набор данных-запрос по таблице перерасчёта: «объект перерасчёта», «вид расчёта», «сотрудник», «подразделение» — без группировок и сложностей («за три секунды нарисовали»). **Форма отчёта:** добавить кнопку **«Пересчитать»** (команда формы, обработчик: клиент → сервер → `Скомпоновать результат`), после выполнения — формирует отчёт заново (таблица перерасчёта пустеет — **записи удаляются сами при пересчёте**; ручная очистка «не нужна», автор не понимает, зачем Белоусов её делает).

## Способ 1 — «в лоб» (неправильно, −2 балла)
`Выборка` объектов перерасчёта (**без повторяющихся**): `ДокументОбъект = Выборка.ОбъектПерерасчета.ПолучитьОбъект(); ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение)` — перепроводим документ целиком: выполняются все остальные проверки и расчёты — лишнее, медленно.

## Способ 2 — «курсы 1С.рф» (−1 балл)
1. **Вынести расчёт в общий модуль «ПроведениеРасчётов»** (на сервере; при желании «вызов — сервер»): экспортные процедуры `РассчитатьОсновныеНачисления(НаборЗаписей, Регистратор)` и `РассчитатьДополнительныеНачисления(НаборЗаписей, Регистратор, ПериодРегистрации)` — **код расчёта из обработки проведения** (в нём `Движения.ДополнительныеНачисления` заменить на параметр `НаборЗаписей`, `Ссылка` — на `Регистратор`). Из `ОбработкаПроведения` вызывать эти процедуры (поведение не меняется; разделять на модули можно в любой задаче).
2. Обработчик «Пересчитать»: запрос по таблице перерасчёта (`Объект перерасчёта`, `НАЧАЛОПЕРИОДА(ОбъектПерерасчёта.Дата, МЕСЯЦ)` → «ПериодРегистрации») **без повторяющихся**; цикл по выборке: `НаборЗаписей = РегистрыРасчета.ДополнительныеНачисления.СоздатьНаборЗаписей(); НаборЗаписей.Отбор.Регистратор.Установить(Выборка.ОбъектПерерасчета); НаборЗаписей.Прочитать(); ПроведениеРасчетов.РассчитатьДополнительныеНачисления(НаборЗаписей, Выборка.ОбъектПерерасчета, Выборка.ПериодРегистрации);` — внутри процедуры в конце `НаборЗаписей.Записать()`.
3. **Недостаток:** пересчитывается **весь** документ по всем сотрудникам (в компании 5 000 человек — пересчитывать 5 000 строк из-за одного сотрудника).

## Способ 3 — по сотруднику и подразделению (оптимизация)
- В запросе по таблице перерасчёта — **итоги по «ОбъектПерерасчёта»** (запрос: `ИТОГИ ПО ОбъектПерерасчёта`), выборка — `РезультатЗапроса.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам)` → цикл по документам; внутри — вложенная выборка `Выборка.Выбрать()` по детальным записям — **формируем таблицу отборов** `ТаблицаОтборов = Новый ТаблицаЗначений;` колонки **«Сотрудник» (`Новый ОписаниеТипов("СправочникСсылка.ФизическиеЛица")`) и «Подразделение»** — **тип колонок задавать обязательно** (используем в запросе; иначе ошибка «тип не может быть выбран в запросе»; в интернете примера нет) — и `ТаблицаОтборов.Очистить()` на каждый документ.
- Передаём таблицу в `РассчитатьДополнительныеНачисления(НаборЗаписей, Регистратор, ПериодРегистрации, ТаблицаОтборов = Неопределено)`: если параметр определён — это **перерасчёт** → в запросе добавляется условие **`ДополнительныеНачисления.Сотрудник = ... И Подразделение` из таблицы отборов** (передавать `Запрос.УстановитьПараметр("ТаблицаОтборов", ТаблицаОтборов)`; условие `(ДополнительныеНачисления.Сотрудник, ДополнительныеНачисления.Подразделение) В (ВЫБРАТЬ Сотрудник, Подразделение ИЗ &ТаблицаОтборов)` — **имена полей с именем таблицы** («неоднозначные поля» после соединения с «Базой»); **условие нужно в двух местах — в основной таблице и в `База(…)`** (используется замена части текста запроса: «ДополнительноеУсловие»).
- Если параметр не определён — расчёт целиком (из проведения), условие убирается: в запросе подставляется пустая строка.
- Цикл расчёта: для перерасчёта строки движения, не попавшие в отбор, пропускаем (поиск в таблице отборов: `ТаблицаОтборов.НайтиСтроки(Новый Структура("Сотрудник, Подразделение", Движение.Сотрудник, Движение.Подразделение))`; `Если Найденные.Количество() = 0 Тогда Продолжить;`) — иначе их результаты были бы пересчитаны без базы (стали бы нулевыми).
- Выигрыш: пересчитываются только нужные сотрудники.

## Способ 4 — «белоусовский»
Максимально близкий к тому, что показывает Белоусов: **таблица видов расчёта** — для каждого объекта перерасчёта строится таблица значений **(ВидРасчёта → ТаблицаОтборов)**, т.е. **пересчитываем только тот вид расчёта, который указан в перерасчёте**, по нужным сотрудникам.
- Запрос: **итоги по «ОбъектПерерасчёта», затем «ВидРасчёта»**; обход — **вложенный `ПоГруппировкам`**: `ВыборкаПоОбъектам = …Выбрать(ПоГруппировкам); Пока ВыборкаПоОбъектам.Следующий() Цикл ВыборкаПоВидам = ВыборкаПоОбъектам.Выбрать(ПоГруппировкам); Пока ВыборкаПоВидам.Следующий() Цикл ТаблицаОтборов.Очистить(); ВыборкаДетали = ВыборкаПоВидам.Выбрать(); Пока ВыборкаДетали.Следующий() Цикл НоваяСтрока = ТаблицаОтборов.Добавить(); ЗаполнитьЗначенияСвойств(...); КонецЦикла; НоваяСтрокаВидов = ТаблицаВидовРасчета.Добавить(); НоваяСтрокаВидов.ВидРасчета = ВыборкаПоВидам.ВидРасчета; НоваяСтрокаВидов.ТаблицаОтборов = ТаблицаОтборов.Скопировать();` (**копировать таблицу** — иначе все строки ссылаются на одну).
  - ВАЖНО: вложенный `Выбрать(…ПоГруппировкам)` нужен и для второго уровня (в видео автор забыл — «не туда воткнул обход результата запроса»; из-за этого получились дубли).
- Вызов метода `РассчитатьДополнительныеНачисления(НаборЗаписей, Регистратор, ПериодРегистрации, ТаблицаВидовРасчета)`; из проведения передаётся таблица видов расчёта, **выгруженная из движений** (`ТаблицаВидовРасчета = Движения.ДополнительныеНачисления.Выгрузить(, "ВидРасчета"); ТаблицаВидовРасчета.Свернуть("ВидРасчета")`; тип параметра — **таблица значений**).
- В методе: **проверка «перерасчёт ли»**: `ТаблицаВидовРасчета.Колонки.Найти("ТаблицаОтборов") <> Неопределено` (колонка есть только у перерасчёта); `Для Каждого СтрокаВидов Из ТаблицаВидовРасчета Цикл`; `Если ВидыРасчета.Найти(СтрокаВидов.ВидРасчета) = Неопределено Тогда Продолжить;` (виды, для которых есть алгоритм — «компенсация за мобильный» и т.п.), `ТаблицаОтборов = СтрокаВидов.ТаблицаОтборов;` — запрос и цикл **выполняются внутри цикла по видам**; в цикле по движениям при перерасчёте — `Если Движение.ВидРасчета <> СтрокаВидов.ВидРасчета Тогда Продолжить;`.
- Для демонстрации автор добавил **вид «КомпенсацияЗаСтационарный»** (его пересчитывать не надо — в плане может быть много видов, пересчёт идёт только для нужного). На экзамене ничего подобного не требуется: «вид один — зачем усложнять»; сам автор на экзамене сделал способ 3 (получил «4», но придирались не к перерасчёту).
- В «белоусовском» варианте Белоусов перед пересчётом **вручную очищает** записи/перерасчёты — автор считает это лишним.
- **Запросы в цикле** — по видам расчёта итераций мало, альтернативы нет, на экзамене «простят» (аналогично урокам про способы расчёта/приоритеты); «разбиение на части, а не запрос в цикле» (зритель Юрий Зайцев).
