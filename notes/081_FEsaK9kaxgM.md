# Урок 81. Перерасчёты (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=FEsaK9kaxgM · ~15 мин · [полный текст](../transcripts/081_FEsaK9kaxgM.md)

## О чём урок
Последняя формулировка **билета № 4**: **отчёт «Перерасчёт зарплаты», в котором пользователь должен увидеть записи регистра расчёта, которые требуется пересчитать.** Тема «перерасчёты» — самый простой из трёх типов задач.

## Три типа задач на перерасчёт
1. **Только настроить** перерасчёт (этот урок; чаще всего).
2. Настроить и **самостоятельно рассчитать** записи перерасчёта.
3. Настроить, рассчитать и реализовать перерасчёт самих перерасчётов (редко, сложно).

## Что такое перерасчёт
Механизм «уведомления»: система создаёт таблицу (отдельный объект «Перерасчёт» регистра расчёта) с полями **«Объект перерасчёта» (регистратор — «НачислениеЗарплаты»)**, **«Вид расчёта»** и **измерения регистра**. Записи в ней = «какие начисления, вероятно, посчитаны неправильно, потому что изменились данные, от которых они зависят (входили в базу)».
- Создавать перерасчёт нужно только в тех регистрах расчёта, где есть зависимость: у **оплаты по часовому тарифу** зависимости нет (результат от среза ставки — на экзамене не требуется), а **премия руководителю зависит от оплаты** → перерасчёт создаётся у регистра **«ДополнительныеНачисления»** (имя — «ПремияРуководителю…» не нужно, обычно «Перерасчёты»).

## Настройка (перерасчёт у регистра «ДополнительныеНачисления»)
1. Добавить регистр расчёта → **перерасчёт** (в дереве «Регистры расчёта → ДополнительныеНачисления → Перерасчёты»).
2. **Измерения перерасчёта = все измерения регистра**: «Сотрудник» и «Подразделение» (так как база определяется по обоим). Для каждого измерения указать **«Регистр расчёта»** (откуда берутся данные для перерасчёта — основные начисления; поле сотрудник ↔ сотрудник) и **«Ведущее измерение»** (поле «Сотрудник» ведущего регистра «ОсновныеНачисления»): так задаётся соответствие полей двух регистров. Для подразделения — аналогично.
3. В плане видов расчёта «ДополнительныеНачисления», у вида **«ПремияРуководителю»**, закладка **«Ведущие»**: выбрать **ведущий вид расчёта — «ОплатаПоЧасовомуТарифу»**. Смысл: **при изменении (перезаполнении, даже теми же значениями) записей ведущего вида в основном регистре система создаёт запись в таблице перерасчёта по этому виду**. Ведущий вид чаще всего совпадает с базовым, но не обязан (можно было бы сделать «штраф» ведущим для премии).

## Проверка
- Таблицы перерасчётов — отдельные объекты (не в регистрах расчёта). Пока задним числом ничего не перепроводили — пусто.
- Пример: премия за сентябрь считается по базе августа; перепровели документ августа (изменили оплату) → в перерасчёте появилась запись «ПремияРуководителю, Сотрудник, Подразделение, документ сентября»; перепроводим документ-регистратор сентября → запись исчезает (пересчитано); аналогично для премии за август при изменении июльской оплаты.
- При ручном перерасчёте достаточно **перепровести** документ-объект перерасчёта.

## Отчёт «Перерасчёт зарплаты»
Простейший СКД: запрос по таблице перерасчёта (`РегистрРасчета.ДополнительныеНачисления.Перерасчет…` — «Объект перерасчёта», «Вид расчёта», «Сотрудник», «Подразделение», опц. «Регистратор»); без параметров, детальные записи, **без заголовков и особых настроек** (в образце — именно таблица как есть); подсистема «Расчёты». Особенно «колдовать» не нужно.
