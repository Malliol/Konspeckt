# Урок 74. Получение ставки по шкале (СПР). Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=7JQclDNHuYw · 49 мин · [полный текст](../transcripts/074_7JQclDNHuYw.md)

## О чём урок
Работа над ошибками (стаж, пустая строка в отчёте, флажок «Базовый») и начало **билета № 5**: оклад определяется **по шкале в зависимости от отработанных часов** и подразделения. Заготовка — выгрузка после занятия 71 (оклад уже считается).

## Работа над ошибками

### Стаж, если сотрудник принят после начала учёта в базе
Замечание зрителя: при сотруднике, принятом **после** даты начала учёта в базе, стаж считался от даты начала учёта — неверно. Исправление:
- В справочнике/регистре нужны **и константа «ДатаНачалаУчётаВБазе», и «НачальныйСтажДней», и «ДатаПриёма»** (дата приёма — «не выдавать ошибку», может быть пустой).
- Если дата приёма **раньше** начала учёта (`ДатаНачалаУчёта > ДатаПриёма`): стаж = `РАЗНОСТЬДАТ(ДатаНачалаУчёта, ПериодРегистрации, ДЕНЬ) + НачальныйСтажДней`.
- Иначе: стаж = `РАЗНОСТЬДАТ(ДатаПриёма, ПериодРегистрации, ДЕНЬ)`, начальный стаж **не прибавляется**.
- Затем деление на 365.
- **Рефакторинг запроса:** стаж вычисляется в **одном месте** (во временной таблице «ВТ_БазаНачислений»: номер строки, база, стаж), а шкала присоединяется левым соединением к ней: `Стаж >= Шкала.СтажОт И Стаж < ШкалаСледующая.СтажОт`, `ЕСТЬNULL(Процент, 0)`. Не дублировать длинное выражение стажа в трёх местах.
- Проверка: Васина с приёмом 1 июня 2021 → стаж ≈ 0,17 (5 %); при приёме 1 августа — 0 (5 %).

### Пустая строка в отчёте «Анализ премий» — короткий рецепт
Вместо «колдовства» урока 70 (подчинение группировок и т. п.) — три действия:
1. Заголовок — группировка «заголовок» с вариантом использования **«Дополнительная информация»** и **макетом группировки** («Месяц: [ПериодРегистрации]», формат `ММММ гггг "г."`).
2. В ресурсы вынести сумму премии; на закладке «Выбранные поля» — поля отчёта.
3. **Снять флажок «Авто-позиция ресурсов» → «Не использовать»** (в структуре отчёта) — это убирает пустую строку, но пропадает итог → в **детальных записях** поставить **расположение общих итогов по вертикали — «Конец»**.
Бонус: чтобы не рисовать ячейки макета, **не отключать макет оформления**, а у ячейки задать цвет рамки и цвет фона = цвет формы.

### Флажок «Базовый»
Для всех измерений из массива, передаваемого в виртуальную таблицу «База» (сотрудник и подразделение), в регистре расчёта поставить флажок **«Базовый»** — ускоряет получение базы; на экзамене за это могут снижать оценку (автор опять забыл).

## Билет № 5: условие
- Метод отклонений; **совместительство допускается** (измерения сотрудник + подразделение в регистре расчёта, документе, сведениях о сотруднике).
- Каждый сотрудник работает **по собственному графику**; **график закрепляется за парой «сотрудник + подразделение»**.
- Оклад считается **пропорционально времени в часах**; **начальное значение оклада** одинаково для всех сотрудников подразделения и определяется **по шкале в зависимости от фактически отработанных часов**.

## Реализация
1. **График за парой «сотрудник + подразделение»:** в регистре сведений «ГрафикРаботы» вместо измерения «ГрафикРаботы» создать измерения **«Сотрудник»** и **«Подразделение»** (так принято на экзамене; вместо отдельного регистра соответствия «пара → график»). Обработку заполнения графика переписать: параметры «Сотрудник» и «Подразделение» вместо «ГрафикРаботы» (в форме, реквизитах, отборе, записи).
2. **Единицы:** задача только про часы → ресурс «Дней» удалить, оставить **«Часов»** (что не используется — не хранить).
3. **Связь с графиком** в регистре расчёта: **два поля** — «Сотрудник» ↔ измерение «Сотрудник», «Подразделение» ↔ измерение «Подразделение».
4. **Очистка следов предыдущей задачи:** убрать из документа таблицу/условия командировки, запрос базы, **флажок «Базовый период»** в регистре расчёта, **«Зависимость от базы»** в плане видов расчёта, флажки «Базовый» у измерений (базы нет), ресурс «ОтработаноЧасов» → **заменить реквизитом** (ресурс нужен только если по нему считают базу).
5. **Реквизиты регистра расчёта:** «НормоЧасов» (норма — `ЗначениеПериодДействия`), «ОтработаноЧасов» (`ЗначениеФактическийПериодДействия`), «Оклад» (из шкалы). Название «нормо-часы» привычнее для экзаменатора, чем «рабочие часы».
6. **Регистр сведений «ШкалаОкладов»:** непериодический, независимый; **измерения:** «Подразделение», **«ЧасовОт»** (число 5/2), **«ЧасовДо»** (обязательно заполнено — запрет незаполненных; верхняя граница, напр. 999); **ресурс «Оклад»** (10/2). Правило: **измерения — «параметры функции», ресурсы — «результат»**; поэтому «от/до» — измерения. Шкала для отдела внедрения: 0–60 → 2 000, 60–130 → 2 500, 130–999 → 3 000; бухгалтерия: 0–50 → 1 500, 50–150 → 2 000, 150–999 → 3 000. Включить шкалу в подсистему «Расчёты».
7. **Запрос получения оклада:** `РегистрРасчета.ОсновныеНачисления.ДанныеГрафика(Регистратор = &Ссылка)`; `ЕСТЬNULL(ЗначениеПериодДействия, 0)` → НормоЧасов, `ЕСТЬNULL(ЗначениеФактическийПериодДействия, 0)` → ОтработаноЧасов; **левое соединение** со шкалой по подразделению и условию `ОтработаноЧасов >= ЧасовОт И ОтработаноЧасов < ЧасовДо`; `ЕСТЬNULL(Оклад, 0)`. Отладка — в консоли запросов, затем «Конструктор запроса» / вставка в модуль.
8. Тест: Бердыев 176 нормо-часов, 160 отработал → оклад 3 000 (бухгалтерия, интервал 150–999) → результат = 3 000 / 176 × 160. Если считает «не так» — проверить, не осталась ли командировка/возврат в коде.
