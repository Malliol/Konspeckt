# Урок 77. Штраф за опоздание — два решения (СПР). Подготовка к специалисту по платформе 1С
Видео: https://www.youtube.com/watch?v=gh9lUT74czM · ~1 ч · [полный текст](../transcripts/077_gh9lUT74czM.md)

## О чём урок
Завершение **билета № 5**: условие **«если сотрудник опоздал на работу, то за каждые целые 15 минут опоздания начисляется штраф 100 рублей»**. Два решения: «по уму» (удержание) и «каноническое экзаменаторское» (штраф — вытесняющее начисление). Также — работа над ошибками.

## Работа над ошибками (после занятия 76)
1. **Поле «График работы» в документе «НачислениеЗарплаты» удалить**: график закреплён за парой «сотрудник + подразделение» (регистр «ГрафикРаботы»), в документе поле не используется (небольшой косяк).
2. **Серьёзная ошибка (снижает оценку):** в запросе надбавки (урок 75) **не было соединения** таблицы движений («ДополнительныеНачисления» документа) с оборотами регистра бухгалтерии. Нужно **соединить по подразделению**: `ДополнительныеНачисления.Подразделение = Обороты.КтСубконто1` (субконто «Подразделение» — по кредиту). (Замечание зрителя; выгрузка исправлена.)

## Способ 1 — «по уму»: штраф как удержание
- Штраф уже есть в плане видов расчёта **«Удержания»** (каркас). Создать регистр расчёта **«Удержания»** (по образцу «ДополнительныеНачисления»): план «Удержания», **период действия — нет**, **базовый период — нет**, измерения «Сотрудник», «Подразделение», ресурс «Результат», **параметр «КоличествоМинутОпоздания»**.
- В документе — табличная часть **«Удержания»**: «Сотрудник», «Подразделение», «ВидРасчёта» (тип плана «Удержания»), «Параметр» (минуты).
- Подготовка записей — копия цикла допначислений: `ЗаполнитьЗначенияСвойств`, `ПериодРегистрации = НачалоМесяца(Дата)`.
- Расчёт отдельным циклом по движениям: `Движение.Результат = Цел(Движение.Параметр / 15) * 100` (**100 рублей прописывать в коде — так сказано в условии**; константу не требуется, но за неё не снизят). Запись `Движения.Удержания.Записать()`. Запросов не нужно — ни графика, ни базы.
- Пример: Бердыев 40 минут → 2 интервала → 200 ₽; Васина 45 минут → 3 → 300 ₽.
- Можно считать результат сразу при подготовке (меньше кода), но принято: «подготовка — отдельно, расчёт — отдельно».
- С точки зрения типовых конфигураций именно так и правильно: «зарплата к выплате = все начисления − все удержания», штраф не вытесняет оклад.

## Способ 2 — «белоусовский» (скорее всего, ожидается на экзамене)
Логика проверяющего (Павел Белоусов, вопрос 2010 г.): ввод «общего количества минут» — простой вариант, но «для отпуска вы тоже будете вводить количество дней? Начисление зарплаты осуществляется **методом отклонений**» → **штраф должен быть интервалом, вытесняющим оклад**:
1. **Штраф — вид расчёта в плане «Основные начисления»** (вытеснение работает только внутри одного плана; допначисления и удержания основные не вытесняют). **Оклад вытесняется штрафом** (флажок «Вытесняющий» по связи «вытесняется»).
2. **Дата начала/окончания в документе — с временем** (состав даты «Дата и время»), строка штрафа: «ДатаНачала» = время прихода по графику (08:00), «ДатаОкончания» = фактическое время прихода (08:40). Не приводить к концу дня: `ПериодДействияКонец = Строка.ДатаОкончания` (без `КонецДня`), только для данных с временем.
3. **График работы заполнять 15-минутными интервалами** (так отвечал Белоусов на курсе): в регистре сведений «ГрафикРаботы» измерение **«Дата» → состав «Дата и время»**; ресурс «Часов» = 0,25 для каждой 15-минутки (в запросе — «Количество15Минуток» = 1 для интервала). В обработке «ЗаполнениеГрафика» для рабочего дня — цикл: `Дата = НачалоДня + 8*3600` (+15 минут от начала, т.е. с 8:15 — см. ниже), пока `ДатаНачала < ДатаОкончания`: записать запись (`Дата = ДатаНачалаИнтервала` — **не Дата дня**, иначе ошибка «запись с такими ключевыми полями существует»), `ДатаНачалаИнтервала += 15*60`. Обеденный перерыв — тоже пришлось бы учитывать (на практике не требуют).
4. **Тонкость границ:** интервал «с 8:00 до 8:40» должен захватить 2 интервала (8:15 и 8:30, а не 3) → **начинать заполнение графика с 8:15 и заканчивать в 16:00 включительно** (запись — окончание интервала). Тогда: Бердыев 40 мин → 2 (30 минут), Васина 45 → 3 (45 мин).
5. **Отдельный запрос расчёта штрафа** (оклад и штраф считать раздельно: сначала оклад, потом штраф — иначе не вытеснит): `ДанныеГрафика(Регистратор = &Ссылка)`: `НомерСтроки`, `ЕСТЬNULL(ЗначениеФактическийПериодДействия, 0)` → «Количество15Минуток»; отбор **`ВидРасчета = &Штраф`**; цикл по движениям, `Если Движение.ВидРасчета <> Штраф Тогда Продолжить;` затем `Выборка.Сбросить(); Если Выборка.НайтиСледующий(…) Тогда ЗаполнитьЗначенияСвойств(Движение, Выборка); Движение.Результат = Выборка.Количество15Минуток * 100`. Запись — **`Записать(, Истина)`**. Реквизит регистра «Количество15Минуток» (число; вещественное — избыточно).
6. **В запросе оклада обязательно добавить отбор по виду расчёта «Оклад»** (в плане теперь два вида), и в цикле оклада: `Если Движение.ВидРасчета <> Оклад Тогда Продолжить`. Иначе штраф посчитается по формуле оклада.
7. **Результат:** при окладе 150 000 Бердыев теряет ≈620 ₽ (**дважды: вытеснение оклада + штраф 200 ₽**), Васина ≈ 1 200 ₽. Автор считает решение «бредовым с ног до головы» (штраф с плюсом, вытесняет оклад, 15-минутный график, время в документе), но «именно его хотят видеть» экзаменаторы.

## Ответы зрителям
- **Часы должны быть кратны единице?** Нет: интервал = 0,25 часа, иначе вытеснение не работает.
- **Хранить ставку штрафа в константе?** Если в условии прямо «100 рублей» — писать 100; константу вводят, когда сказано «хранится в базе». За константу вряд ли снизят.
- В конце: билет № 5 закрыт; следующий билет — расчёт оклада заново с нуля (иванча просил без заготовок). Выгрузки «после занятия 77» (варианты 1 и 2) сохранены.
