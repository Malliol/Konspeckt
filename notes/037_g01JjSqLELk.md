# Урок 37. Сообщение из обработки проведения при закрытии формы. Подготовка к специалисту по платформе 1С

Видео: https://www.youtube.com/watch?v=g01JjSqLELk · 52 мин · [полный текст](../transcripts/037_g01JjSqLELk.md)

## О чём урок
Возврат «долга» из уроков 35–36: в задаче о бюджете при превышении нужно **выводить сообщение, но не отказываться от проведения**. `Сообщить` в обработке проведения при нажатии «Провести и закрыть» форма закрывается раньше, и пользователь сообщения не видит. Автор разбирает несколько способов. Многие сдают задачу с этим дефектом и экзаменаторы «закрывают глаза» (оправдание: «хочешь видеть сообщение — жми “Провести”»), но автор называет это подгонкой постановки под собственные возможности.

## Способ 1 (любимый автора, рекомендован для экзамена): проверка в форме
Проверку выполняют **в форме**, а не в обработке проведения.
- Общий модуль «ПроведениеДокументов»: экспортная процедура **«ПроверитьБюджет(Объект, ТекстСообщения)»** — тот же запрос по регистру «Бюджет» (обороты), но вместо `Сообщить` **заполняет переменную текста сообщения** (при отсутствии превышения — пустая строка).
- В форме документа — реквизит **«ТекстСообщения»** и два обработчика:
  - **«ПриЗаписиНаСервере»** (на сервере, при записи): сброс текста и `ПроверитьБюджет(Объект, ТекстСообщения)`, только если `ПараметрыЗаписи.РежимЗаписи = РежимЗаписиДокумента.Проведение` (при простой записи и отмене проведения проверка не нужна). Выбор этого события, а не «ПослеЗаписиНаСервере»: **блокировка от записи движений ещё держится**, значит данные не изменятся между записью и проверкой;
  - **«ПослеЗаписи»** (клиент): `Если ТекстСообщения <> "" Тогда Сообщить(ТекстСообщения)` — сообщение появляется и при «Провести», и при «Провести и закрыть».
- Вместо реквизита можно передавать значение через **параметры записи** (`ПараметрыЗаписи` — существуют в форме, между `ПриЗаписиНаСервере` и `ПослеЗаписи`).
- Подключение к каждому следующему документу (приходная, приход/расход денег) — **~30 секунд**: реквизит + два обработчика (копирование). Аргумент «на экзамене нет времени» автор отвергает: экзамен 5 часов, а правильное решение важнее.
- Минус: сообщение **не выводится при проведении из формы списка** (при задаче «документы задним числом не вводятся» это допустимо).

## Способ 2: дополнительные свойства объекта
Проверку выполняют в обработке проведения, а текст сообщения **«перебрасывают» через `ЭтотОбъект.ДополнительныеСвойства`** (структура, существует только на время записи объекта; одинакова в обработчиках модуля объекта и в форме).
- В обработке проведения: `ДополнительныеСвойства.Вставить("ТекстСообщения", Текст)` (перед проверкой — пустая строка).
- В форме «ПриЗаписиНаСервере»: `ТекущийОбъект.ДополнительныеСвойства.Свойство("ТекстСообщения", ТекстСообщения)`; метод `Свойство` возвращает `Истина`, если ключ есть, и записывает значение во второй параметр — исключения при отсутствии ключа нет (прямое обращение `…ТекстСообщения` при отсутствии выбросило бы исключение). В отладке: «Объект» в форме — **данные формы** (копия, без допсвойств), настоящий объект — `ТекущийОбъект` в параметре обработчика.
- Тот же способ: `ПослеЗаписи` на клиенте выводит сообщение. При отмене проведения и простой записи текст пуст автоматически (обработки проведения нет).
- Автор считает способ 2 отличным («мало кто знает про дополнительные свойства — а они очень рабочие»). Сообщения тоже **не выводятся из формы списка**.
- Альтернативы без особых рекомендаций: реквизит документа или **параметр сеанса** для текста (заполнить при проведении, показать после); функция **`ПолучитьСообщенияПользователю`** (возвращает массив сообщений, выведенных в фоновом задании — для обычной записи не подходит); трюки с активацией окон (в управляемом интерфейсе не работают).

## Способ 3: переопределить кнопку «Провести и закрыть» (сообщение из любого места, в том числе проверка при закрытии формы)
Нет способа узнать, какой кнопкой нажато проведение (из обработки проведения/«ПослеЗаписиНаСервере»), поэтому единственный вариант — **заменить стандартную команду**:
1. Форма → «Состав команд» командной панели: выключить типовую «Провести и закрыть»; отключить **автозаполнение** командной панели; создать группу «Стандартные команды» с источником «Форма» (так вернуть остальные типовые кнопки), свою кнопку «Провести и закрыть» ставят по умолчанию. Свойства «слева» у кнопки нет — позиция получается порядком групп.
2. Обработчик команды (клиент): `Записать(Новый Структура("РежимЗаписи", РежимЗаписиДокумента.Проведение))`; затем `Закрыть()`; сообщение выводится (в модуле вызывается `Сообщить` из общего модуля).
3. Проблема: при закрытии изменённой формы крестиком появляется стандартное окно «Данные были изменены. Сохранить?» и срабатывает стандартная команда, а не наша. Решение — переопределить **«ПередЗакрытием»**: «Стандартная обработка = Ложь»; своё окно через **`ПоказатьВопрос`**; ответ «Да» → записать (проведением) и закрыть, «Нет» → закрыть без сохранения, «Отмена» → ничего. Синхронный `Вопрос` недоступен (режим использования модальности «Не использовать» — правильный, во всех типовых так); использовать **`ПоказатьВопрос(ОписаниеОповещения, …)`** (преобразовать автоматически через рефакторинг «Не рекомендуемые синхронные вызовы» → «Преобразовать вызов»; процедура-обработчик получает ответ, второй параметр `ОписаниеОповещения` — «ЭтотОбъект» (форма)).
4. Подводные камни: в «ПередЗакрытием» нужно установить **`Отказ = Истина`** (иначе форма закроется до ответа) и обязательно **`Модифицированность = Ложь`** после показа вопроса (иначе `ПередЗакрытием` вызывается повторно — «ловушка»), учитывать только если форма изменена (`Если Модифицированность`).
- Вывод автора: способ 3 для экзамена — «клинический случай», перебор.

## Вывод и рекомендации
- На экзамене автор выбрал бы **способ 1** (обработчики в форме + общий метод проверки) и объяснил бы экзаменатору, что это лучше «обычно принимаемого» `Сообщить` в обработке проведения; способ 2 — тоже отличный.
- **Параметры записи** — ещё один способ общения между обработчиками формы (в отличие от дополнительных свойств, живут в форме).
- Выгрузки по занятию: три варианта — приходная накладная (исходное решение), расходная (способ 2), приход денег (способ 3), расход денег/другие (способ 1).
- Зритель (иванча): на экзамене для ускорения целиком сделать один документ и скопировать на остальные. Следующая часть — через 5 минут (занятие 38).
